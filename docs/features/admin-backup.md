# 관리자 설정: 백업 및 복원

관리자가 설정을 파일 하나로 내려받고, 그 파일로 되돌릴 수 있다. 다른 서버로 옮기거나 설정을 크게 바꾸기 전에 쓴다. 사용자 지정(2026-10-13), 결정은 D-112.

**이것은 설정의 백업이다. 데이터의 백업이 아니다.** 티켓, 프로젝트, 문서, 댓글, 올린 파일은 들어가지 않는다. 그것은 PostgreSQL 덤프와 업로드 볼륨(`/var/lib/flowbit/uploads`)으로 백업한다.

## 범위

- 관리자 설정의 **"백업 및 복원"** 탭 (`/admin/backup`): 위에 백업, 아래에 복원
- 항목 네 가지를 골라서 백업하고, 파일에 든 것 중에서 골라서 복원한다
- 파일을 암호로 보호할 수 있다 (선택)

범위 밖: 티켓·프로젝트 등 데이터, 올린 파일(로고·프로필 사진 포함), 프로젝트 구성원 권한, 라벨, 자동(예약) 백업, 서버에 백업 보관.

## 항목

| 항목 | 파일에 들어가는 것 | 복원하면 |
|---|---|---|
| 워크스페이스 (`WORKSPACE`) | 이름, 티켓 키. 로고는 없다 | 두 값을 바꾼다. 티켓 번호는 그대로이고 앞의 키만 바뀐다 |
| 로그인 연동 (`AUTH`) | LDAP·SSO 설정 전부. **검색 계정 비밀번호와 클라이언트 시크릿 포함** | 두 설정을 통째로 바꾼다 |
| 알림 (`NOTIFICATIONS`) | 메일 서버, 웹 푸시, API 알림 목록. **SMTP 비밀번호, Firebase 서비스 계정 키, 웹훅 헤더·서명 값 포함** | 메일·푸시 설정을 바꾸고, **API 알림은 지금 있는 것을 모두 지운 뒤** 파일의 것으로 다시 만든다(마지막 전달 결과는 사라진다) |
| 구성원 (`MEMBERS`) | 아이디, 이메일, 이름, 역할, 상태, 로그인 방식(`LOCAL`·`LDAP`·`SSO`)과 외부 구분 값, **비밀번호 해시**, 메일 수신 여부, 언어·시간대. 프로필 사진과 프로젝트 권한은 없다 | **없는 사람만 추가한다.** 아이디나 이메일이 이미 쓰이고 있으면 그 사람은 건너뛴다 |
| Git 연동 (`GIT`, D-141) | Git 서버 연결: 이름, 종류, 서버 주소, **비밀 값**, 사용 여부, 허용 프로젝트(id), 자동 상태 변경, 받는 방식, GitHub App 의 조직·ID·**비공개 키·클라이언트 시크릿**·설치 ID(D-146). 티켓에 연결된 브랜치·PR·커밋, 가져오기의 진행 위치, 구성원 Git 아이디는 없다 | **백업과 같게 맞춘다.** 같은 id 의 연결은 고치고(웹훅 주소가 그대로라 Git 서버를 다시 설정하지 않아도 된다), 없는 것은 같은 id 로 만들고, 백업에 없는 연결은 지운다(그 연결의 티켓 연결도 함께 지워진다). 이 설치에 없는 프로젝트는 허용 목록에서 빠진다 |

구성원을 "추가만" 하는 이유: 있는 계정을 덮어쓰면 복원하는 관리자 자신의 역할·비밀번호가 바뀌어 못 들어오게 될 수 있고, 백업 뒤에 바꾼 비밀번호가 되돌아간다. 사람을 지우지도 않는다(티켓이 그 사람을 가리킨다). 복원된 로컬 계정은 백업 당시의 비밀번호로 로그인한다.

## 파일

JSON 하나다. 이름은 `flowbit-backup-20261013-1020.json`(받은 사람의 시각).

```json
{
  "format": "flowbit-backup", "version": 1,
  "createdAt": "2026-10-13T01:20:23Z",
  "sections": ["WORKSPACE", "AUTH", "NOTIFICATIONS", "MEMBERS"],
  "data": {
    "workspace": { "name": "…", "workspaceKey": "FB" },
    "auth": { "ldap": { … }, "sso": { … } },
    "notifications": { "smtp": { … }, "push": { … }, "webhooks": [ … ] },
    "members": [ { "loginId": "…", "role": "MEMBER", "passwordHash": "…", … } ]
  }
}
```

- `auth`·`notifications` 안의 모양은 설정 화면이 저장할 때 보내는 값과 같다(`LdapSettingsInput`, `SsoSettingsInput`, `SmtpInput`, `PushInput`, `WebhookInput`). 다만 비밀 값이 실제 값으로 들어 있다.
- **암호를 정하면** `data` 대신 `encrypted` 가 들어간다: `{ kdf: "PBKDF2-SHA256", iterations, salt, iv, ciphertext }`. `data` 의 JSON 을 AES-256-GCM 으로 암호화한 것이고, 키는 암호에서 PBKDF2-HMAC-SHA256(21만 회)으로 만든다. `sections` 와 `createdAt` 은 암호 없이 읽힌다(화면이 무엇이 들었는지 보여 주려고).
- 암호는 8~128자. 서버에 저장하지 않는다. **잊으면 복원할 수 없다.**
- 암호 없이 받은 파일에는 비밀번호·키·비밀번호 해시가 그대로 보인다. 화면이 받기 전과 받은 뒤에 알린다.
- 형식이 바뀌면 `version` 을 올린다. 다른 `version` 의 파일은 거부한다.

## API

둘 다 관리자만(`/api/v1/admin/**` 규칙). 감사 로그에 `BACKUP_EXPORTED`·`BACKUP_RESTORED` 를 남긴다(항목과 암호화 여부. 값은 남기지 않는다).

| 메서드 | 경로 | 본문 | 응답 |
|---|---|---|---|
| POST | `/api/v1/admin/backup/export` | `{ sections: [...], password: string \| null }` | 200, 위의 파일 내용 그대로 |
| POST | `/api/v1/admin/backup/restore` | `{ file: <파일 내용>, sections: [...], password: string \| null }` | 200 `{ restored: [...], membersAdded, membersSkipped, webhooks }` |

- 백업이 `GET` 이 아닌 것은 암호를 주소에 싣지 않기 위해서다. 파일로 저장하는 일은 브라우저가 한다.
- 오류는 전부 422 `VALIDATION_FAILED` 이고 `errors[0]` 이 이유다.

| `field` | `code` | 뜻 |
|---|---|---|
| `sections` | `REQUIRED` | 항목을 하나도 고르지 않았다 |
| `sections` | `NOT_IN_FILE` | 파일에 없는 항목을 복원하려 했다 |
| `password` | `INVALID` | 백업 암호가 8~128자가 아니다 |
| `password` | `REQUIRED` | 암호화된 파일인데 암호가 없다 |
| `password` | `WRONG_PASSWORD` | 암호가 틀렸거나 파일이 바뀌었다 |
| `file` | `INVALID` | 백업 파일이 아니다, 읽을 수 없다, 또는 값 하나가 설정 화면의 검사를 통과하지 못했다(메시지에 항목과 이유) |
| `file` | `UNSUPPORTED_VERSION` | 형식 버전이 다르다 |

- 복원 중에 같은 아이디의 구성원이 따로 추가되면 409 `RESTORE_CONFLICT`.

## 복원의 규칙

- **전부 아니면 전무.** 고른 항목을 한 트랜잭션에서 순서대로(워크스페이스 → 로그인 연동 → 알림 → 구성원 → Git 연동) 넣고, 하나라도 거부되면 아무것도 바뀌지 않는다.
- **설정 화면에서 저장할 때와 같은 검사를 거친다**(같은 서비스 함수를 부른다). 그래서 켜져 있는 OpenID Connect 설정은 복원할 때 발급자 주소에 닿아야 하고, 닿지 않으면 복원이 거부된다.
- 파일의 값은 관리자가 화면에서 직접 넣을 수 있는 값과 같은 권한으로 다뤄진다. 구성원의 비밀번호 해시만은 화면으로 넣을 수 없는 값인데, 파일을 고칠 수 있는 사람은 이미 관리자다.
- LDAP 을 쓰는 동안에도 구성원 복원은 된다(구성원 화면의 "추가"는 막혀 있지만 복원은 관리자가 옮겨 오는 일이다).

## 화면

- **백업**: 항목 체크박스 넷(처음에는 전부 선택, 각각 무엇이 들어가는지 한 줄), 파일 암호(선택), "백업 파일 받기".
- **복원**: 파일을 고르면 브라우저가 읽어 만든 시각과 암호 보호 여부를 보여 주고, 파일에 든 항목만 체크박스로 나온다(각각 복원하면 무엇이 바뀌는지 한 줄). 암호화된 파일이면 암호 칸이 나온다. "복원"을 누르면 한 번 더 묻고("현재 설정을 바꾸고 복원"), 끝나면 무엇을 복원했고 구성원을 몇 명 추가·건너뛰었는지 보여 준다.
- 백업 파일이 아니면 서버에 보내기 전에 파일 칸 아래에 알린다.

## 인수 기준

`BackupIntegrationTest` 가 확인한다.

- 관리자가 아니면 백업도 복원도 403
- 백업한 뒤 설정을 지우고 구성원을 없앤 다음 복원하면 이름·티켓 키·LDAP 비밀번호·SMTP 비밀번호·웹훅 서명 값이 돌아오고, 없던 구성원이 생겨 예전 비밀번호로 로그인하며, 있던 관리자는 건너뛴다
- 고른 항목만 파일에 담기고, 파일에 없는 항목의 복원은 422, 고르지 않은 항목은 바뀌지 않는다
- 암호를 정한 파일에는 비밀 값과 아이디가 보이지 않고, 암호가 없거나 틀리면 422 로 아무것도 바뀌지 않으며, 맞으면 복원된다
- 값 하나(웹훅 주소)가 올바르지 않으면 422 이고 워크스페이스·웹훅·구성원 어느 것도 바뀌지 않는다
- 백업 파일이 아닌 JSON, 짧은 암호, 빈 항목은 422

## 알려진 한계

- 요청 본문이 256KB(WebFlux 기본값)를 넘으면 복원 요청이 거부된다. 구성원이 수백 명을 넘는 설치에서는 한도를 올려야 한다(`spring.http.codecs.max-in-memory-size`). 지금은 올리지 않았다.
- DB 에 평문으로 있는 비밀 값을 그대로 옮긴다. DB 쪽 암호화(PROGRESS "열린 질문")를 하게 되면 파일 형식을 다시 봐야 한다.
- 버전이 다른 Flowbit 사이의 복원은 형식 버전이 같을 때만 된다. 설정 항목이 늘어난 뒤의 옛 파일은 빠진 값 때문에 거부될 수 있다.
