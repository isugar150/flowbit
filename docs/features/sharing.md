# 공유 링크

로그인하지 않아도 URL 만 알면 열 수 있는 **읽기 전용 공유 화면**을 만든다. 처음에는 **"내 티켓"의 캘린더**(한 달)를 공유했고, 이어서 **타임라인**(몇 월부터 몇 월까지)과 **티켓**(하위 티켓·문서로 이동할 수 있는 읽기 전용 화면)을 더했다. 사용자 지정(2026-10-23), 결정은 D-197·D-198, 타임라인은 D-199, 티켓은 D-200, 캘린더의 마우스 오버 카드는 D-201, 내 설정의 "내 공유 링크"는 D-202.

## 사용자가 한 말

"내 티켓 > 캘린더에서 공유하기 버튼을 넣고, 누르면 현재 로그인한 계정을 해시화해서 URL 을 만든다. URL 을 아는 사람은 누구든 접근할 수 있고 특정 페이지에 임베드도 할 수 있다. 페이지와 공유한 사용자와 선택한 월이 같으면 같은 URL 이 나와야 한다. 다른 사람이 접근하면 인증 없이 이 사람의 그 달 캘린더만 보인다. 나중에 티켓 등에도 쓸 것이니 공통으로 쓸 수 있게 한다. 누가 공유한 링크에 어떤 클라이언트에서 접속했는지 히스토리를 남기고, 이것도 관리자 설정의 자동 정리 스케줄러에 넣는다."

## 범위

- 내 티켓 두 탭(담당 티켓·요청한 티켓)의 캘린더 보기 맨 위 줄의 **"공유하기"** 단추. 지금 보는 달이 공유할 달이다.
- **티켓** 상세의 오른쪽 열 "공유하기" 단추(D-200, 아래 "티켓 공유"). 그 티켓과 그 아래의 하위 티켓·문서를 읽을 수 있고 아무것도 바꿀 수 없다.
- 같은 두 탭의 **타임라인** 보기 맨 위 줄의 **"공유하기"** 단추. 창에서 **몇 월부터 몇 월까지** 공유할지 고른다(D-199, 아래 "타임라인 공유").
- 공유 링크 `/s/{토큰}`: 로그인 없이 열리는 읽기 전용 화면, **iframe 으로 다른 사이트에 넣을 수 있다**.
- **같은 링크는 같은 URL**: (화면 종류, 공유한 사람, 달, 탭)이 같으면 몇 번을 눌러도 같은 URL 이 나온다.
- **접속 기록**: 링크가 열릴 때마다 누가 공유한 링크인지(링크), 어느 클라이언트(IP, 브라우저)에서, 어디에 임베드돼 있는지 남기고, 공유한 사람이 공유 창에서 최근 기록을 본다.
- **공유 중지**: 링크를 끈다. 끈 링크는 열리지 않는다.
- 접속 기록은 관리자 설정 > "데이터 보관"의 **네 번째 항목**으로 기간을 정하면 서버가 주기적으로 지운다.

범위 밖(지금은 하지 않는다): 프로젝트 개요·프로젝트 문서 같은 다른 화면의 공유(구조만 공통으로 만든다), 공유 화면에서의 댓글·이모지, 링크 만료일·비밀번호, 관리자가 모든 사람의 링크·기록을 한 화면에서 보기, 접속 알림, 공유한 사람 대신 관리자가 링크를 끄기.

## 구조: 공통으로 쓰는 부분

공유할 수 있는 것은 **종류**(`kind`) 하나와 그 종류의 **매개변수**(`params`)로 정해진다. 새로 공유할 화면을 만들 때 고치는 곳은 백엔드의 종류 하나(제공자 클래스)와 프런트의 화면 하나다. 링크 만들기·끄기·기록·정리는 그대로 쓴다.

| 종류 (`kind`) | 매개변수 | 공개되는 내용 |
|---|---|---|
| `ISSUE` (D-200) | `number` = 티켓 번호 | **그 티켓과 그 아래의 하위 티켓·문서**(아래 "티켓 공유") |
| `MY_ISSUES_TIMELINE` (D-199) | `from`·`to` = `YYYY-MM`(그 달부터 그 달까지, **끝 달 포함**, 최대 24개월), `scope` | 공유한 사람의 그 탭 티켓 중 **그 기간에 걸친** 티켓의 번호·키·제목·상태·시작일·기한·만든 때·바뀐 때·**프로젝트 이름**(묶음 이름으로 쓴다) |
| `MY_ISSUES_CALENDAR` | `month` = `YYYY-MM`, `scope` = `assigned`(담당 티켓)·`created`(요청한 티켓) | 공유한 사람의 그 탭 티켓 중 **그 달에 걸친** 티켓의 번호·키·제목·상태·시작일·기한과, 마우스 오버 카드(D-201)를 위한 우선순위·라벨·**프로젝트 이름**·**만든 사람의 표시 이름**·**최근 활동 3건**(누가·무슨 종류의 변경·언제, **바뀐 값은 제외**) |

- 공개하는 값은 **종류마다 정한 최소한**이다. 캘린더는 담당자·본문·댓글·첨부 같은 것은 내보내지 않는다. 티켓 제목은 보인다. 마우스 오버 카드(D-201) 때문에 캘린더에도 프로젝트 이름·만든 사람의 이름·최근 활동 3건이 보인다(활동은 "홍길동님이 상태를 바꿨습니다"까지이고 바뀐 값은 없다). **타임라인은 프로젝트별로 묶어 그리므로 프로젝트 이름이 보인다**(프로젝트 id·담당자·본문·댓글은 아니다). 하위 티켓의 상위 경로는 내보내지 않는다(상위 티켓의 제목이 새지 않도록 타임라인의 하위 티켓은 들여 쓰지 않고 줄마다 따로 나온다).
- 내용은 **열 때마다 공유한 사람의 지금 권한**으로 만든다. 공유한 사람이 들어갈 수 없게 된 프로젝트의 티켓, 삭제한 티켓은 빠진다. 공유한 사람이 비활성이면 링크는 열리지 않는다.
- 공유한 사람 이름은 표시 이름만 보인다(없으면 이름 없이 "공유된 캘린더"). 로그인 아이디는 내보내지 않는다.

## URL 과 토큰

- 주소: `/s/{토큰}`. 접속 주소(`FLOWBIT_PUBLIC_URL` 이 아니라 **지금 열린 주소**의 origin)를 앞에 붙여 보여 준다.
- 토큰은 서버가 만든 **256비트 난수**(URL 안전 base64, 43자)다. 계정을 해시한 값이 아니다(D-197: 해시로는 되돌려 찾을 수 없어 표를 두어야 하고, 계정에서 계산하는 값은 짐작·되돌릴 수 없는 폐기가 안 된다). 같은 입력에 같은 URL 이 나오는 것은 표의 `(owner_id, kind, target)` 가 같은 행을 다시 돌려주어서다.
- `target` 은 매개변수를 키 순서로 정렬한 `k=v&k=v` 문자열(정규형)이다. 매개변수는 종류마다 검사한다(`month` 는 `YYYY-MM`, 1900~2999년).
- **공유 중지** 뒤 다시 공유하면 **새 토큰**(다른 URL)이 나온다. 중지한 링크는 다시 살아나지 않는다.

## 임베드

- 공유 창에 **복사할 수 있는 iframe 코드**가 있다: `<iframe src="https://…/s/토큰" width="100%" height="640" style="border:0" loading="lazy"></iframe>`.
- `/s/*` 만 다른 사이트의 프레임 안에서 열린다(`Content-Security-Policy: frame-ancestors *`). 다른 모든 화면은 전처럼 같은 사이트의 프레임에서만 열린다(`next.config.ts`).
- 공유 화면은 쿠키·로그인 상태를 쓰지 않는다. 검색 엔진에는 `noindex` 를 알린다.
- 어디에 임베드됐는지는 화면이 `window.self !== window.top`·`document.referrer` 로 알아 접속할 때 함께 보낸다(**클라이언트가 말하는 값**이라 기록용일 뿐 믿지 않는다).

## 접속 기록

링크가 열릴 때마다 한 줄:

| 항목 | 내용 |
|---|---|
| 시각 | 서버 시계 |
| 링크 | 어느 공유 링크(→ 공유한 사람, 종류, 달) |
| IP 주소 | 요청의 `remoteAddress`(프록시 뒤에서는 `X-Forwarded-*` 를 따른다, `server.forward-headers-strategy=native`) |
| 브라우저 | `User-Agent`(512자까지) |
| 임베드 | 프레임 안에서 열렸는지, 그 페이지 주소(512자까지) |

- 존재하지 않는 토큰·중지된 링크의 접근은 기록하지 않는다(링크가 없다).
- 공유한 사람은 공유 창에서 **최근 20건**(시각·브라우저·OS·IP·임베드 여부)을 본다. 전체 기간의 기록은 DB 의 `share_accesses`.
- **자동 정리**: 관리자 설정 > "데이터 보관"의 항목 **"공유 링크 접속 기록"**(`shareAccesses`)에서 "영구 삭제 안 함" 또는 N일·주·개월을 정한다. 기본은 "영구 삭제 안 함". 기록한 시각 기준으로 기간이 지난 줄을 서버가 시작 1분 뒤와 1시간마다 지운다(다른 항목과 같은 작업, [admin-retention.md](admin-retention.md)). 지운 개수는 감사 로그 `DATA_PURGED` 의 `shareAccesses` 에 들어간다.
- 링크를 중지해도 기록은 남고 같은 기간 뒤에 지워진다.

## 한계와 보호

- **공개된 링크다**: 링크를 받은 사람이 다시 다른 사람에게 줄 수 있다. 공유 창이 "링크를 아는 누구나 이 달의 티켓 제목·상태·기간을 볼 수 있습니다"라고 알린다.
- 공개 API 는 **IP 별 요청 제한**(분당 120회)이 있다. 토큰은 256비트라 짐작할 수 없다. 토큰이 맞지 않는 모든 경우(없음·중지·공유한 사람 비활성)는 같은 `404` 로 답한다.
- 감사 로그: 링크를 만들 때(`SHARE_LINK_CREATED`, 이미 있는 링크를 다시 받을 때는 남기지 않는다)와 중지할 때(`SHARE_LINK_REVOKED`).

## API

| 메서드·경로 | 내용 |
|---|---|
| `POST /api/v1/shares` | 링크를 만들거나(없으면) 이미 있는 링크를 돌려준다. 본문 `{ "kind": "MY_ISSUES_CALENDAR", "params": { "month": "2026-10", "scope": "assigned" } }`. 응답 `{ id, kind, params, token, path, createdAt }`. 공유한 사람은 요청한 사람 |
| `DELETE /api/v1/shares/{id}` | 링크를 중지한다(204). 만든 사람만 |
| `GET /api/v1/shares` | **내 링크 목록**(쓰고 있는 것만, 최근에 만든 순): `[{ id, kind, params, token, path, createdAt, accessCount, lastAccessedAt, subject }]`. `subject` 는 티켓 링크일 때 "FB-12 제목"(지금 볼 수 없으면 null), 다른 종류는 null(화면이 매개변수로 말한다). 내 설정이 쓴다(D-202) |
| `GET /api/v1/shares/{id}/accesses?limit=` | 그 링크의 최근 접속(기본 20건, 최대 200건) `{ total, items: [{ accessedAt, ipAddress, userAgent, embedded, referrer }] }`. 만든 사람만 |
| `GET /api/v1/public/shares/{token}?embedded=&referrer=` | **로그인 없이.** 공유한 내용 `{ kind, sharedBy, params, content }` 를 돌려주고 접속을 기록한다. `Cache-Control: no-store` |

`content` 는 종류마다 다르다. `MY_ISSUES_CALENDAR`: `{ "issues": [{ "number", "key", "title", "status", "startDate", "dueDate" }] }`.

## 타임라인 공유 (D-199)

- "내 티켓"의 **타임라인** 보기(두 탭 모두) 맨 위에 "공유하기" 단추가 있다. 눌러도 링크가 바로 만들어지지 않는다: 창에서 **시작 월과 끝 월**을 고른 뒤 "링크 만들기"를 누른다(범위마다 링크가 달라서, 열자마자 만들면 쓰지 않는 링크가 쌓인다). 처음 값은 이번 달부터 두 달 뒤까지다.
- 달은 오늘 기준 앞뒤 3년 안에서 고른다. 시작 월을 끝 월보다 뒤로 하면 끝 월이 따라오고, 끝 월을 시작 월보다 앞으로 하면 시작 월이 따라온다. 기간이 24개월을 넘으면 반대쪽 끝이 따라온다(서버도 같은 규칙으로 422).
- 링크를 만든 뒤에는 고른 범위가 한 줄로 보이고 "범위 바꾸기"를 누르면 다시 고를 수 있다(이미 만든 링크는 그대로 열리고, 다른 범위를 만들면 다른 링크다. 이전 링크를 끄려면 그 범위를 다시 골라 "공유 중지"). 같은 범위를 다시 고르면 같은 URL.
- 공유 화면은 지금의 타임라인과 같은 차트다: 프로젝트별 묶음과 전체 기간 막대, 티켓별 막대, 월 이름, 오늘 선. 다른 점: **보이는 기간이 고른 범위로 고정**(시작 월 1일부터 끝 월 말일까지, 양쪽 여백 없음, 범위 밖은 막대를 잘라 그린다), 오늘 선은 범위 안일 때만, 티켓은 눌러도 열리지 않는다. 기한 없는 티켓은 지금처럼 만든 날(또는 시작일)부터 오늘까지(끝난 것은 마지막으로 바뀐 날까지)로 보고, 그것이 범위에 걸치면 나온다.
- 어떤 티켓이 걸치는지는 서버가 **열 때마다** 정한다(공유한 사람의 지금 권한).

## 티켓 공유 (D-200)

링크 하나가 **티켓 한 개와 그 아래**를 연다: 하위 티켓(몇 단계 아래든)과 그 티켓들의 문서. **모두 읽기 전용**이다.

### 누가, 언제

- 티켓 상세 오른쪽 열(담당자·기한 아래)의 **"공유하기"** 단추. 삭제된 티켓과 보기 역할만 가진 사람에게는 보이지 않는다.
- **그 티켓을 고칠 수 있는 사람만** 링크를 만든다(보기 역할은 403). 공개는 되돌리기 어려운 일이라 읽을 수만 있는 사람에게는 열지 않는다. 링크가 만들어진 뒤에는 `공유한 사람의 지금 권한` 으로 열 때마다 확인한다(티켓·프로젝트에 더는 들어갈 수 없거나 비활성이면 열리지 않는다).
- 매개변수 `number`(티켓 번호)만 같으면 같은 URL(D-197). 삭제된 티켓은 링크가 만들어지지 않고, 만든 뒤 삭제되면 링크는 열리지 않는다(복원하면 다시 열린다).

| 키·제목·상태·우선순위·시작일·기한·만든 때·바뀐 때·라벨(이름·색)·프로젝트 이름 | 댓글·활동 기록·리액션·첨부 파일 목록·Git 연결·구독자·사용자 속성 |
| **본문**(읽기 전용 편집기: 서식·표·사진·파일 블록·임베드·코드) | 편집·삭제·상태 변경 같은 모든 동작, 새 하위 티켓·문서 만들기 |
| 담당자·만든 사람의 **표시 이름**(없으면 빠진다. 로그인 아이디·사진은 내보내지 않는다) | 로그인 아이디, 사람의 사진 |
| **하위 티켓** 목록(키·제목·상태·우선순위·기한·진행률), 그중 지금 공유한 사람이 볼 수 있고 삭제되지 않은 것만 | 삭제된 하위 티켓, 공유한 사람이 들어갈 수 없는 프로젝트의 것 |
| **문서** 목록(제목·바뀐 때)과 문서 본문 | 삭제된 문서 |

### 이동

- 하위 티켓 목록의 줄이나 문서 목록의 줄을 누르면 **같은 링크 안에서** 그 티켓·문서가 열린다: `/s/{토큰}?issue={번호}`, `/s/{토큰}?doc={문서 id}`. 주소가 바뀌어 브라우저의 뒤로 가기가 되고, 그 주소를 그대로 열어도 된다(링크의 토큰이 맞아야 한다).
- 위쪽에 **경로**가 있다: 공유한 티켓부터 지금 열린 티켓·문서까지. 공유한 티켓보다 위(상위 티켓)로는 가지 않는다 — 공유한 티켓이 맨 위다.
- 열 수 있는 것은 **공유한 티켓의 하위 티켓(몇 단계 아래든)과 그 티켓들의 문서**뿐이다. 다른 번호나 다른 문서의 id 를 주소에 넣어도 `404`.
- 본문 안의 문서 블록(`pageLink`)은 눌러서 같은 링크 안에서 열린다. 열 수 없는 문서(공유한 티켓 아래의 문서가 아닌 것)이면 "열 수 없습니다" 화면이 뜨고 "공유한 티켓으로" 단추가 있다. 본문 속 다른 티켓 링크(`/issue/FB-12`)는 그대로 글이고 로그인이 필요한 주소로 간다.

### 사진과 파일

본문의 사진·파일 블록은 로그인이 필요한 주소(`/api/v1/files/…`, `/api/v1/editor-files/…`)를 가리키므로, 공유 화면에는 **링크 안에서만 쓰는 주소**로 바꿔 내려 준다: `/api/v1/public/shares/{토큰}/files/{키}`, `…/files/{키}/original`, `…/editor-files/{키}`. 서버는 그 키가 **공유한 티켓·하위 티켓·그 문서의 본문에 실제로 들어 있을 때만** 내준다(다른 파일의 키를 넣어도 404). 파일은 다른 곳과 같이 내려받기로만 나간다.

### 접속 기록

공유 화면에서 하위 티켓·문서를 열 때마다 한 줄이 더 남는다(`share_accesses.item`: `issue:13`, `document:{id}`; 링크 자체를 열 때는 비어 있다). 사진·파일 요청은 남기지 않는다. 공유 창의 최근 접속 기록에 어느 티켓·문서였는지 보인다.

### 한계

- 공유한 사람이 비활성이거나 그 티켓을 볼 수 없게 되면 링크 전체가 열리지 않는다.
- 편집기 안의 `@` 태그 칩은 태그할 때의 이름으로 보인다. 사진·내려받는 파일은 링크가 열려 있는 동안만 받을 수 있다.
- 본문의 임베드(Figma·Google·Office·Outline)는 그 서비스의 주소를 그대로 보여 주므로 그쪽의 공개 설정을 따른다.

## 마우스 오버 카드 (D-201)

캘린더의 **막대에 마우스를 올리면** 브라우저의 기본 말풍선(`title`) 대신 작은 카드가 뜬다. **공유 화면과 로그인한 사용자의 캘린더(내 티켓·전체 티켓·프로젝트의 티켓) 모두** 같은 카드다.

- 내용(본문은 넣지 않는다): 키와 **제목**, **속성**(상태·우선순위·기한 또는 기간·라벨, 로그인한 캘린더는 담당자도), **프로젝트**, **요청자**(만든 사람), **최근 활동 3건**(최신순, "누가 무엇을 바꿨습니다 · 몇 분 전").
- 활동 줄: 로그인한 캘린더는 바뀐 값까지("상태를 바꿨습니다: 진행 중 → 완료"), 공유 화면은 바뀐 값 없이 종류까지만("님이 상태를 바꿨습니다"). 로그인한 캘린더는 카드가 뜰 때 `GET /api/v1/issues/{번호}/activity/recent?limit=3` 으로 불러오고(한 번 받으면 다시 받지 않는다), 공유 화면은 링크가 열릴 때 함께 받는다.
- 위치: 막대 아래에 왼쪽을 맞춰 뜨고, **화면 밖으로 나갈 것 같으면 위로 뒤집고 옆으로 밀어서** 항상 잘리지 않게 한다(바깥 여백 8px, Base UI `PreviewCard` 의 충돌 보정). 너비는 최대 20rem(320px).
- 열리는 때: 마우스가 막대 위에 0.3초 머물면 열리고 벗어나면 닫힌다. 키보드로 막대에 초점이 가도 열린다. **막대를 끄는 동안과 끝을 잡은 동안에는 열리지 않는다.** 터치 화면에는 없다(마우스 오버가 없으므로).
- "+N개 더" 목록의 줄과 타임라인의 막대에는 아직 없다.

## 내 공유 링크 (D-202)

내 설정(`/settings`)에 **"내 공유 링크"** 구역이 있다. 내가 만든 링크 중 쓰고 있는 것을 한곳에서 보고 지운다.

- 줄마다: 무엇을 공유한 링크인지(예: "2026년 10월 캘린더 · 담당 티켓", "2026년 10월 ~ 2026년 12월 타임라인 · 요청한 티켓", "FB-12 제목 티켓"), 만든 때, **접속 횟수와 마지막 접속**, 링크 주소와 "복사", **"접속 기록"**(누가 봤는지: 열린 때·브라우저와 OS·IP 주소·임베드한 페이지·하위 티켓이나 문서를 열었으면 그것, 최근 100건), **"삭제"**(= 공유 중지, 한 번 더 눌러 확인. 지우면 그 링크는 열리지 않는다).
- 공유 창(공유하기 단추)과 같은 링크·같은 기록이다. 여기서 지운 링크를 다시 공유하면 새 URL 이 나온다(D-197).
- 공개 링크는 로그인하지 않은 사람이 여므로 "누가"는 계정이 아니라 **접속한 곳의 IP 와 브라우저**다.
- 남의 링크는 보이지도 지워지지도 않는다(관리자도 이 화면에서는 자기 것만). 링크가 없으면 "만든 공유 링크가 없습니다. 캘린더·타임라인·티켓의 "공유하기"로 만듭니다."

## 화면

- **공유하기 단추**: 캘린더 맨 위 줄, "오늘" 단추 오른쪽. 누르면 창이 열리고 링크를 만든다(이미 있으면 그 링크).
- **공유 창**: 안내 문구, 링크(읽기 전용 칸 + "복사"), 임베드 코드("복사"), 최근 접속 기록(없으면 "아직 접속한 사람이 없습니다"), "공유 중지" 단추. 복사하면 단추가 잠깐 "복사했습니다"로 바뀐다.
- **공유 화면** `/s/{토큰}`: 위에 "{이름}님이 공유한 캘린더"와 "Flowbit 에서 공유됨", 그 달의 캘린더(달 이동·티켓 끌기·새 티켓 만들기 없음). 그 달이 아닌 날 칸에는 티켓을 그리지 않는다. 티켓은 눌러도 열리지 않는다(로그인이 필요한 화면이므로). 한 날에 티켓이 많으면 "+N개 더"가 그날의 티켓 목록을 연다(제목·키·상태, 링크 없음). 링크가 없거나 중지됐으면 "이 링크는 열 수 없습니다".

## 인수 기준

구현과 테스트 코드(`ShareIntegrationTest`, `RetentionIntegrationTest` 의 새 테스트 둘)는 썼고 컴파일·ktlint 까지 통과했다. **이 PC 에서는 Docker 가 꺼져 있어 통합 테스트를 돌리지 못했고(체크 안 함), 화면도 확인하지 않았다**(사용자 지시).

- [ ] 마우스 오버 카드: 캘린더 막대에 마우스를 올리면 제목·속성·프로젝트·요청자·최근 활동 3건이 카드로 뜨고(공유 화면에서도), 화면 가장자리의 막대에서는 카드가 잘리지 않도록 위치가 바뀐다. 끄는 동안에는 뜨지 않는다
- [ ] 공유 캘린더의 데이터에 우선순위·프로젝트 이름·만든 사람 이름·최근 활동 3건(값 없이)이 들어 있고 담당자·본문은 없다
- [ ] 내 설정: 내 링크 목록(접속 횟수·마지막 접속 포함)이 나오고, 접속 기록을 보고, 삭제하면 목록에서 사라지고 그 링크는 열리지 않는다. 남의 링크는 보이지 않는다
- [ ] 티켓: 고칠 수 있는 사람만 링크를 만들고(같은 티켓이면 같은 URL), 열면 제목·본문·하위 티켓 목록·문서 목록이 나오고 댓글·활동은 없다
- [ ] 티켓: 하위 티켓(몇 단계 아래든)과 그 문서는 같은 링크 안에서 열리고, 공유한 티켓의 위쪽 티켓·다른 티켓의 문서는 404. 열 때마다 `item` 이 있는 접속 기록이 남는다
- [ ] 티켓: 본문의 사진·파일은 링크 안의 주소로 바뀌어 내려오고, 본문에 없는 파일의 키는 404
- [ ] 타임라인: 같은 사람·탭·범위는 같은 URL, 범위가 다르면 다른 URL. 열면 그 기간에 걸친 티켓만 프로젝트 이름과 함께 나오고 본문·담당자·상위 티켓은 없다. 범위가 `from > to` 이거나 24개월을 넘으면 422
- [ ] 같은 사람이 같은 화면·같은 달·같은 탭으로 두 번 공유하면 같은 URL, 달이나 탭이 다르면 다른 URL, 다른 사람이 같은 달을 공유하면 다른 URL
- [ ] 로그인 없이 `GET /api/v1/public/shares/{토큰}` 이 그 달에 걸친 티켓만 돌려주고(담당 탭은 공유한 사람이 담당자인 것, 요청한 탭은 만든 것) 삭제된 티켓·다른 사람의 티켓·본문 같은 다른 필드는 없다
- [ ] 열 때마다 접속 기록이 쌓이고 공유한 사람이 `accesses` 로 읽는다(IP·브라우저·임베드 표시)
- [ ] 공유 중지 뒤 그 토큰은 열리지 않고, 다시 공유하면 다른 URL
- [ ] 데이터 보관의 "공유 링크 접속 기록" 기간이 지난 접속 기록만 지우고 나머지와 링크는 남긴다. 설정이 없으면 지우지 않는다
- [ ] `/s/*` 만 프레임에 넣을 수 있다
