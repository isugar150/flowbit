# 공유 링크

로그인하지 않아도 URL 만 알면 열 수 있는 **읽기 전용 공유 화면**을 만든다. 처음에는 **"내 티켓"의 캘린더**(한 달)를 공유하고, 나중에 티켓 같은 다른 화면에도 같은 구조를 쓴다. 사용자 지정(2026-10-23), 결정은 D-197·D-198.

## 사용자가 한 말

"내 티켓 > 캘린더에서 공유하기 버튼을 넣고, 누르면 현재 로그인한 계정을 해시화해서 URL 을 만든다. URL 을 아는 사람은 누구든 접근할 수 있고 특정 페이지에 임베드도 할 수 있다. 페이지와 공유한 사용자와 선택한 월이 같으면 같은 URL 이 나와야 한다. 다른 사람이 접근하면 인증 없이 이 사람의 그 달 캘린더만 보인다. 나중에 티켓 등에도 쓸 것이니 공통으로 쓸 수 있게 한다. 누가 공유한 링크에 어떤 클라이언트에서 접속했는지 히스토리를 남기고, 이것도 관리자 설정의 자동 정리 스케줄러에 넣는다."

## 범위

- 내 티켓 두 탭(담당 티켓·요청한 티켓)의 캘린더 보기 맨 위 줄의 **"공유하기"** 단추. 지금 보는 달이 공유할 달이다.
- 공유 링크 `/s/{토큰}`: 로그인 없이 열리는 읽기 전용 화면, **iframe 으로 다른 사이트에 넣을 수 있다**.
- **같은 링크는 같은 URL**: (화면 종류, 공유한 사람, 달, 탭)이 같으면 몇 번을 눌러도 같은 URL 이 나온다.
- **접속 기록**: 링크가 열릴 때마다 누가 공유한 링크인지(링크), 어느 클라이언트(IP, 브라우저)에서, 어디에 임베드돼 있는지 남기고, 공유한 사람이 공유 창에서 최근 기록을 본다.
- **공유 중지**: 링크를 끈다. 끈 링크는 열리지 않는다.
- 접속 기록은 관리자 설정 > "데이터 보관"의 **네 번째 항목**으로 기간을 정하면 서버가 주기적으로 지운다.

범위 밖(지금은 하지 않는다): 티켓 상세·문서 등 다른 화면의 공유(구조만 공통으로 만든다), 링크 만료일·비밀번호, 관리자가 모든 사람의 링크·기록을 한 화면에서 보기, 접속 알림, 공유한 사람 대신 관리자가 링크를 끄기.

## 구조: 공통으로 쓰는 부분

공유할 수 있는 것은 **종류**(`kind`) 하나와 그 종류의 **매개변수**(`params`)로 정해진다. 새로 공유할 화면을 만들 때 고치는 곳은 백엔드의 종류 하나(제공자 클래스)와 프런트의 화면 하나다. 링크 만들기·끄기·기록·정리는 그대로 쓴다.

| 종류 (`kind`) | 매개변수 | 공개되는 내용 |
|---|---|---|
| `MY_ISSUES_CALENDAR` | `month` = `YYYY-MM`, `scope` = `assigned`(담당 티켓)·`created`(요청한 티켓) | 공유한 사람의 그 탭 티켓 중 **그 달에 걸친** 티켓의 번호·키·제목·상태·시작일·기한 |

- 공개하는 값은 **종류마다 정한 최소한**이다. 캘린더는 프로젝트 이름·담당자·본문·댓글·첨부 같은 것은 내보내지 않는다. 티켓 제목은 보인다.
- 내용은 **열 때마다 공유한 사람의 지금 권한**으로 만든다. 공유한 사람이 들어갈 수 없게 된 프로젝트의 티켓, 삭제한 티켓은 빠진다. 공유한 사람이 비활성이면 링크는 열리지 않는다.
- 공유한 사람 이름은 표시 이름만 보인다(없으면 이름 없이 "공유된 캘린더"). 로그인 아이디는 내보내지 않는다.

## URL 과 토큰

- 주소: `/s/{토큰}`. 접속 주소(`FLOWBIT_PUBLIC_URL` 이 아니라 **지금 열린 주소**의 origin)를 앞에 붙여 보여 준다.
- 토큰은 서버가 만든 **256비트 난수**(URL 안전 base64, 43자)다. 계정을 해시한 값이 아니다(D-197: 해시로는 되돌려 찾을 수 없어 표를 두어야 하고, 계정에서 계산하는 값은 짐작·되돌릴 수 없는 폐기가 안 된다). 같은 입력에 같은 URL 이 나오는 것은 표의 `(owner_id, kind, target)` 가 같은 행을 다시 돌려주어서다.
- `target` 은 매개변수를 키 순서로 정렬한 `k=v&k=v` 문자열(정규형)이다. 매개변수는 종류마다 검사한다(`month` 는 `YYYY-MM`, 1900~2999년).
- **공유 중지** 뒤 다시 공유하면 **새 토큰**(다른 URL)이 나온다. 중지한 링크는 다시 살아나지 않는다.

## 임베드

- 공유 창에 **복사할 수 있는 iframe 코드**가 있다: `<iframe src="https://…/s/토큰" width="100%" height="640" style="border:0" loading="lazy"></iframe>`.
- `/s/*` 만 다른 사이트의 프레임 안에서 열린다(`Content-Security-Policy: frame-ancestors *`). 다른 모든 화면은 전처럼 같은 사이트의 프레임에서만 열린다(`next.config.ts`).
- 공유 화면은 쿠키·로그인 상태를 쓰지 않는다. 검색 엔진에는 `noindex` 를 알린다.
- 어디에 임베드됐는지는 화면이 `window.self !== window.top`·`document.referrer` 로 알아 접속할 때 함께 보낸다(**클라이언트가 말하는 값**이라 기록용일 뿐 믿지 않는다).

## 접속 기록

링크가 열릴 때마다 한 줄:

| 항목 | 내용 |
|---|---|
| 시각 | 서버 시계 |
| 링크 | 어느 공유 링크(→ 공유한 사람, 종류, 달) |
| IP 주소 | 요청의 `remoteAddress`(프록시 뒤에서는 `X-Forwarded-*` 를 따른다, `server.forward-headers-strategy=native`) |
| 브라우저 | `User-Agent`(512자까지) |
| 임베드 | 프레임 안에서 열렸는지, 그 페이지 주소(512자까지) |

- 존재하지 않는 토큰·중지된 링크의 접근은 기록하지 않는다(링크가 없다).
- 공유한 사람은 공유 창에서 **최근 20건**(시각·브라우저·OS·IP·임베드 여부)을 본다. 전체 기간의 기록은 DB 의 `share_accesses`.
- **자동 정리**: 관리자 설정 > "데이터 보관"의 항목 **"공유 링크 접속 기록"**(`shareAccesses`)에서 "영구 삭제 안 함" 또는 N일·주·개월을 정한다. 기본은 "영구 삭제 안 함". 기록한 시각 기준으로 기간이 지난 줄을 서버가 시작 1분 뒤와 1시간마다 지운다(다른 항목과 같은 작업, [admin-retention.md](admin-retention.md)). 지운 개수는 감사 로그 `DATA_PURGED` 의 `shareAccesses` 에 들어간다.
- 링크를 중지해도 기록은 남고 같은 기간 뒤에 지워진다.

## 한계와 보호

- **공개된 링크다**: 링크를 받은 사람이 다시 다른 사람에게 줄 수 있다. 공유 창이 "링크를 아는 누구나 이 달의 티켓 제목·상태·기간을 볼 수 있습니다"라고 알린다.
- 공개 API 는 **IP 별 요청 제한**(분당 120회)이 있다. 토큰은 256비트라 짐작할 수 없다. 토큰이 맞지 않는 모든 경우(없음·중지·공유한 사람 비활성)는 같은 `404` 로 답한다.
- 감사 로그: 링크를 만들 때(`SHARE_LINK_CREATED`, 이미 있는 링크를 다시 받을 때는 남기지 않는다)와 중지할 때(`SHARE_LINK_REVOKED`).

## API

| 메서드·경로 | 내용 |
|---|---|
| `POST /api/v1/shares` | 링크를 만들거나(없으면) 이미 있는 링크를 돌려준다. 본문 `{ "kind": "MY_ISSUES_CALENDAR", "params": { "month": "2026-10", "scope": "assigned" } }`. 응답 `{ id, kind, params, token, path, createdAt }`. 공유한 사람은 요청한 사람 |
| `DELETE /api/v1/shares/{id}` | 링크를 중지한다(204). 만든 사람만 |
| `GET /api/v1/shares/{id}/accesses` | 그 링크의 최근 접속 20건 `{ total, items: [{ accessedAt, ipAddress, userAgent, embedded, referrer }] }`. 만든 사람만 |
| `GET /api/v1/public/shares/{token}?embedded=&referrer=` | **로그인 없이.** 공유한 내용 `{ kind, sharedBy, params, content }` 를 돌려주고 접속을 기록한다. `Cache-Control: no-store` |

`content` 는 종류마다 다르다. `MY_ISSUES_CALENDAR`: `{ "issues": [{ "number", "key", "title", "status", "startDate", "dueDate" }] }`.

## 화면

- **공유하기 단추**: 캘린더 맨 위 줄, "오늘" 단추 오른쪽. 누르면 창이 열리고 링크를 만든다(이미 있으면 그 링크).
- **공유 창**: 안내 문구, 링크(읽기 전용 칸 + "복사"), 임베드 코드("복사"), 최근 접속 기록(없으면 "아직 접속한 사람이 없습니다"), "공유 중지" 단추. 복사하면 단추가 잠깐 "복사했습니다"로 바뀐다.
- **공유 화면** `/s/{토큰}`: 위에 "{이름}님이 공유한 캘린더"와 "Flowbit 에서 공유됨", 그 달의 캘린더(달 이동·티켓 끌기·새 티켓 만들기 없음). 그 달이 아닌 날 칸에는 티켓을 그리지 않는다. 티켓은 눌러도 열리지 않는다(로그인이 필요한 화면이므로). 한 날에 티켓이 많으면 "+N개 더"가 그날의 티켓 목록을 연다(제목·키·상태, 링크 없음). 링크가 없거나 중지됐으면 "이 링크는 열 수 없습니다".

## 인수 기준

구현과 테스트 코드(`ShareIntegrationTest`, `RetentionIntegrationTest` 의 새 테스트 둘)는 썼고 컴파일·ktlint 까지 통과했다. **이 PC 에서는 Docker 가 꺼져 있어 통합 테스트를 돌리지 못했고(체크 안 함), 화면도 확인하지 않았다**(사용자 지시).

- [ ] 같은 사람이 같은 화면·같은 달·같은 탭으로 두 번 공유하면 같은 URL, 달이나 탭이 다르면 다른 URL, 다른 사람이 같은 달을 공유하면 다른 URL
- [ ] 로그인 없이 `GET /api/v1/public/shares/{토큰}` 이 그 달에 걸친 티켓만 돌려주고(담당 탭은 공유한 사람이 담당자인 것, 요청한 탭은 만든 것) 삭제된 티켓·다른 사람의 티켓·본문 같은 다른 필드는 없다
- [ ] 열 때마다 접속 기록이 쌓이고 공유한 사람이 `accesses` 로 읽는다(IP·브라우저·임베드 표시)
- [ ] 공유 중지 뒤 그 토큰은 열리지 않고, 다시 공유하면 다른 URL
- [ ] 데이터 보관의 "공유 링크 접속 기록" 기간이 지난 접속 기록만 지우고 나머지와 링크는 남긴다. 설정이 없으면 지우지 않는다
- [ ] `/s/*` 만 프레임에 넣을 수 있다
