# M2a. 설정 화면과 이미지 업로드

상태: **구현됨** (2026-10-12). 사용자 요청: "왼쪽 아래 사용자에서 설정 버튼, 관리자 설정 버튼, 이미지 업로드, 저장 경로는 .env 로 지정, 업로드하면 WebP 변환과 해상도 최적화". 어떤 이미지를 올리는지와 화면 구성은 에이전트가 정했다(아래 "확인이 필요한 것").

백엔드는 통합 테스트 15개로 확인했다. **화면은 에이전트가 브라우저로 확인하지 못했다** (사용자 계정의 비밀번호를 모르기 때문). 린트와 타입 검사만 통과한 상태다.

M2(구성원과 워크스페이스 설정)의 일부를 먼저 만든 것이다. 구성원 추가·역할 변경·비밀번호 변경은 여기에 없다.

## 범위

포함:

- 사용자 메뉴(사이드바 왼쪽 아래)에 **설정**, 관리자에게는 **관리자 설정**도 표시
- 내 프로필 설정: 프로필 사진 올리기/바꾸기/삭제, 이름
- 관리자 설정(워크스페이스): 로고 올리기/바꾸기/삭제, 워크스페이스 이름
- 올린 이미지를 WebP 로 변환하고 용도에 맞는 크기로 줄여 저장
- 저장 폴더를 `.env` 의 `FLOWBIT_STORAGE_PATH` 로 지정
- 사이드바에 워크스페이스 로고와 이름, 사용자 메뉴에 프로필 사진과 이름 표시

제외:

- 티켓 본문·댓글의 이미지 첨부 (M3. 같은 저장소와 변환 코드를 쓴다)
- 사진 자르기 편집 UI (프로필 사진은 가운데 기준으로 자동으로 잘린다)
- 로그인 화면에 로고 표시 (이미지는 로그인한 사용자만 볼 수 있다)
- S3 같은 외부 저장소

## 화면

| 경로 | 내용 | 접근 |
|---|---|---|
| `/settings` | **내 설정**: 프로필 사진, 이름, 화면 테마(밝게 / 어둡게 / 기기 설정 따르기, 기본은 기기 설정 따르기) | 로그인한 사용자 |
| `/admin/workspace` | **관리자 설정**: 로고, 워크스페이스 이름 | 관리자. 구성원이 들어오면 홈으로 이동 |
| `/admin/members` | **관리자 설정**: 구성원 관리 ([M3-projects-and-issues.md](M3-projects-and-issues.md)) | 관리자 |

- **내 설정과 관리자 설정은 서로 다른 화면이다** (사용자 지정, D-037). 사용자 메뉴의 "내 설정"은 `/settings`, "관리자 설정"은 `/admin` 으로 간다. 한 화면에 탭으로 섞지 않는다.
- 관리자 설정 안에서만 탭("워크스페이스", "구성원")으로 나눈다.
- 화면 테마는 사용자 메뉴가 아니라 내 설정 안에 있다. 브라우저에만 저장되므로 기기마다 다르게 정할 수 있다.
- 이미지: 파일을 고르면 바로 올린다. 올리는 동안 버튼에 진행 표시. 실패하면 이유를 그 아래에 보여준다. 올리기 전에 브라우저에서 형식과 크기를 먼저 확인한다(서버가 다시 확인한다).
- 이름: 입력란과 "저장" 버튼. 바뀐 내용이 없으면 버튼이 비활성. 저장하면 "저장했습니다." 를 보여주고 사이드바와 사용자 메뉴에 바로 반영된다.
- 사진이 없으면 이름의 글자를 보여준다. 한글 이름은 마지막 두 글자("김지민" → "지민"), 그 밖에는 앞의 두 글자.

## 이미지 처리 규칙

| 용도 | 결과 크기 | 방식 |
|---|---|---|
| 프로필 사진 | 256 × 256 | 정사각형을 가득 채우고 넘치는 부분은 가운데 기준으로 잘라낸다 |
| 워크스페이스 로고 | 가로·세로 최대 512 | 비율을 지키며 줄인다. 이미 작으면 키우지 않는다 |

- 받는 형식: JPEG, PNG, WebP, GIF(첫 장면만). 저장 형식은 항상 **WebP**(품질 82).
- 최대 파일 크기: 기본 5MB, `FLOWBIT_MAX_UPLOAD_SIZE` 로 바꾼다. 넘으면 413 `FILE_TOO_LARGE`(문구에 설정한 크기가 들어간다). **화면은 이 값을 서버에서 받아 쓴다**(D-174): 공개 `GET /api/v1/upload-limit` → `{ maxUploadBytes }`. 로그인한 화면은 서버 렌더에서 받고(`getUploadLimit`, `UploadLimitProvider`), 초기 설정 화면은 열린 뒤에 묻는다. 사진 올리기·편집기 이미지·티켓 첨부·댓글 파일이 미리 거르는 크기와 안내 문구("10MB까지")가 모두 이 값이다.
- 가로×세로가 4천만 화소를 넘으면 풀지 않고 거부한다(422 `IMAGE_DIMENSIONS_TOO_LARGE`). 파일은 작아도 풀면 메모리를 다 쓰는 이미지를 막기 위해서다. 화소 수는 파일 머리말만 읽어서 판단한다.
- 이미지로 읽을 수 없으면 422 `UNSUPPORTED_IMAGE`. 파일 이름이나 `Content-Type` 은 믿지 않고 내용으로 판단한다.
- 다시 인코딩하므로 원본의 EXIF(위치, 기기 정보)는 저장되지 않는다. 사진의 회전 정보는 반영된다.
- **올린 원본도 따로 저장한다**(D-169, 2026-10-22; 그 전에는 저장하지 않았다). 화면에는 WebP 사본만 내려 주고 원본은 복구용이다. 사본은 줄이고 손실 압축한 것이라 원래 사진을 되살릴 수 없어서, 서버를 잃어도 원본으로 다시 만들 수 있게 했다. 원본에는 EXIF 가 그대로 있다(바깥에 내려 주지 않는다).

## 저장

- 폴더: `FLOWBIT_STORAGE_PATH` (기본 `./data/uploads`, 백엔드를 실행한 폴더 기준). 그 아래 `images/`(WebP 사본), `originals/`(올린 원본), `files/`(첨부 파일)에 저장한다. 폴더가 없으면 시작할 때 만든다. **D-167 부터 `FLOWBIT_S3_BUCKET` 이 있으면 폴더 대신 S3 의 `<접두어>/images/`·`originals/`·`files/` 에 저장한다**([02-architecture.md](../02-architecture.md) "파일 저장소"). 어느 쪽이든 키(파일 이름)와 DB 에 두는 것은 같다.
- 파일 이름: 서버가 만든 무작위 UUID + `.webp`. 사용자가 준 파일 이름은 쓰지 않는다. 원본은 같은 UUID 에서 `.webp` 를 뺀 이름(확장자 없음)으로 `originals/` 에 둔다. 원본을 먼저 올리고 사본을 올리며, 어느 쪽이든 못 올리면 업로드가 실패하고 올라간 쪽은 지운다.
- 이미지를 바꾸거나 지우면 이전 파일(과 그 원본)을 지운다. 새 이미지는 새 이름을 받으므로 같은 주소의 내용은 바뀌지 않는다.
- DB 에는 파일 이름만 저장한다: `users.avatar_key`, `instance_settings.logo_key` (마이그레이션 `V2`).
- 백엔드는 `.env` 파일을 직접 읽는다: 저장소 루트의 `.env`(백엔드를 `backend/` 에서 실행할 때)와 실행 폴더의 `.env`. 실제 환경 변수가 있으면 그것이 우선한다.
- **백업 대상이다.** 이 폴더를 잃으면 이미지가 모두 사라진다. 운영에서는 백업되는 절대 경로를 지정한다. S3 에 두면 버킷이 그 몫을 한다(버킷의 버전 관리·복제는 S3 쪽 설정).

## API

공통 규칙과 오류 형식은 [../06-api-conventions.md](../06-api-conventions.md). 모두 로그인이 필요하다.

| 메서드와 경로 | 설명 | 응답 |
|---|---|---|
| `GET /api/v1/me` | `displayName`, `avatarUrl` 이 추가됐다 | 내 정보 |
| `PATCH /api/v1/me` | `{ "displayName": "김지민" }`. 앞뒤 공백 제거, 최대 50자. 비우면 지워진다 | 내 정보 |
| `PUT /api/v1/me/avatar` | `multipart/form-data`, 파일은 `file` 파트 | 내 정보 |
| `DELETE /api/v1/me/avatar` | 프로필 사진 삭제 | 내 정보 |
| `GET /api/v1/workspace` | 워크스페이스 이름과 로고 | `{ "name": "...", "logoUrl": "..." \| null }` |
| `PATCH /api/v1/admin/workspace` | `{ "name": "..." }`. 1~100자. **관리자** | 워크스페이스 |
| `PUT /api/v1/admin/workspace/logo` | `multipart/form-data`, `file` 파트. **관리자** | 워크스페이스 |
| `DELETE /api/v1/admin/workspace/logo` | 로고 삭제. **관리자** | 워크스페이스 |
| `POST /api/v1/images` | `multipart/form-data`, `file` 파트. 편집기 본문에 넣을 이미지. 1600px 안으로 줄인 WebP. 로그인한 누구나 (D-052) | 201 `{ "url": "/api/v1/files/<key>" }` |
| `GET /api/v1/files/{key}` | 저장된 이미지. `image/webp`, 1년 캐시(`private, immutable`) | 파일 |

- `/api/v1/admin/**` 는 관리자 역할이 아니면 403 `FORBIDDEN`. 이후의 관리자 전용 API 도 이 경로 아래에 둔다.
- `avatarUrl`, `logoUrl` 은 `/api/v1/files/<key>` 형태의 같은 출처 경로다.

## 인수 기준

백엔드 통합 테스트(`SettingsIntegrationTest`)가 있는 것:

- [x] 이름을 바꾸면 내 정보에 반영되고, 비우면 지워진다. 50자를 넘으면 거부한다
- [x] 프로필 사진을 올리면 256px 정사각형 WebP 로 저장된다
- [x] JPEG, PNG, WebP 를 올릴 수 있다
- [x] 사진을 바꾸면 이전 파일이 지워지고 주소가 바뀐다. 삭제하면 파일도 지워진다
- [x] 이미지가 아닌 파일, 설정한 크기(기본 5MB)를 넘는 파일, 화소 수가 지나치게 큰 이미지는 거부하고 아무것도 저장하지 않는다
- [x] 업로드 제한은 로그인하지 않아도 `GET /api/v1/upload-limit` 로 읽을 수 있고 설정한 값을 준다 (`SettingsIntegrationTest`, 돌리지 않음. D-174)
- [x] 로그인하지 않으면 올리거나 볼 수 없다
- [x] 파일 주소로 저장 폴더 밖의 파일을 읽을 수 없다
- [x] 관리자는 워크스페이스 이름과 로고를 바꿀 수 있다. 로고는 비율을 지키며 512px 안으로 줄고, 작은 로고는 키우지 않는다
- [x] 구성원은 워크스페이스를 볼 수 있지만 바꿀 수 없다 (403)

화면에서 확인이 필요한 것 (자동 테스트 없음, 에이전트가 보지 못함):

- [ ] 사용자 메뉴에 "설정"이 보이고, 관리자에게만 "관리자 설정"이 보인다
- [ ] 사진을 올리면 설정 화면, 사이드바, 사용자 메뉴에 바로 반영된다
- [ ] 오류(형식, 크기)가 이미지 아래에 한국어로 보인다
- [ ] 다크 모드와 좁은 화면에서 깨지지 않는다

## 확인이 필요한 것

1. 올릴 이미지의 종류를 "프로필 사진"과 "워크스페이스 로고"로 정했다. 다른 이미지(예: 티켓 첨부)를 뜻했다면 알려 달라.
2. 프로필 사진 256px, 로고 512px, 품질 82, 최대 5MB.
3. 이미지는 로그인한 사용자만 볼 수 있다. 로그인 화면에 로고를 보여주려면 로고만 공개로 바꿔야 한다.
