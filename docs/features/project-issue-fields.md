# 프로젝트 공통 티켓 속성과 설정 목차

2026-10-28 사용자 요청으로 확정. 프로젝트에서 정한 속성을 기존·새 티켓 모두에 표시하며, 사람 형식 속성을 자동화 알림 대상으로 사용한다.

## 공통 속성

- 프로젝트 설정과 관리자 설정 > 프로젝트의 **티켓 속성**에서 이름·형식·기본값을 정의한다. 기존 사용자 속성의 텍스트·숫자·날짜·체크박스·링크·사람을 지원한다. 이름 1~30자, 프로젝트당 20개, 같은 프로젝트 안에서 대소문자 구분 없이 유일하다. 형식은 만든 뒤 바꾸지 않는다.
- 공통 속성은 모든 기존 티켓, 새 티켓 창, 이후 만드는 티켓에 자동 표시한다. 티켓에서 항목을 삭제·이름 변경할 수 없다. 값은 티켓마다 편집하며 비워 둘 수 있다. '강제'는 항목의 존재를 뜻하며 값 입력을 필수로 막지는 않는다.
- 기본값은 아직 값을 지정하지 않은 티켓에 적용된다. 명시적으로 값을 비운 티켓은 비운 상태를 유지한다. 기본값 변경은 티켓별 값을 덮어쓰지 않는다. 기본값을 사람으로 지정할 수도 있다.
- 같은 이름·형식의 기존 개별 티켓 속성은 공통 속성으로 편입하고 값을 보존한다. 같은 이름인데 형식이 다르면 설정을 거부하고 다른 이름을 안내한다. 공통 속성 이름을 개별 속성으로 다시 추가할 수 없다.
- 공통 속성 삭제는 모든 티켓의 해당 값도 삭제하며 화면에서 확인한다. 정의를 삭제한 자동화 알림 블록은 대상을 찾지 못하면 건너뛰고 실행 기록에 남긴다. 티켓 이동 시 도착 프로젝트의 공통 속성을 표시한다. 이전 프로젝트 값은 숨겨 보존하며 돌아가면 복원된다. 복제는 지정한 공통 속성 값도 복사한다.
- **사람 형식은 한 명만 받을지 여러 명을 받을지 고른다**(D-238, 2026-10-28). 속성을 만들 때 "여러 명 선택 가능"이 기본으로 켜져 있고, 끄면 티켓마다 한 명만 고른다. 만든 뒤에 바꿀 수 있다: 한 명 → 여러 명이면 이미 고른 값이 한 명짜리 목록이 되고, 여러 명 → 한 명이면 티켓마다 맨 앞 사람만 남는다. 여러 명이면 값은 사용자 id 의 목록이고(순서 유지, 중복 없음, 50명까지), 모두 프로젝트 구성원이어야 한다. 개별 사용자 속성의 사람은 그대로 한 명이다.
- **하위 티켓은 만들 때 상위 티켓이 직접 지정한 공통 속성 값을 이어받는다**(D-239). 요청이 값을 준 속성은 그 값이 이기고, 상위에 지정값이 없는 속성은 프로젝트 기본값이다. 그 뒤에는 상위와 하위가 따로 바뀐다(담당자와 같다). 개별 사용자 속성은 이어받지 않는다.
- 개별 사용자 속성은 기존대로 별도로 최대 20개 지원한다. 공통 속성은 이 개수에서 제외한다.

## 자동화

알림 대상에 **티켓의 사람 속성**을 추가한다. 같은 프로젝트의 사람 형식 공통 속성(예: 리뷰어)을 선택한다. 실행 당시 그 티켓의 값(미지정이면 프로젝트 기본값)을 읽는다. 여러 명을 받는 속성이면 고른 사람 모두에게 보낸다. 값이 없거나 비활성·접근 불가인 사람은 알리지 않는다. 수동·보드·Git 상태 변경에 동일하게 적용한다.

## 설정 목차

프로젝트 설정의 왼쪽에 설정·공개 범위·사이클·트리아지·티켓 속성·자동화·추정치·구성원·Git 저장소(사용할 때만)·아카이브 목차를 표시한다. 누르면 해당 구역으로 스크롤하고, 스크롤할 때 현재 구역을 강조한다. 좁은 화면은 목차를 위에 줄바꿈해서 표시한다. 관리자 설정의 프로젝트에서도 같은 목차를 사용한다. 숨겨진 이전 페이지의 요소를 찾지 않고 현재 설정 영역 안에서만 이동한다.

## API / 데이터

- GET·POST `/api/v1/projects/{id}/issue-fields`, PUT·DELETE `…/{fieldId}`. 관리자는 `/api/v1/admin/projects/{id}/issue-fields`에서도 설정한다. 읽기는 프로젝트 접근 권한, 쓰기는 관리 역할(관리자 경로는 관리자 역할).
- PUT `/api/v1/custom-properties/issue/{issueId}/project-fields/{fieldId}`: `{value}`. 티켓 편집 권한 필요, 값 변경은 기존 사용자 속성 활동·알림 경로를 사용한다.
- 기존 사용자 속성 조회 응답에 공통 속성도 포함한다. `projectFieldId`가 있는 행은 프로젝트 관리 항목이다.
- 새 티켓 `projectFields: [{fieldId, value}]`로 값을 함께 저장한다. 보내지 않은 항목은 기본값을 사용한다.
- V16: `project_issue_fields`(프로젝트·이름·형식·기본값), `issue_field_values`(티켓·속성·값). 정의를 조회 시 합성하므로 기존 티켓마다 빈 행을 만들지 않는다. 프로젝트·티켓 영구 삭제 시 관련 값도 함께 삭제한다.
- V17: `project_issue_fields.multiple`(기본 true, D-238). 정의의 요청·응답에 `multiple`, 응답에 `people`(기본값이 가리키는 사람들; `person` 은 그 첫 사람)이 있다. 여러 명인 속성의 `defaultValue`·티켓 값은 id 목록, 한 명이면 id 하나. 티켓의 속성 응답(`/custom-properties/issue/{id}`)도 `multiple`·`people` 을 담는다.
- 자동화 `audience=PROJECT_FIELD`, `fieldId`로 알림 대상을 지정한다. 설정 감사 종류 PROJECT_ISSUE_FIELDS_CHANGED.

## 검증 범위

공통 속성의 기존·신규 티켓 노출, 기본값·티켓별 값·빈 값, 기존 값 편입, 자동화에서 해당 사람 알림, 복제·이동을 관련 통합 테스트로 확인한다. 전체 백엔드 검사를 반복하지 않는다. 프런트는 lint·typecheck를 기본으로 확인하고 새 서버/클라이언트 구성은 빌드 1회로 확인한다. 화면 조작은 기존 사용자 지시에 따라 하지 않는다.

## 내 티켓 포함 (2026-10-28)

내 티켓의 assigned 범위는 기본 담당자이거나 현재 프로젝트의 공통 PERSON 속성에 본인이 지정된 티켓을 포함한다. 단일·복수 사람 모두 지원하며, 티켓 지정값이 없을 때만 프로젝트 기본값을 사용한다. 명시적 빈 값은 기본값을 적용하지 않는다. 개별 사용자 속성은 포함하지 않는다. 여러 조건에 맞아도 한 번만 표시한다. 기존 접근 권한·삭제 여부·정렬·한도를 유지한다. 같은 assigned 범위를 쓰는 캘린더·타임라인·공유 조회에도 적용한다.
