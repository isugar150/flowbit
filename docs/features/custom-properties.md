# 사용자 속성

프로젝트·목표·티켓에 **사용자가 직접 속성을 더한다**. 이름(label)과 값 형식을 정하면 그 항목에 값을 넣는 칸이 생긴다. 예: 이름 "배포예정일", 형식 "날짜" → 날짜를 고르는 칸. 결정은 [D-186](../09-decisions.md).

## 정한 것

| 항목 | 내용 | 정한 사람 |
|---|---|---|
| 속성은 어디에 있나 | **항목마다 따로.** 정의를 공유하는 "종류별 속성 정의"가 아니다. 같은 속성을 다른 항목에 쓰려면 그 항목에서 다시 더한다 | 사용자 (질문 답) |
| 누가 더하고 지우나 | **편집 역할 이상**: 프로젝트와 목표는 그 프로젝트의 편집·관리 역할, 티켓은 티켓을 고칠 수 있는 사람(프로젝트에 연결된 티켓은 그 프로젝트의 편집 역할, 연결 안 된 티켓은 누구나). 값을 채우는 사람도 같다. 보기 역할은 읽기만 한다 | 사용자 (질문 답) |
| 값 형식 | **텍스트 · 숫자 · 날짜 · 체크박스 · 링크 · 사람** 여섯 가지 | 사용자 (다섯 가지에 "사람"을 더해 달라고 함. 이름은 "글자"가 아니라 "텍스트"로 쓰라고 함) |
| 사람은 한 명인가 | 한 명. 담당자(여러 명)와 달리 "QA 담당"처럼 한 자리를 채우는 값으로 본다 | 에이전트 |
| 형식을 바꿀 수 있나 | 못 바꾼다. 지우고 다시 더한다 | 에이전트 |

## 규칙

- 이름은 1~30자(앞뒤 공백 제외). 한 항목 안에서 **대소문자 없이 겹칠 수 없다**(409 `CUSTOM_PROPERTY_EXISTS`). 다른 항목에는 같은 이름을 쓸 수 있다.
- 한 항목에 **20개까지**(21번째를 더하면 422 `TOO_MANY`). 순서는 더한 차례다.
- 값은 없을 수 있다(`null`). 체크박스는 늘 켜짐/꺼짐이라 꺼진 채로 시작한다.

| 형식 | 값 | 확인 |
|---|---|---|
| 텍스트 `TEXT` | 문자열 | 앞뒤 공백을 지운다, 500자까지(422 `TOO_LONG`), 비면 값 없음 |
| 숫자 `NUMBER` | 숫자 | 문자열은 거부(422 `INVALID`), 절댓값 1조 미만(422 `OUT_OF_RANGE`). 정수로 떨어지면 정수로 저장 |
| 날짜 `DATE` | `YYYY-MM-DD` | 없는 날짜는 거부, 빈 문자열은 값 없음 |
| 체크박스 `CHECKBOX` | 참/거짓 | 그 밖의 값은 거부, `null` 은 거짓 |
| 링크 `LINK` | 주소 | `http://` 또는 `https://` 와 호스트가 있어야 한다(422 `NOT_A_LINK`), 500자까지. `javascript:` 같은 것은 거부 |
| 사람 `PERSON` | 사용자 id | 프로젝트에 속한 활성 구성원만(422 `NOT_A_MEMBER`). 프로젝트가 없는 티켓은 활성 사용자 누구나. 이미 그 값인 사람은 프로젝트에서 빠졌어도 다시 검사하지 않는다(담당자와 같다) |

## API

`type` 은 `project` · `milestone` · `issue`, `id` 는 그 행의 id(티켓은 번호가 아니라 `id`).

| 요청 | 설명 |
|---|---|
| `GET /api/v1/custom-properties/{type}/{id}` | `{ canEdit, items: [{ id, label, type, value, person }] }`. 읽을 수 있는 사람이면 누구나. `person` 은 사람 형식의 값을 풀어 쓴 것(`id`, `loginId`, `displayName`, `avatarUrl`). 볼 수 없는 항목은 404 |
| `POST /api/v1/custom-properties/{type}/{id}` | `{ label, type, value? }` → 201 + 만든 속성 |
| `PATCH /api/v1/custom-properties/{propertyId}` | `{ label?, value? }` 있는 것만 바꾼다. 형식은 못 바꾼다(`type` 은 무시) |
| `DELETE /api/v1/custom-properties/{propertyId}` | 204 |

쓰기에 편집 권한이 없으면 403, 항목이 없거나 볼 수 없으면 404. 삭제된 티켓은 읽기만 된다(복원하면 다시 고친다).

## 화면

- **프로젝트**: 개요 오른쪽 "속성" 카드의 맨 아래(만든 날 아래). 값은 다른 속성처럼 알약 모양.
- **목표**: 상세 창 오른쪽 "속성" 목록의 맨 아래(목표일 아래). 티켓 옆 읽기 전용 패널에서는 값만 보인다.
- **티켓**: 오른쪽 속성 패널 맨 아래에 "사용자 속성" 묶음. 새 티켓 창에는 없다(만든 뒤에 더한다).
- 줄마다 왼쪽에 이름, 오른쪽에 값 칸과 "…" 메뉴(삭제). 맨 아래 "속성 추가"를 누르면 이름과 값 형식을 고르는 작은 창이 열린다.
- 텍스트·숫자·링크는 칸에 쓰고 Enter 나 칸을 벗어날 때 저장된다(Esc 는 쓰던 것을 버린다). 숫자는 쉼표를 지워 읽고 숫자가 아니면 원래 값으로 돌아간다. 날짜는 달력, 사람은 구성원 목록, 체크박스는 누르는 즉시 저장.
- 링크는 칸 옆 아이콘(읽기 전용은 글자 자체)을 누르면 새 탭으로 열린다(`rel="noopener noreferrer"`).
- 값은 바로 바뀌어 보이고 서버가 거절하면 원래 값으로 돌아가며 이유가 글자로 나온다. 다른 사람이 바꾸면 실시간으로 다시 읽는다(프로젝트·목표는 `project:{id}`, 티켓은 `issue:{번호}` 알림으로 페이지가 다시 그려질 때).

## 활동과 알림

속성을 **더하거나, 값을 바꾸거나, 이름을 바꾸거나, 지우면** 그 항목의 활동에 한 줄이 남는다(프로젝트·목표는 `content_activities`, 티켓은 `issue_activities`, 종류 `CUSTOM_PROPERTY_CHANGED`). `detail` 은 `{ op, label, from?, to? }`:

| `op` | 뜻 | 문구 |
|---|---|---|
| `ADDED` | 더함 (`to`: 처음 값, 없으면 생략) | 님이 속성을 추가했습니다: 배포예정일 = 2026-11-01 |
| `CHANGED` | 값을 바꿈 (`from`, `to`) | 님이 '배포예정일' 속성을 바꿨습니다: 2026-11-01 → 2026-12-01 |
| `RENAMED` | 이름을 바꿈 (`from`, `to`) | 님이 속성 이름을 바꿨습니다: 배포예정일 → 출시일 |
| `REMOVED` | 지움 (`from`: 마지막 값) | 님이 속성을 삭제했습니다: 출시일 |

값은 사람이 읽는 말로 적는다(사람은 이름, 체크박스는 예/아니요). 같은 값을 다시 저장하면 남기지 않는다.

알림은 다른 변경과 같다: 티켓은 티켓 구독자와 프로젝트 구독자에게, 프로젝트와 목표는 프로젝트 구독자에게 모아서 간다(D-126). 메일·푸시·API 알림 문구는 `속성 추가: 이름 = 값`, `이름: 이전 → 새 값`, `속성 삭제: 이름`, `속성 이름: 이전 → 새 이름`. **API 알림의 "보낼 변경" 목록에는 이 종류가 없다**(고를 수 없다).

## 데이터

`custom_properties` ([05-data-model.md](../05-data-model.md)), 마이그레이션 `V3__custom_properties.sql`. 항목이 영구 삭제되면 함께 지워진다(`ON DELETE CASCADE`).

## 아직 없는 것

- **속성으로 찾기·거르기·정렬·묶기**(목록, 검색), 목록의 열로 보이기.
- 선택(고정 목록) 형식, 사람 여러 명, 여러 줄 글, 형식 바꾸기.
- 새 티켓·새 프로젝트를 만들 때 속성을 함께 정하기, 속성 이름 바꾸기 화면(API 는 된다).
- 다른 항목에서 쓴 이름·형식을 제안하기, 항목끼리 속성 복사.
- 백업·복원에는 들어가지 않는다(티켓·프로젝트와 같다).
