# 검색: 티켓과 문서

어디서나 티켓과 문서를 찾는다. 사용자 지정(2026-10-15), 결정은 D-133. 화면은 [01-product.md](../01-product.md) 4.6(커맨드 팔레트)·4.8(검색 결과)을 따르되, 이번에는 **찾기만** 한다(팔레트의 액션 실행은 아직 없다).

## 범위

- **검색 창**: 어느 화면에서든 `Ctrl/⌘+K` 또는 `/`(글을 쓰는 중이 아닐 때), 사이드바의 "검색", 좁은 화면 위쪽 줄의 돋보기. 화면 위쪽 가운데의 창(폭 640px, 좁은 화면은 거의 전체), 결과는 티켓·문서로 묶어 각각 5개까지
- **검색 결과 페이지** (`/search?q=&type=`): 같은 검색을 더 많이(종류마다 50개까지) 본다. 탭 "전체 / 티켓 / 문서"
- 찾는 것: 티켓은 제목, 본문, 댓글, 번호(`FB-12`, `12`, `#12`). 문서는 제목과 본문
- **볼 수 있는 것만** 나온다: 티켓 목록과 같은 규칙(독립 티켓은 모두, 프로젝트 티켓은 그 프로젝트의 구성원만, 아카이브된 프로젝트는 빠짐). 삭제된 티켓·문서, 삭제된 문서 안의 문서, 삭제된 댓글은 나오지 않는다

범위 밖: 프로젝트·사람·업데이트 검색, 필터 칩(상태·담당자·기간), 조사 무시("결제를" → "결제"), 한/영 자판 실수 보정, 오타 허용, 팔레트의 액션 실행, 최근 본 티켓.

## 찾는 규칙

- 검색어는 앞뒤 공백을 지우고 1~100자. 공백으로 나눈 낱말(5개까지)이 **모두** 들어 있어야 한다. 대소문자는 가리지 않는다. `%`·`_` 는 글자 그대로 찾는다
- 낱말은 티켓이면 제목·본문·댓글 중 어디에 있어도 된다(낱말마다 다른 곳이어도 된다). 문서면 제목·본문
- **초성**: 검색어가 한글 자음(ㄱ~ㅎ)과 공백뿐이면 제목의 초성으로 찾는다(`ㄱㅈ` → "결제 개편"). DB 함수 `hangul_initials(text)`
- **번호**: `FB-12`(워크스페이스 키, 대소문자 무관)·`12`·`#12` 는 그 번호의 티켓을 맨 위에 놓는다. 제목에 "12" 가 든 티켓도 함께 나온다
- 순서: 번호가 맞는 티켓 → 제목에 모든 낱말이 든 것 → 나머지, 같은 단계 안에서는 최근에 바뀐 것부터
- 결과마다 **찾은 곳 조각**(`snippet`): 제목 밖에서 찾았으면 본문이나 댓글에서 첫 낱말 앞 30자·뒤 90자쯤. 화면은 조각과 제목 안의 낱말을 강조한다

## API

`GET /api/v1/search?q=결제&limit=5` (로그인한 누구나). `limit` 은 1~50, 기본 20.

```json
{
  "issues": [
    {
      "id": "…", "key": "FB-12", "number": 12, "title": "결제 버튼이 두 번 눌린다",
      "status": "IN_PROGRESS", "priority": "HIGH",
      "project": { "id": "…", "name": "결제 개편" },
      "match": "TITLE", "snippet": null, "updatedAt": "…"
    }
  ],
  "documents": [
    {
      "id": "…", "title": "회의록", "updatedAt": "…",
      "issue": { "key": "FB-12", "title": "…" }, "project": null,
      "snippet": "…결제 실패 원인은 …"
    }
  ],
  "issuesMore": false,
  "documentsMore": false
}
```

- `match`: `KEY`(번호)·`TITLE`·`DESCRIPTION`·`COMMENT`. `snippet` 은 `DESCRIPTION`·`COMMENT` 일 때 그곳의 조각, `TITLE` 이면 본문에도 있을 때만 본문 조각.
- 문서의 `issue` 와 `project` 는 둘 중 하나만 있다(티켓의 문서 / 프로젝트의 문서).
- `…More`: `limit` 보다 많이 맞았다.
- 빈 검색어는 빈 결과(200). 100자를 넘으면 422.

## 화면

- 검색 창: 입력칸(돋보기 아이콘, 오른쪽에 불러오는 중 표시), 아래에 "티켓"·"문서" 묶음. 줄 = 상태 아이콘·번호·제목(강조)·오른쪽에 프로젝트, 조각이 있으면 둘째 줄. 문서 줄 = 문서 아이콘·제목·오른쪽에 속한 곳(`FB-12` 또는 프로젝트 이름).
- 글자를 치면 150ms 쉬었다가 찾는다. 새 결과가 오기 전까지 앞의 결과를 그대로 둔다(깜박이지 않게).
- 키보드: `↑`/`↓` 로 옮기고(맨 끝에서 처음으로), `Enter` 로 연다(한글 조합 중의 `Enter` 는 무시), `Esc` 로 닫는다. 마우스를 올린 줄이 고른 줄이 된다. 아래쪽에 "모든 결과 보기"(`/search`)와 키 안내.
- 티켓은 지금 화면 위의 티켓 창으로(`/issue/FB-12`), 문서는 문서 화면(`/doc/{id}`)으로 연다.
- **열고 닫을 때 움직임이 없다.** 하루에 수십 번 쓰는 키보드 기능이라 바로 뜨고 바로 닫힌다(스킬 `emil-design-eng`, `better-ui`).
- 빈 검색어: 무엇을 찾을 수 있는지 안내(제목·본문·댓글·번호·초성). 결과 없음: "'검색어'에 맞는 티켓이나 문서가 없습니다".

## 인수 기준

2026-10-15 구현만 했고 아무것도 돌려 보지 않았다(사용자 요청으로 검사·화면 확인 생략). 통합 테스트도 아직 없다.

- [ ] 제목·본문·댓글·번호로 티켓을, 제목·본문으로 문서를 찾는다
- [ ] 낱말이 여럿이면 모두 들어 있어야 한다
- [ ] 초성으로 제목을 찾는다
- [ ] 들어갈 수 없는 프로젝트의 티켓·문서, 삭제된 티켓·문서·댓글은 나오지 않는다
- [ ] 번호가 맞는 티켓이 맨 위다
- [ ] `%` 는 글자 그대로 찾는다, 100자를 넘으면 422, 로그인하지 않으면 401
- [ ] 화면 확인 (검색 창 키보드 조작, 결과 페이지, 좁은 화면)
