# 알림 수신함(종)과 하루 요약

상태 (2026-10-26): **구현했다.** 화면은 확인하지 않았다. 사용자 요청(2026-10-26), 결정은 D-216. 알림 통로(메일·웹 푸시·API 알림, [M7a](M7a-notification-channels.md))는 앱 밖으로 알리는 것이고, 이 명세는 **앱 안**에서 보는 수신함(사이드바 아래의 종)과, 정한 시각에 보내는 **하루 요약**이다.

## 1. 수신함 (종)

사이드바 맨 아래 사용자 메뉴 **오른쪽에 종 버튼**이 있다(좁은 화면은 위쪽 줄의 사용자 메뉴 왼쪽). 종 위에 **읽지 않은 알림 수**가 숫자로 붙는다(99를 넘으면 `99+`, 없으면 숫자 없음).

- 누르면 **알림 목록**이 열린다(최근 30건, 최신순). 한 건은 제목(`[FB-12] 티켓 제목`), 머리말(`김지민 님이 티켓을 수정했습니다`), 변경 줄 최대 3개(넘으면 `외 N줄`), 몇 분 전. 읽지 않은 것은 앞에 점과 옅은 배경, 제목이 굵다.
- 한 건을 누르면 **그 알림이 가리키는 곳이 열리고 읽음**이 된다(티켓 `/issue/FB-12`, 문서 `/doc/…`, 프로젝트 접근 요청은 프로젝트 설정). 위쪽 **"모두 읽음"** 은 전부 읽음으로 한다.
- **그 화면을 열면 그 화면에 대한 알림이 읽음이 된다** (사용자 지정, D-217). 종에서 누르든, 메일·푸시의 링크든, 주소를 직접 쳐서 들어가든 같다. 앱이 화면을 열 때마다(읽지 않은 알림이 있고 탭이 앞에 있을 때만) 서버에 그 화면의 주소를 알리고(`POST /api/v1/me/inbox/read-path`), 서버는 알림의 주소(`#` 뒤는 뺀 것, 대소문자 무시)가 그 주소인 안 읽은 알림을 읽음으로 한다. 티켓 `/issue/FB-12`, 문서 `/doc/<id>`, 프로젝트 개요 `/project/<id>`, 프로젝트 접근 요청은 `/project/<id>/settings`. 탭이 뒤에 있다 앞으로 오거나, 그 화면을 보는 중에 새 알림이 와도 읽음이 된다(이미 보고 있으므로). 알림이 하나도 안 읽혀 있으면 서버를 부르지 않는다. 주소가 `/issue/12`(번호만)이거나 워크스페이스 키를 바꾸기 전의 알림은 맞지 않아 종에서 눌러야 읽음이 된다.
- 새 알림이 오거나 다른 탭에서 읽으면 **새로 고침 없이** 숫자가 바뀐다(실시간 `inbox:<내 id>`, 본인만 들을 수 있다). 목록이 열려 있으면 다시 읽는다.
- **무엇이 쌓이는가**: 다른 통로가 알리는 것과 **같은 것, 같은 받는 사람, 같은 문구**다. 티켓·프로젝트·문서의 구독자가 받는 변경, 댓글에서 태그된 사람, 프로젝트 접근 요청의 관리 역할. 내가 한 변경은 나에게 오지 않는다. 메일 주소가 없거나 푸시를 안 켠 사람도 수신함에는 쌓인다(설정이 필요 없는 통로). Git 서버의 링크·커밋(API 알림이 직접 고른 경우에만 가는 것)은 쌓지 않는다.
- **얼마나 두는가**: 90일이 지난 것은 읽었든 안 읽었든 지운다(1시간에 한 번 정리). 목록은 최근 30건만 보인다. 앱 안에 전체 수신함 페이지는 아직 없다(범위 밖).

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/me/inbox?limit=30` | `{ items: [{ id, title, headline, lines, path, createdAt, read }], unreadCount }`. `limit` 1~100. `unreadCount` 는 목록에 없는 것까지 센 전체 |
| GET | `/api/v1/me/inbox/unread-count` | `{ count }`. 페이지가 서버에서 읽어 종에 넘긴다 |
| POST | `/api/v1/me/inbox/read` | `{ ids: [...] }` 또는 `{ all: true }` → 204. 남의 것은 건드리지 않는다 |
| POST | `/api/v1/me/inbox/read-path` | `{ path: "/issue/FB-12" }` → `{ marked }`. 그 화면에 대한 안 읽은 알림을 읽음으로 한다(D-217) |

`/api/v1/me/notifications` 는 내 알림 **설정**(메일 주소·푸시)이라 따로 두고 `inbox` 를 썼다.

### 데이터 (`V6`)

`inbox_notifications(id, user_id → users CASCADE, title, headline, body, path, created_at, read_at)`. `body` 는 변경 줄을 줄바꿈으로 이은 것. 인덱스: `(user_id, created_at desc)`, 안 읽은 것만 `(user_id) where read_at is null`. 백업에는 넣지 않는다.

### 코드

백엔드 `com.flowbit.notification`: `InboxStore`, `InboxNotificationChannel`(다른 통로와 같은 `NotificationChannel` 이라 디스패처가 알아서 부른다), `InboxController`. 실시간 주제 `RealtimeHub.inbox(userId)`(`PagePresence.canRead` 가 본인 것만 허용). 프런트 `features/notifications/components/inbox-bell.tsx`(`InboxBell`), `inbox-seen.tsx`(`InboxSeen`, 화면을 열면 읽음, `AppShell` 에 있다), `app/(app)/layout.tsx` 가 읽지 않은 수를 서버에서 읽어 `AppShell` 을 거쳐 종에 준다.

## 2. 하루 요약

정한 시각에 구성원에게 **요약을 하루 한 번** 보낸다. **기본은 꺼져 있고**, 관리자가 구성원마다 **관리자 설정 > 구성원 > (구성원 선택) > "하루 요약 알림"** 에서 켠다(사용자 지정). 구성원 본인은 바꾸지 않는다(내 설정에는 없다).

### 설정 (관리자 설정 > 구성원)

| 항목 | 내용 |
|---|---|
| 하루 요약 보내기 | 꺼짐(기본) / 켜짐 |
| 보내는 시각 | `HH:mm`, **그 구성원의 시간대** 기준(구성원이 정한 시간대, 없으면 워크스페이스 기본 `Asia/Seoul`). 기본 값은 09:00 |
| 마지막으로 보낸 날 | 읽기 전용 |
| 지금 보내 보기 | 저장한 설정과 상관없이 지금 한 번 보내 본다. 그날의 정해진 발송은 쓰이지 않는다 |

고르는 즉시 저장되고(시각은 칸을 떠날 때), 바꿀 때마다 감사 로그 `MEMBER_DAILY_SUMMARY_CHANGED`(누가, 어느 구성원, 켬/끔, 시각)가 남는다.

API(관리자): `GET`·`PUT /api/v1/admin/members/{id}/daily-summary` (`{ enabled, time }` → `{ enabled, time, timezone, lastSentOn }`, 시각이 `HH:mm` 이 아니면 422 `INVALID`), `POST …/send` → `{ sent }`. 표 `member_daily_summaries(user_id, enabled, send_time, last_sent_on)`(`V6`, 행이 없으면 꺼짐). 백업에는 넣지 않는다.

### 내용

그 구성원 **자신의 일**만, 다음 줄 가운데 **있는 것만** 넣는다. 한 줄에 티켓은 3개까지 이름을 대고 나머지는 `외 N건`.

1. `기한 지남 N건: FB-3 제목, …` (내게 할당됐고 끝나지 않았고 기한이 오늘보다 앞)
2. `오늘 마감 N건: …`
3. `7일 안에 마감 N건: …` (내일부터 7일)
4. `어제 이후 새로 할당된 티켓 N건: …` (지난 24시간 안에 담당자가 된 것)
5. `내게 할당된 진행할 티켓 N건 (백로그 a · 준비됨 b · 진행 중 c)`
6. `읽지 않은 알림 N건` (수신함)

**줄이 하나도 없으면 보내지 않는다**(지금 보내 보기는 `sent: false`). 완료·취소·삭제된 티켓은 세지 않는다. 티켓은 그 구성원이 볼 수 있는 것만(프로젝트 권한을 따른다).

### 보내는 방법

- 통로는 **메일**(주소가 있고 "메일로 알림 받기"를 켠 사람, SMTP 가 켜져 있을 때)과 **웹 푸시**(브라우저를 등록한 사람, Firebase 가 켜져 있을 때). 제목 `[워크스페이스 이름] 오늘의 요약`, 머리말 `김지민 님, 오늘의 요약입니다`, 줄은 위의 것, 링크는 내 티켓(`/my-issues`). **API 알림(웹훅)으로는 보내지 않는다**: 웹훅은 티켓이 바뀐 것을 알리는 용도이고 요약용 이벤트가 아직 없다. 수신함에도 넣지 않는다.
- **하루에 한 번**: 백그라운드 작업이 1분마다 켜진 구성원을 보고, 구성원의 오늘 날짜에서 정한 시각이 지났고 아직 오늘 것을 보내지 않았으면 보낸다. **먼저 "오늘 보냈다"를 적고** 보낸다(보내기가 실패해도 그날 다시 보내지 않는다). 서버가 꺼져 있다 늦게 켜지면 **정한 시각에서 6시간까지** 늦게라도 보내고, 그 뒤면 내일을 기다린다.
- 설정: `flowbit.daily-summary.enabled`(기본 `true`), `initial-delay`(`30s`), `interval`(`1m`). 통합 테스트는 끈다.

## 범위 밖 (필요해지면 따로)

수신함 전체 페이지(`/inbox`)와 지우기·필터, 알림 종류별 켜고 끄기, 구성원 본인이 요약을 켜고 시각을 바꾸기, 요약의 항목 고르기·프로젝트/팀 요약(구독 프로젝트의 어제 대비 추가 티켓·미할당 티켓 등), 요약을 API 알림으로 보내기, 주말 건너뛰기.

## 인수 기준

`InboxAndDailySummaryIntegrationTest`:

- 티켓이 바뀌면 구독자의 수신함에 쌓이고(제목·머리말·변경 줄·경로), 한 사람이 한 변경은 자기에게 오지 않는다. 읽음 표시로 읽지 않은 수가 줄고 "모두 읽음"이 전부 읽음으로 한다
- 화면을 열면 그 화면의 알림만 읽음이 된다(대소문자 무시, 다른 화면의 것은 그대로, 다시 열면 0건)
- 하루 요약은 처음에 꺼져 있고(09:00), 관리자만 켜고 시각을 정한다
- 정한 시각이 아직 안 왔으면 보내지 않고, 지났으면 오늘 날짜가 "마지막으로 보낸 날"에 남는다
- 요약의 줄: 기한 지남·오늘 마감·새로 할당·상태별 수가 들어가고 끝난 티켓은 빠진다. 보낼 내용이 없는 구성원에게는 보내지 않는다
