# 온보딩 투어 (둘러보기)

마일스톤 밖의 기능이다. 사용자 지정(2026-10-13, D-120).

## 무엇인가

처음 로그인한 사람에게 앱 위에 겹쳐 보여 주는 8단계 안내다. 어디에 무엇이 있는지 짚어 주고, **연습용 예시 이슈**로 만들기·상태 바꾸기·삭제를 직접 해 보게 한다. 건너뛸 수 있고, 내 설정에서 다시 볼 수 있다.

## 동작

- **언제 뜨는가**: `users.tour_completed_at` 이 null 인 사람이 로그인 후 화면(`(app)`)을 열 때. 어느 화면으로 들어오든 뜬다. 이 기능이 생기기 전에 만들어진 계정도 null 이라 다음에 열 때 한 번 본다.
  - 이슈를 대화상자로 연 주소(`/issue/…`)에서는 뜨지 않고, 그 창을 닫으면 뜬다(대화상자가 바깥을 조작할 수 없게 만들기 때문이다).
- **끝내기**: 마지막 단계의 "시작하기", 어느 단계에서든 "건너뛰기", `Esc`. 셋 다 `POST /api/v1/me/tour/complete` 를 불러 시각을 남긴다. 건너뛴 것과 끝까지 본 것을 구분하지 않는다.
- **다시 보기**: 내 설정(`/settings`) 맨 아래 "사용 안내"의 "둘러보기 다시 보기". 처음부터 다시 보여 준다. **DB 의 시각은 바뀌지 않는다**(처음 본 때가 남는다).
- 요청이 실패하면(오프라인 등) 화면에는 아무 표시도 하지 않고, 다음에 열 때 투어가 다시 뜬다.
- 투어가 떠 있는 동안 뒤의 화면은 누를 수 없다.

## 단계

| # | 제목 | 가리키는 곳 | 내용 |
|---|---|---|---|
| 1 | 환영 | 없음(가운데) | 무엇을 하는지, 건너뛸 수 있다는 것 |
| 2 | 메뉴 | 사이드바의 내 이슈·전체 이슈·전체 프로젝트 | 각 메뉴에 무엇이 모이는지 |
| 3 | 내 프로젝트 | 사이드바의 프로젝트 목록 | 참여하는 프로젝트, 열면 개요와 이슈 |
| 4 | 이슈 만들기 | 없음 + **예시 목록** | 제목을 입력해 예시 이슈 추가. 실제로는 "새 이슈" 버튼이나 `C` |
| 5 | 상태 바꾸기 | 없음 + 예시 목록 | 상태 아이콘을 눌러 바꾸기(실제 목록과 같은 메뉴) |
| 6 | 이슈 삭제 | 없음 + 예시 목록 | 휴지통 버튼. 실제로는 이슈를 열어 "이슈 삭제", 복원 가능 |
| 7 | 내 설정 | 사용자 메뉴 | 프로필, 알림, 테마 |
| 8 | 마무리 | 없음 | 내 설정에서 다시 볼 수 있다는 것 |

- 좁은 화면에는 사이드바가 없다. 2·3단계는 위쪽 막대의 메뉴 버튼을, 7단계는 위쪽 막대의 사용자 메뉴를 가리킨다.
- 키보드: `→`/`←` 다음·이전(입력란에서는 글자 이동), `Enter` 다음(주 버튼에 초점), `Esc` 건너뛰기, `Tab` 은 카드 안에서만 돈다.

## 연습용 예시 이슈

투어 중에 실제 데이터를 만들고 지우게 할 수는 없어서(다른 구성원에게 보이고 알림이 간다) 투어 안에만 있는 예시 이슈 3건을 보여 준다.

- 4~6단계가 **같은 목록**을 쓴다. 4단계에서 추가한 이슈의 상태를 5단계에서 바꾸고 6단계에서 지울 수 있다. 단계와 상관없이 세 조작 모두 언제나 된다.
- 상태 메뉴와 우선순위 아이콘은 실제 이슈 목록의 컴포넌트(`ChipSelect`, `PriorityMark`)다.
- 그 단계의 조작을 한 번 하면 "해 봤습니다"가 뜬다. 하지 않아도 다음으로 넘어갈 수 있다.
- **브라우저 메모리에만 있다.** 서버로 아무것도 보내지 않고, 투어를 닫으면 사라지며 다시 보면 처음 3건으로 돌아온다. 목록 위에 "연습용 예시입니다. 여기서 한 작업은 저장되지 않습니다"라고 적는다.
- 키는 `EX-1`… 이다(워크스페이스 키와 무관한 고정값).

## API

| 메서드 | 경로 | 권한 | 내용 |
|---|---|---|---|
| POST | `/api/v1/me/tour/complete` | 로그인 | 본문 없음. `tour_completed_at` 이 null 일 때만 지금 시각을 넣는다. 응답은 `GET /api/v1/me` 와 같다 |

`GET /api/v1/me`(로그인·초기 설정 응답 포함)에 `tourCompletedAt`(시각 또는 null)이 추가됐다.

## 데이터

`users.tour_completed_at timestamptz null` (`V4__user_tour.sql`). [05-data-model.md](../05-data-model.md).

## 코드

- 백엔드: `MeController.completeTour`, `UserService.completeTour`, `UserRepository.completeTour`.
- 프런트: `features/tour/` — `steps.ts`(단계와 예시 데이터), `components/onboarding-tour.tsx`(`TourProvider`, `useTour`, 겹쳐 그리는 화면), `components/tour-practice.tsx`(예시 목록), `components/replay-tour-button.tsx`. `app-shell.tsx` 가 `TourProvider` 로 페이지를 감싼다. 문구는 `messages.tour`.
- 가리킬 곳은 `data-tour="이름"` 속성으로 표시한다(`nav`, `projects`, `user-menu`). 같은 이름을 여러 요소가 가질 수 있고(사이드바와 좁은 화면의 위쪽 막대), 그중 화면에 보이는 것을 쓴다. 보이는 것이 없으면 가운데에 띄운다.
- 투어는 `z-40` 이다. 메뉴(`z-50`)가 그 위에 떠야 예시 목록의 상태 메뉴가 보인다.

## 테스트

- 백엔드: `SettingsIntegrationTest` 의 "투어를 마치면 시각이 남고 다시 마쳐도 처음 시각 그대로다".
- E2E: `e2e/tour.spec.ts` 2개(처음 방문에 뜨고 예시로 만들기·상태·삭제를 한 뒤 끝내면 기억된다 + 서버의 이슈는 그대로다 / 건너뛰기·다시 보기·좁은 화면에서 창 밖으로 나가지 않는다).
- 다른 E2E 는 `logIn()`(`e2e/support.ts`)으로 로그인하면서 투어를 본 것으로 표시한다. 안 그러면 투어가 화면을 덮어 모든 테스트가 막힌다.

## 확인이 필요한 것 (에이전트가 정한 것)

- 건너뛰기도 "본 것"으로 기록한다(안 그러면 열 때마다 다시 뜬다). 건너뛴 것과 끝까지 본 것을 따로 남길 필요가 있는지.
- 기존 계정에게도 한 번 뜬다. 원하지 않으면 배포 전에 `update users set tour_completed_at = now()` 를 돌리면 된다.
- 단계의 수와 문구, 예시 이슈의 제목.
- 관리자에게 관리자 설정을 안내하는 단계는 없다.
