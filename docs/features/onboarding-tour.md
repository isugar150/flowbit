# 온보딩 투어 (둘러보기)

마일스톤 밖의 기능이다. 사용자 지정(2026-10-13, D-120).

## 무엇인가

처음 로그인한 사람에게 앱 위에 겹쳐 보여 주는 14단계 안내다. 어디에 무엇이 있는지 짚어 주고, **연습용 예시 이슈**로 만들기·상태 바꾸기·삭제를 직접 해 보게 한다. 건너뛸 수 있고, 내 설정에서 다시 볼 수 있다.

## 동작

- **언제 뜨는가**: `users.tour_completed_at` 이 null 인 사람이 로그인 후 화면(`(app)`)을 열 때. 어느 화면으로 들어오든 뜬다. 이 기능이 생기기 전에 만들어진 계정도 null 이라 다음에 열 때 한 번 본다.
  - 이슈를 대화상자로 연 주소(`/issue/…`)에서는 뜨지 않고, 그 창을 닫으면 뜬다(대화상자가 바깥을 조작할 수 없게 만들기 때문이다).
- **끝내기**: 마지막 단계의 "시작하기", 어느 단계에서든 "건너뛰기", `Esc`. 셋 다 `POST /api/v1/me/tour/complete` 를 불러 시각을 남긴다. 건너뛴 것과 끝까지 본 것을 구분하지 않는다.
- **다시 보기**: 내 설정(`/settings`) 맨 아래 "사용 안내"의 "둘러보기 다시 보기". 처음부터 다시 보여 준다. **DB 의 시각은 바뀌지 않는다**(처음 본 때가 남는다).
- 요청이 실패하면(오프라인 등) 화면에는 아무 표시도 하지 않고, 다음에 열 때 투어가 다시 뜬다.
- 투어가 떠 있는 동안 뒤의 화면은 누를 수 없다.
- **투어는 서버가 보내는 HTML 에 넣지 않고, 페이지의 스크립트가 돈 뒤에만 그린다** (`TourProvider` 의 `inBrowser`). 투어는 앱 전체를 덮기 때문에, 스크립트보다 먼저(또는 스크립트 없이) 보이면 버튼이 눌리지 않는 채로 앱을 막는다. 2026-10-13 에 사용자가 "건너뛰기와 둘러보기가 둘 다 안 눌린다"고 한 뒤 고쳤다.

## 단계

| # | 제목 | 보여 주는 것 | 내용 |
|---|---|---|---|
| 1 | 환영 | 가운데 카드 | 무엇을 하는지, 건너뛸 수 있다는 것 |
| 2 | 메뉴 | 사이드바의 내 이슈·전체 이슈·전체 프로젝트 | 각각 누르면 어떤 화면이 나오는지 이어서 보여 준다는 것 |
| 3 | 내 이슈 | 예시 화면: 내 이슈 목록(내가 담당한 예시 이슈만) | 메뉴에서 누르면 열리는 화면, 담당한 이슈가 상태별로 |
| 4 | 전체 이슈 | 예시 화면: 전체 이슈 목록 | 모든 프로젝트의 이슈가 모이는 곳 |
| 5 | 찾기와 보기 | 목록 위의 도구 줄을 강조 | 찾기, 필터, 보기 전환, 새 이슈 |
| 6 | 이슈 한 줄 | 목록의 첫 줄을 강조 | 상태 아이콘과 각 열의 뜻, 제목을 눌러 열기 |
| 7 | 제목과 본문 | 예시 화면: 이슈 상세의 왼쪽을 강조 | 그 자리에서 수정·자동 저장, `/`·`@`, 실제 화면에서 그 아래 이어지는 것 |
| 8 | 속성 | 이슈 상세의 오른쪽을 강조 | 상태·우선순위·담당자·기간·라벨·프로젝트와 목표 |
| 9 | 내 프로젝트 | 사이드바의 프로젝트 목록 | 프로젝트를 누르면 나오는 화면을 이어서 보여 준다는 것 |
| 10 | 프로젝트 개요 | 예시 화면: 개요의 이름·요약·설명을 강조 | 프로젝트를 누르면 처음 나오는 화면 |
| 11 | 목표 | 개요의 목표를 강조 | 단계, 진행률, 누르면 목표 상세 |
| 12 | 프로젝트 업데이트 | 개요의 업데이트를 강조 | 진행 상황 글과 진행 상태 |
| 13 | 내 설정 | 사용자 메뉴 | 프로필, 알림, 테마 |
| 14 | 마무리 | 가운데 카드 | 내 설정에서 다시 볼 수 있다는 것 |

- 6단계에서 이슈 제목을 누르면 7단계가 그 이슈로 열린다(누르지 않고 "다음"을 누르면 첫 예시 이슈).
- 예시 화면의 강조할 부분은 `data-tour` 속성으로 찾는다. 목록의 도구 줄(`issue-toolbar`)과 줄(`issue-row`)은 `issues-view.tsx` 에, 나머지는 `tour-demo.tsx` 의 감싸는 요소에 달려 있다. 화면이 늦게 도착하거나 아래쪽에 있을 수 있어서, 나타날 때까지 기다렸다가 한 번 보이는 곳으로 옮긴다.
- 예시 화면 단계의 카드는 아래쪽 구석에 놓인다. 강조하는 부분이 오른쪽에 있으면 왼쪽 구석으로 간다.
- 좁은 화면에는 사이드바가 없다. 2·3단계는 위쪽 막대의 메뉴 버튼을, 7단계는 위쪽 막대의 사용자 메뉴를 가리킨다.
- 키보드: `→`/`←` 다음·이전(입력란에서는 글자 이동), `Enter` 다음(주 버튼에 초점), `Esc` 건너뛰기, `Tab` 은 카드 안에서만 돈다.

## 예시 화면 (2026-10-13 에 다시 만듦)

처음에는 투어 카드 안의 작은 예시 목록이었다. 사용자가 "이슈를 다루는 것은 실제 화면으로 보여 주고, 이슈 상세와 프로젝트 개요도 설명해야 한다"고 해서 바꿨다.

- 4~6단계는 **앱의 실제 컴포넌트**를 예시 데이터로 그린다(`components/tour-demo.tsx`): `IssuesView`, `IssueBody` + `IssueProperties`, `ProjectOverviewEditor` + `MilestonesSection` + `ProjectUpdates`. 화면이 창을 채우고, 투어 카드는 오른쪽 아래에 떠 있다.
- 예시 데이터는 `features/tour/demo.ts` 의 `createDemo()` 가 만든다(프로젝트 하나, 사람 둘, 목표 하나, 라벨 둘, 이슈 넷, 업데이트 하나). 브라우저 메모리에만 있고 투어를 닫으면 사라진다.
- **서버로 아무것도 보내지 않는다.** 예시 화면이 떠 있는 동안 `apiFetch` 의 모든 호출을 `setDemoBackend`(`lib/api/client.ts`)에 건 함수가 대신 답한다(`demo.ts` 의 `answer`). 이슈 만들기·수정·삭제, 목표 추가·수정·삭제, 업데이트 남기기, 프로젝트 설명 수정은 예시 데이터에 반영되고, 그 밖의 요청(댓글, 첨부, 구독 등)은 성공으로 답하되 아무것도 바꾸지 않는다. 읽기 요청은 예시 이슈·목표 또는 빈 목록을 받는다.
- 예시 화면 안의 링크는 투어를 벗어나지 않는다. 이슈 제목을 누르면 5단계가 그 이슈로 열리고, 나머지 링크는 아무 일도 하지 않는다.
- 예시 화면은 `next/dynamic` 으로 그 단계에 왔을 때 받는다(앱 틀이 이슈 목록과 편집기를 늘 들고 다니지 않게).
- 알려진 한계: 예시 화면이 떠 있는 동안에는 뒤의 실제 화면이 보내는 요청도 예시 데이터가 답한다(뒤 화면은 가려져 있고, 투어를 닫으면 원래대로다). 목록의 보기·필터를 바꾸면 뒤 화면의 주소에 `?view=` 같은 값이 남는다. 예시 이슈 상세에는 댓글·활동·첨부·하위 이슈가 없다. 프로젝트 개요에는 오른쪽 속성 카드와 구성원이 없다.

## API

| 메서드 | 경로 | 권한 | 내용 |
|---|---|---|---|
| POST | `/api/v1/me/tour/complete` | 로그인 | 본문 없음. `tour_completed_at` 이 null 일 때만 지금 시각을 넣는다. 응답은 `GET /api/v1/me` 와 같다 |

`GET /api/v1/me`(로그인·초기 설정 응답 포함)에 `tourCompletedAt`(시각 또는 null)이 추가됐다.

## 데이터

`users.tour_completed_at timestamptz null` (`V4__user_tour.sql`). [05-data-model.md](../05-data-model.md).

## 코드

- 백엔드: `MeController.completeTour`, `UserService.completeTour`, `UserRepository.completeTour`.
- 프런트: `features/tour/` — `steps.ts`(단계), `components/onboarding-tour.tsx`(`TourProvider`, `useTour`, 겹쳐 그리는 화면), `demo.ts`(예시 데이터와 가짜 서버), `components/tour-demo.tsx`(예시 화면), `components/replay-tour-button.tsx`. `app-shell.tsx` 가 `TourProvider` 로 페이지를 감싼다. 문구는 `messages.tour`.
- 가리킬 곳은 `data-tour="이름"` 속성으로 표시한다(`nav`, `projects`, `user-menu`). 같은 이름을 여러 요소가 가질 수 있고(사이드바와 좁은 화면의 위쪽 막대), 그중 화면에 보이는 것을 쓴다. 보이는 것이 없으면 가운데에 띄운다.
- 투어는 `z-40` 이다. 메뉴(`z-50`)가 그 위에 떠야 예시 목록의 상태 메뉴가 보인다.

## 테스트

- 백엔드: `SettingsIntegrationTest` 의 "투어를 마치면 시각이 남고 다시 마쳐도 처음 시각 그대로다".
- E2E: `e2e/tour.spec.ts` 2개(처음 방문에 뜨고 예시 목록에서 상태를 바꾸고 이슈를 열고 개요를 본 뒤 끝내면 기억된다 + 서버의 이슈는 그대로다 / 건너뛰기·다시 보기·좁은 화면에서 창 밖으로 나가지 않는다).
- 다른 E2E 는 `logIn()`(`e2e/support.ts`)으로 로그인하면서 투어를 본 것으로 표시한다. 안 그러면 투어가 화면을 덮어 모든 테스트가 막힌다.

## 확인이 필요한 것 (에이전트가 정한 것)

- 건너뛰기도 "본 것"으로 기록한다(안 그러면 열 때마다 다시 뜬다). 건너뛴 것과 끝까지 본 것을 따로 남길 필요가 있는지.
- 기존 계정에게도 한 번 뜬다. 원하지 않으면 배포 전에 `update users set tour_completed_at = now()` 를 돌리면 된다.
- 단계의 수와 문구, 예시 이슈의 제목.
- 관리자에게 관리자 설정을 안내하는 단계는 없다.
