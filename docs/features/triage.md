# 요청함 (분류 대기열)

2026-10-28 사용자 결정: 화면과 알림의 이름을 **요청함**으로 바꾼다. 기존 URL(`/triage`), API, DB 필드와 내부 식별자는 유지한다. 대기·수락·거절·중복 처리 동작은 같다.

상태 (2026-10-28): **구현됨** (D-231, D-236). 요청하는 사람이 만든 티켓을 관리 역할이 처리 전에 분류하는 대기열이다 (`01-product.md` §2 "요청함").

- **프로젝트 설정 > 요청함**(관리 역할, 기본 꺼짐)를 켜면, 그 프로젝트에서 **관리 역할이 아닌 사람**(편집 역할)이 만드는 티켓은 `triage = true` 로 시작한다. **관리 역할이 만든 티켓은 기본으로 바로 일반 티켓**이고, 새 티켓 창의 **"요청함으로 보내기"**(아래쪽 "계속 만들기" 옆 체크, 요청함을 켠 프로젝트의 관리 역할에게만 보임, 창을 열 때마다 꺼진 채로 시작)를 켜고 만들면 그 티켓도 대기열에 들어간다(D-236. 처음에는 이 선택이 없어서 관리하는 프로젝트에서 직접 만든 티켓이 대기열에 안 보여 고장으로 보였다). API: 티켓 만들기 요청의 `triage: true`(관리 역할이 아닌 사람의 요청에서는 값과 관계없이 대기열, 요청함을 켜지 않은 프로젝트에서는 무시). 대기 중이거나 요청함에서 거절된 티켓은 **내 티켓(내 티켓·요청한 티켓 탭)과 전체 티켓에서 제외**한다. 목록·보드·타임라인·캘린더와 삭제된 티켓 보기에도 같은 규칙을 적용하고, 프로젝트로 좁힌 일반 목록도 같다. 수락하면 일반 목록에 나타난다. 일반 취소·중복 티켓을 일괄 제외하지는 않는다. 요청함의 대기 중·거절됨 목록, 권한이 있는 사용자의 상세 직접 열기와 검색은 기존 규칙을 유지하고 담당자·속성도 바꿀 수 있다. 같은 내 티켓 조회를 쓰는 캘린더·타임라인 공유와 일일 요약에서도 대기·거절 티켓은 제외한다.
- 왼쪽 사이드바의 **요청함**(`/triage`, 단축키 `G T`)는 **내가 관리 역할인 프로젝트**의 대기 티켓을 오래된 것부터 보인다. 줄마다:
  - **우선순위** 칩: 바로 바꾼다.
  - **수락**: 대기열에서 뺀다(`triage = false`). 상태·담당자는 티켓 창에서 평소처럼 정한다.
  - **중복**: 번호나 제목으로 원본 티켓을 찾아 고르면 "다음 티켓의 중복" 관계([issue-relations.md](issue-relations.md))를 맺고, 대기열에서 빼고 취소 상태로 닫는다.
  - **거절**: 이유(선택)를 쓰면 요청한 사람이 볼 수 있게 댓글로 남기고, 대기열에서 빼고 취소 상태로 닫는다.
- 분류(`triage` 를 바꾸는 것)는 **프로젝트 관리 역할만** 할 수 있다(403). 관리 역할이 아닌 사람은 자기가 만든 티켓을 스스로 수락할 수 없다. 켜지 않은 프로젝트의 티켓, 프로젝트가 없는 티켓은 대기열에 들어가지 않는다.
- 프로젝트 설정을 나중에 켜도 이미 있는 티켓은 대기열에 들어가지 않는다. 끄면 이미 대기 중인 티켓은 그대로 대기열에 남아 분류할 수 있다.
- API: `GET /api/v1/triage`(내가 관리하는 프로젝트의 대기 티켓), 티켓의 `triage`(응답, `PATCH /issues/{번호}` 의 `triage: false`), 프로젝트의 `triageEnabled`.
- 아직 없는 것: 사이드바의 대기 개수, 수락할 때 한 번에 정하는 담당자·상태, 외부(구성원이 아닌 사람)에서 들어오는 요청 — 지금은 구성원이 만든 티켓만 다룬다.

표 마이그레이션 `V10`. 코드: `IssueService.triageQueue`, `IssueController.TriageController`, 프런트 `app/(app)/triage`, `features/issues/components/triage-queue.tsx`, `features/projects/components/project-triage-field.tsx`. 테스트 `TriageIntegrationTest`.

## 내가 요청한 티켓 보기 (2026-11-03)

관리 역할이 아닌 사람이 만든 티켓은 대기 중인 동안 내 티켓·전체 티켓에서 빠지므로, 만든 본인도 그 티켓이 어떻게 됐는지 볼 곳이 없었다. 요청함 화면의 세 번째 보기 **내가 요청한**(`/triage?mine=true`)이 이를 채운다.

- 내가 만든 티켓 중 **분류를 기다리는 것**과 **거절된 것**을 두 구역으로 보인다. 최근에 만든 것부터 보이고, 줄에는 번호·제목·프로젝트·시각이 있다. 제목을 누르면 티켓을 열어 거절 이유 댓글과 상세를 읽는다. 수락되면 이 보기에서 빠지고 전체 티켓과 내 티켓에 나타난다.
- **읽기 전용**이다. 우선순위 변경·수락·중복·거절 버튼은 없고, 분류는 프로젝트 관리 역할만 한다(관리 역할이 자기 티켓을 요청함으로 보낸 경우도 이 보기에는 읽기 전용으로 나오며, 분류는 ‘대기 중’에서 한다). **남이 요청한 티켓은 보이지 않는다.**
- 지금 들어갈 수 있는 프로젝트의 티켓만 보인다(프로젝트에서 빠졌거나 프로젝트를 아카이브하면 보이지 않는다). 삭제한 티켓과 프로젝트 없는 티켓은 대기열에 들어가지 않으므로 나오지 않는다.
- 사이드바의 **요청함**을 열었을 때 ‘대기 중’이 비어 있고 내가 요청한 티켓이 있으면 ‘내가 요청한’이 먼저 열린다(관리 역할이 아닌 사람이 빈 화면을 보지 않게 한다). ‘대기 중’ 탭은 `/triage?rejected=false`로 직접 연다.
- API: `GET /api/v1/triage/mine`(분류를 기다리는 내 요청), `?rejected=true`(거절된 내 요청). 응답은 `GET /api/v1/triage`와 같은 티켓 목록이다. 기존 `GET /api/v1/triage`는 그대로 내가 관리하는 프로젝트의 대기열이다.
- 코드: `IssueQueries.myRequests`, `IssueService.myRequests`, `TriageController.mine`, 프런트 `app/(app)/triage/page.tsx`, `triage-queue.tsx`의 `MyRequests`. 테스트 `TriageIntegrationTest`.

## 거절된 요청 다시 보기 (2026-10-28)

요청함 화면에서 **대기 중 / 거절됨**을 전환한다. 거절됨 목록에서 제목을 눌러 이유 댓글과 상세를 읽는다. 일반 취소·중복과 구분하려고 `issues.triage_rejected`를 저장한다(V12). 기존 PATCH에 `triageRejected: true`를 함께 보내며, 대기 티켓을 관리 역할이 취소하며 분류할 때만 허용한다. 다시 대기열로 보내면 거절 표시는 초기화한다. `GET /api/v1/triage?rejected=true`로 조회한다. 이전 버전은 거절 여부를 저장하지 않아 기존 취소 티켓을 소급 분류하지 않는다.

## 분류 요청 알림 (2026-10-28)

새 티켓이 요청함에 들어오거나 기존 티켓이 대기열로 다시 들어오면 프로젝트의 활성 관리 역할 구성원 모두에게 즉시 알린다. 직접 보낸 관리 역할 본인은 제외한다. 구독 여부와 관계없이 알림 수신함에 저장하고, 메일·푸시·API 알림은 기존 설정을 따른다. 알림에는 새 요청의 번호·제목과 분류 요청 문구를 넣고 티켓 상세로 연결한다. 대기 중인 티켓의 단순 수정·수락·거절은 분류 요청 알림을 다시 보내지 않는다.
