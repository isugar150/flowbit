# 트리아지 (분류 대기열)

상태 (2026-10-28): **구현됨** (D-231). 요청하는 사람이 만든 티켓을 관리 역할이 처리 전에 분류하는 대기열이다 (`01-product.md` §2 "트리아지").

- **프로젝트 설정 > 트리아지**(관리 역할, 기본 꺼짐)를 켜면, 그 프로젝트에서 **관리 역할이 아닌 사람**(편집 역할)이 만드는 티켓은 `triage = true` 로 시작한다. 관리 역할이 만든 티켓은 바로 일반 티켓이다. 대기 중인 티켓도 **실제 티켓**이라 목록·보드·검색에 그대로 보이고(보드 카드와 티켓에 "트리아지" 표시), 담당자와 속성도 바꿀 수 있다. 대기열은 "분류했는가"를 알려 주는 표시다.
- 왼쪽 사이드바의 **트리아지**(`/triage`, 단축키 `G T`)는 **내가 관리 역할인 프로젝트**의 대기 티켓을 오래된 것부터 보인다. 줄마다:
  - **우선순위** 칩: 바로 바꾼다.
  - **수락**: 대기열에서 뺀다(`triage = false`). 상태·담당자는 티켓 창에서 평소처럼 정한다.
  - **중복**: 번호나 제목으로 원본 티켓을 찾아 고르면 "다음 티켓의 중복" 관계([issue-relations.md](issue-relations.md))를 맺고, 대기열에서 빼고 취소 상태로 닫는다.
  - **거절**: 이유(선택)를 쓰면 요청한 사람이 볼 수 있게 댓글로 남기고, 대기열에서 빼고 취소 상태로 닫는다.
- 분류(`triage` 를 바꾸는 것)는 **프로젝트 관리 역할만** 할 수 있다(403). 요청한 사람이 스스로 수락할 수 없다. 켜지 않은 프로젝트의 티켓, 프로젝트가 없는 티켓은 대기열에 들어가지 않는다.
- 프로젝트 설정을 나중에 켜도 이미 있는 티켓은 대기열에 들어가지 않는다. 끄면 이미 대기 중인 티켓은 그대로 대기열에 남아 분류할 수 있다.
- API: `GET /api/v1/triage`(내가 관리하는 프로젝트의 대기 티켓), 티켓의 `triage`(응답, `PATCH /issues/{번호}` 의 `triage: false`), 프로젝트의 `triageEnabled`.
- 아직 없는 것: 대기열 알림(새 요청이 들어왔다는 알림·사이드바 개수), 수락할 때 한 번에 정하는 담당자·상태, 외부(구성원이 아닌 사람)에서 들어오는 요청 — 지금은 구성원이 만든 티켓만 다룬다.
