# 사이클 (저절로 반복되는 스프린트)

상태 (2026-10-28): **구현됨** (D-232). `01-product.md` §4.5 의 사이클을, 팀이 없으므로(D-032) **프로젝트마다** 만들었다.

- **프로젝트 설정 > 사이클**(관리 역할)에서 켜고 **길이(1~4주)**와 **시작 요일**을 정한다. 켜는 순간 오늘이 든 사이클(가장 가까운 지난 시작 요일부터)과 다음 사이클이 만들어진다. 바꾼 길이·요일은 다음에 만들어지는 사이클부터 적용된다(이미 만든 사이클은 그대로).
- **저절로 돈다**: 서버가 한 시간마다(그리고 시작할 때, 사이클 화면을 읽을 때) 오늘이 든 사이클과 다음 사이클이 있게 새 사이클을 만든다. **사이클이 끝나면 끝나지 않은(완료·취소가 아닌, 삭제되지 않은) 티켓은 지금 사이클로 저절로 넘어간다.** 끝난 티켓은 끝난 사이클에 남는다. 시간대는 워크스페이스 기본 시간대, 날 수는 양 끝 날을 모두 센다.
- 사이클은 티켓의 **라벨**일 뿐이다(`issues.cycle_id`): 사이클에 있다고 티켓의 상태가 바뀌지 않는다. 티켓 창 속성의 **사이클**(켠 프로젝트의 기존 티켓)에서 이번·다음·지난 사이클을 고르거나 비운다. 티켓의 프로젝트를 바꾸면 사이클이 비워진다. 새 티켓은 사이클 없이 시작한다(백로그).
- **프로젝트 개요**의 "사이클 N" 카드: 기간, 남은 날, 완료/전체와 진행 막대, "이번 사이클 보드"(= `?project=…&cycle=current&view=board`). 목록의 도구 줄에는 사이클에 든 티켓이 있을 때 **이번 사이클** 버튼(`?cycle=current`: 티켓의 프로젝트에서 지금 도는 사이클에 든 것만)이 나온다. 저장한 뷰에도 들어간다.
- 완료/전체는 사이클에 든 티켓 중 취소를 뺀 수와 완료 수다.
- API: `GET /api/v1/projects/{id}/cycles`(`{settings, today, current, upcoming, past[]}`), `PUT …/cycles/settings`(`{enabled, weeks, startDay}`, 관리 역할), 티켓의 `cycle`(응답), `cycleId`(`PATCH`).
- 아직 없는 것: 번다운·속도 같은 사이클 보고서, 사이클마다 이름, 넘어간 티켓의 활동 기록, 사이클 알림.
