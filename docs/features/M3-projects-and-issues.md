# M3. 프로젝트와 이슈

상태 (2026-10-13): **1단계 구현됨. 2·3단계는 핵심이 구현됨**(이슈 만들기·목록·상세, 문서 편집기, 프리셋 목차). 4단계는 **댓글과 `@` 태그가 구현됨**(D-101), 변경 이력은 활동 기록(D-061)까지이고 본문의 이전 판 보기는 없다.

구현된 것과 아직 아닌 것은 아래 "지금 구현된 범위"가 기준이다. 그 아래 2~4단계의 글은 처음 쓴 명세이고, 구현하면서 달라진 점은 "지금 구현된 범위"에 적었다.

## 지금 구현된 범위

### 독립 이슈 (D-062): 아래 내용이 이 문서의 다른 설명보다 우선한다

이슈는 **프로젝트에 속하지 않고 워크스페이스에 있다.** 프로젝트는 이슈가 "연결"되는 대상일 뿐이다 (Linear 에서 이슈가 팀에 속하고 프로젝트는 연결인 것과 같다. Flowbit 에는 팀이 없어 워크스페이스 전체가 팀 하나다).

- **키와 번호**: `<워크스페이스 이슈 키>-<번호>`(기본 `FB-12`). 번호는 워크스페이스 전체의 일련번호다. 이슈 키는 관리자 설정의 워크스페이스에서 바꾼다(모든 이슈의 키가 바뀌고 번호는 그대로). 프로젝트 연결을 바꿔도 키는 그대로다.
- **권한**: 프로젝트에 연결된 이슈는 그 프로젝트를 따른다(구성원만 보고, 보기 역할은 고치지 못한다). **어디에도 연결되지 않은 이슈는 로그인한 누구나 보고 고친다.** 볼 수 없는 이슈는 404.
- **연결 바꾸기**: 이슈 상세 오른쪽 "프로젝트" 카드에서 프로젝트를 고르고, 그 아래에서 그 프로젝트의 목표를 고른다. 연결하려면 그 프로젝트에서 편집 권한이 있어야 한다. 프로젝트를 바꾸면 목표는 떨어진다. 담당자는 연결된 프로젝트의 구성원 중에서(독립 이슈는 모든 구성원 중에서) 고른다.
- **프로젝트에는 키가 없다** (D-082). 프로젝트는 내부 ID 로만 가리킨다: 주소 `/project/{id}`, API `/api/v1/projects/{id}`, 실시간 주제 `project:{id}`. 화면에는 이름만 보인다. 이름은 겹쳐도 된다.
- **주소**: `/issue/FB-12`(번호만 읽는다). 앱 안에서 이슈를 누르면 어느 화면에서든 그 위에 대화상자로 뜬다. **주소를 직접 열거나 새로 고쳐도 대화상자다** (D-074): 뒤에 둘 화면이 없으므로 전체 이슈 목록 위에 뜨고, 닫으면 `/issues` 로 간다. `/issues` 는 볼 수 있는 모든 이슈("전체 이슈"), `/project/{id}/issues` 는 그 프로젝트에 연결된 이슈, `/my-issues` 는 내 이슈.
- **API**: `GET/POST /api/v1/issues`(`?project={id}` 로 좁히기, 만들 때 `projectId`·`parentId`), `GET/PATCH /api/v1/issues/{번호}`(`projectId`, `parentId` 를 `null` 로 보내면 떼어 낸다), `…/activity`, `…/subscription`, `…/reactions`, `…/attachments`, `…/documents`. `GET/POST /api/v1/projects/{id}/issues` 는 그 프로젝트의 목록과 "그 프로젝트에 연결해 만들기"로 남아 있다. 한 건 조회 응답에는 `canEdit`, `subIssues`, `reactions`, `attachments`, `documents` 가 더 들어 있다.

| 기능 | 내용 | 상태 |
|---|---|---|
| 하위 이슈 (D-063) | 이슈 상세의 "하위 이슈": 완료 수/전체, 목록, "+" 로 제목만 넣어 추가(상위 이슈와 같은 프로젝트에 연결). 하위 이슈 화면 위에는 상위 이슈 링크. 하위 이슈도 보통 이슈다 | 구현, 화면 확인 안 함 |
| 보기 방식 (D-076, D-078) | 내 이슈, 전체 이슈, 프로젝트의 이슈에서 **목록 / 목표 차트 / 캘린더** 를 고른다(`?view=milestone\|calendar`). 세 화면 모두 같은 목록 컴포넌트(`issues-view.tsx`)라 검색과 필터가 세 보기에 똑같이 적용된다. **목표 차트**: 목표별 묶음의 타임라인(간트). 이슈마다 시작일(없으면 만든 날)부터 기한까지 막대, 목표마다 전체 기간 막대(완료 비율만큼 채움)와 목표일의 마름모, 오늘 세로선. 기한이 없는 진행 중 이슈는 오늘까지 흐린 막대. **캘린더**: 월 달력. 이슈는 기한 날짜에, 기간이 있으면 시작일부터 기한까지 매일 이어진 막대로 놓인다. 이슈를 다른 날로 끌면 날짜가 그만큼 옮겨지고(기간은 길이 유지), 빈 날짜를 누르거나 여러 날을 끌면 그 날짜(기간)로 새 이슈 창이 열린다 | 구현, 화면 확인 안 함 |
| 이슈의 날짜 (D-077) | 하루(`dueDate`)이거나 시작일과 종료일(`startDate` ~ `dueDate`). 날짜 칩에서 하루만 고르고 닫으면 하루, 두 번 고르면 기간. 시작일은 종료일이 있어야 하고 종료일보다 늦을 수 없다(422). 종료일을 지우면 시작일도 지워진다 | 구현, 화면 확인 안 함 |
| 이슈 삭제와 삭제된 이슈 보기 (D-079) | 이슈 옆 패널 아래 "이슈 삭제"(두 번 눌러 확인). 삭제는 표시만 한다(`deleted_at`): 목록에서 빠지지만 열 수 있고, 읽기 전용으로 내용과 활동 기록이 남으며 "복원"할 수 있다. 내 이슈·전체 이슈·프로젝트의 이슈의 "삭제된 이슈" 버튼(`?deleted=1`)으로 삭제된 것만 본다. `DELETE /api/v1/issues/{번호}`, `POST …/restore`, 목록의 `?deleted=true`. 프로젝트·목표의 진행률과 하위 이슈 수에서 삭제된 이슈는 빠진다 | 구현, 화면 확인 안 함 |
| 하위 이슈의 프로젝트·목표 (D-080) | 하위 이슈는 만들 때 상위 이슈의 프로젝트와 목표를 물려받는다(요청에 따로 주면 그 값). 상위 이슈의 프로젝트가 바뀌면 같은 프로젝트에 있던 하위 이슈가 따라가고(목표는 상위와 같았던 것만 새 목표로, 나머지는 없음), 상위 이슈의 목표만 바뀌면 같은 목표에 있던 하위 이슈가 따라간다. 일부러 다른 곳에 둔 하위 이슈는 그대로다. 아래 단계 전체에 적용되고 각 하위 이슈의 활동에 기록된다 | 구현, 화면 확인 안 함 |
| 이슈의 옆 패널 (D-073) | 카드 대신 제목만 있는 세 묶음: **속성**(상태, 우선순위, 담당자, 기한), **라벨**(알약 모양 + "+"), **프로젝트**(프로젝트, 그 아래 꺾인 선으로 이어진 목표). 값은 테두리 없는 줄이고 누르면 메뉴가 열린다. 이슈 상세의 하위 이슈 줄 오른쪽에는 라벨·기한·우선순위·담당자가 보인다. **새 이슈 창도 같은 패널(`IssuePropertyFields`)을 쓴다** | 구현, 화면 확인 안 함 |
| 목록의 하위 이슈 (D-072) | 내 이슈, 전체 이슈, 프로젝트의 이슈 목록에서 하위 이슈를 상위 이슈 바로 아래에 한 단계 들여 그린다(꺾인 선). 상위 이슈가 같은 묶음(상태)에 없으면 그 묶음에 상위 이슈를 흐린 줄로 한 번 보여 주고 그 아래에 둔다. 하위 이슈가 있는 이슈에는 `완료/전체` 가 붙는다(목록 응답의 `subIssueCount`, `subIssueDoneCount`) | 구현, 화면 확인 안 함 |
| 이모지 (D-064) | 이슈에 이모지 8개(👍 ❤️ 🎉 😄 👀 🚀 🙏 ✅) 중에서 달고, 다시 누르면 지운다. 볼 수 있는 누구나 | 구현, 화면 확인 안 함 |
| 파일 첨부 (D-065) | 이슈에 아무 파일이나(기본 5MB 까지, `FLOWBIT_MAX_UPLOAD_SIZE`). 올린 그대로 저장하고 **항상 내려받기로만** 돌려준다(`application/octet-stream`, `Content-Disposition: attachment`): 올린 HTML 이 이 사이트에서 실행되지 않게. 편집 권한이 있으면 올리고 지우고, 볼 수 있으면 내려받는다. `GET/DELETE /api/v1/attachments/{id}` | 구현, 화면 확인 안 함 |
| 이슈 문서 (D-066, D-083) | 제목과 편집기 본문을 가진 문서(`/doc/{id}`). 이슈 본문에서 `/문서` 를 고르면 **먼저 문서 이름을 묻고**(이름 없이 Enter, Esc, 다른 곳 클릭은 취소. 아무것도 만들지 않는다) **그 자리에 문서 블록**(아이콘 + 제목, 누르면 열림)이 들어간다. 별도의 문서 목록은 없다. 이슈의 문서 안에는 문서를 만들 수 없다(1단계). 자동 저장, 문서 화면에서 두 번 눌러 삭제. `GET/PATCH/DELETE /api/v1/documents/{id}` | 구현, 화면 확인 안 함 |
| 프로젝트 문서 (D-075, D-083) | 프로젝트 개요의 설명 편집기에서 `/문서` 로 만들면 그 자리에 문서 블록이 들어간다. 문서 안에서도 `/문서` 로 하위 문서를 만들 수 있고 **5단계까지**다(개요의 문서가 1단계, 넘으면 409 `DOCUMENT_TOO_DEEP`). 문서 화면의 경로 표시에 상위 문서가 차례로 보이고, 문서를 지우면 안의 문서도 함께 지워진다. 블록의 제목은 문서의 현재 제목을 따른다. 본문에서 블록만 지우면 문서는 남지만 화면에서 갈 길이 없다(주소로만 열린다). `GET/POST /api/v1/projects/{id}/documents`(개요에 만든 것만), `POST /api/v1/documents/{id}/documents`(하위 문서), 문서 응답의 `ancestors`·`children`·`canAddChild` | 구현, 화면 확인 안 함 |
| 댓글 (D-101) | 이슈 상세의 "활동" 맨 아래 입력 칸에서 쓴다. 본문과 같은 편집기(`/` 블록, 이미지 붙여넣기, `@` 태그)이고 `Ctrl/⌘+Enter` 또는 "댓글 남기기"로 보낸다. 댓글은 활동 기록 사이에 **시간순으로 섞여** 보인다. **편집 역할부터** 쓰고(보기 역할은 읽기만), **글쓴이만** 고치며("수정됨" 표시), **글쓴이와 워크스페이스 관리자**가 지운다(두 번 눌러 확인. 지운 댓글은 행은 남고 보이지 않는다). 삭제된 이슈에는 쓰거나 고칠 수 없다. 빈 댓글은 422(이미지만 있는 댓글은 된다). 댓글을 쓴 사람은 그 이슈를 구독하게 된다. 댓글은 구독자에게 알림으로 간다(`COMMENT_ADDED`, 본문 앞 300자). 고칠 때는 새로 태그된 사람에게만 간다. `POST /api/v1/issues/{번호}/comments`(`{ content }` → 201), `PATCH/DELETE /api/v1/comments/{id}`, 읽기는 `GET …/activity` 의 `comments`(`[{ id, content, author, createdAt, updatedAt, canEdit, canDelete }]`). 오류: 404 `COMMENT_NOT_FOUND`, 403, 422 `REQUIRED`·`INVALID_DOCUMENT` | 구현, 화면 확인 안 함 |
| `@` 태그 (D-101) | 편집기에서 `@` 를 치면 사람 목록이 뜨고(이름·아이디로 찾기, 화살표·Enter), 고르면 `@이름` 조각(`mention` 블록: 사람 id + 그때의 이름)이 들어간다. **댓글, 이슈 본문, 새 이슈 창**에서 된다(프로젝트 개요와 문서에서는 아직 안 된다). 목록에 나오는 사람 = 그 이슈의 담당자가 될 수 있는 사람(연결된 프로젝트의 구성원, 독립 이슈는 모든 활성 구성원). **태그된 사람은 그 이슈를 구독하게 되고**, 그래서 그 알림이 본인이 등록한 수단 전부(메일, 켜 둔 브라우저의 푸시, "받는 사람마다" API 알림)로 간다. 본문에서는 그 저장으로 **새로 태그된 사람**만 대상이다(`MENTIONED`). 이슈를 볼 수 없는 사람이나 자기 자신을 태그하면 글에는 남지만 구독·알림은 없다 | 구현, 화면 확인 안 함 |
| 전체 이슈 | 사이드바 "전체 이슈"(`/issues`). 프로젝트 필터가 더 있다. 여기서 만든 이슈는 프로젝트를 고르지 않으면 독립 이슈다 | 구현, 화면 확인 안 함 |
| 프로젝트 구성원 추가 버튼 | 프로젝트 개요의 "구성원" 카드에 관리 역할에게만 "+" 가 보이고, 누르면 사람과 역할을 골라 추가한다 | 구현, 화면 확인 안 함 |


사용자가 Linear 화면을 보여 주며 정한 것 (D-039): 새 이슈 창은 **왼쪽에 제목 + 본문, 오른쪽에 속성 열**(처음에는 본문 아래 칩 한 줄이었고 D-054 로 바뀜. 좁은 화면에서는 속성이 본문 아래로 내려간다). 프로젝트 설명은 설정이 아니라 **개요에서 바로** 쓴다. 본문은 `/` 로 블록을 넣는 **문서 편집기**다.

| 기능 | 상태 |
|---|---|
| 새 이슈 창 (`C`): 왼쪽에 제목과 본문(편집기), 오른쪽 "속성" 열에 상태·우선순위·담당자·마일스톤·프리셋·기한(이슈 상세와 같은 줄 모양), "계속 만들기", `Ctrl/⌘+Enter` | 구현. 오른쪽 열 배치(D-054)는 화면 확인 안 함 |
| 이슈 목록: 상태별 묶음(진행 중 → 준비됨 → 백로그 → 완료 → 취소), 줄에서 상태 바꾸기 | 구현, 화면 확인 |
| 이슈 상세: 제목과 본문을 그 자리에서 고침(자동 저장), 오른쪽 속성 카드에서 속성 변경 | 구현, 화면 확인(읽기), 속성 변경은 API 테스트만 |
| 문서 편집기: `/` 메뉴(제목 1~3, 글머리·번호 목록, 체크리스트, 코드 블록, 인용, 표, 이미지, 구분선), 마크다운 입력, 자동 저장 | 구현, 화면 확인 |
| 이슈 상세는 목록에서 열면 **목록 위의 대화상자**로 뜬다 (D-055). 주소는 `/issue/{키}`(D-062 전에는 `/project/{id}/issues/{n}`)이고, 닫으면 뒤로 간다. 주소를 직접 열거나 새로 고치면 예전처럼 한 페이지로 보인다 | 구현, 화면 확인 안 함 |
| 이슈 목록 필터 (D-056): 제목·번호 검색, 상태, 우선순위, 담당자(없음 포함), 프리셋(없음 포함), 마일스톤. 모두 주소에 둔다(`?status=&priority=&assignee=&preset=&milestone=&q=`) | 구현, 화면 확인 안 함 |
| **내 이슈** (`/my-issues`, D-059): 사이드바 맨 위 메뉴. "담당"(`/my-issues`)과 "만든 이슈"(`/my-issues/created`) 탭, 상태별 묶음. 들어갈 수 있는 모든 프로젝트의 이슈를 모은다. `GET /api/v1/me/issues?scope=assigned\|created`(최근에 바뀐 순, 최대 1000건) | 구현, 화면 확인 안 함 |
| **이슈 라벨** (D-060): 프리셋을 대신한다. 워크스페이스 공용, 이슈 하나에 여러 개. 기본 `버그`·`기능`·`중요`. 라벨 칩을 열어 찾고, 체크하고, 없는 이름은 그 자리에서 만든다. `GET/POST /api/v1/labels`, 이슈의 `labelIds`(쓰기)·`labels`(읽기). 목록의 줄에 라벨이 보이고 라벨로 거를 수 있다. 라벨 필터는 여러 개를 함께 고르며 그중 하나라도 붙은 이슈가 나온다(`?label=<id>,<id>,none`). 라벨을 고르는 곳(이슈 라벨, 라벨 필터, 프로젝트 라벨)은 모두 같은 콤보박스(`MultiCombobox`)다: 위에 찾기 칸, 열 때 골라져 있던 것이 맨 위, 그 아래 나머지, 화살표 키와 Enter 로 조작 (D-081) | 구현, 화면 확인 안 함 |
| **이슈 활동** (D-061): 이슈 상세의 본문 아래 "활동". 만들기와 제목·본문·상태·우선순위·담당자·기한·목표·라벨 변경이 차례로 남는다("○○ 님이 상태를 바꿨습니다: 백로그 → 진행 중 · 3분 전"). 제목·본문은 같은 사람이 10분 안에 이어서 고치면 한 줄로 합친다. `GET …/issues/{n}/activity` | 구현, 화면 확인 안 함 |
| **이슈 구독** (D-061): 만든 사람과 담당자(나중에 지정된 사람 포함)는 자동 구독. 이슈를 볼 수 있는 누구나(보기 역할 포함) "구독"/"구독 취소" 버튼으로 바꾼다. 구독자 아바타가 활동 제목 옆에 보인다. `PUT/DELETE …/issues/{n}/subscription`. 구독자는 알림의 받는 사람이 된다([02-architecture.md](../02-architecture.md) "알림") | 구현, 화면 확인 안 함 |
| 편집기의 블록 옮기기: 마우스를 올린 블록의 왼쪽에 손잡이가 뜨고, 끌면 문단·목록·표·이미지를 통째로 다른 위치로 옮긴다 (D-058). 터치 화면에는 없다 | 구현, 화면 확인 안 함 |
| 편집기의 이미지: `/` 메뉴에서 고르기, 붙여넣기, 끌어다 놓기. `POST /api/v1/images` 로 올리고 문서에는 주소만 둔다 (D-052) | 구현, 화면 확인(붙여넣기) |
| 편집기의 표: 3×3(머리글 행)으로 시작. 표 도구 모음으로 행·열 추가/삭제, 셀 합치기·나누기, 가로 정렬, 세로 맞춤, 머리글 행·열, 표 삭제. 열 너비 끌어서 조절 (D-052) | 구현, 화면 확인(넣기, 가운데 정렬, 합치기, 저장 후 유지, 다크 모드) |
| 프리셋: 고르면 본문에 목차가 깔린다(직접 쓴 내용이 있으면 덮지 않는다) | 구현, 화면 확인 |
| 프로젝트 개요: 한 줄 요약과 설명 문서를 그 자리에서 씀 | 구현, 화면 확인 |
| 프로젝트 속성 (개요 오른쪽 "속성" 카드): 상태, 우선순위, 리드, 기간(시작일 → 종료일), 라벨 | 구현, 화면 확인 안 함 |
| 마일스톤: 프로젝트 개요에서 추가·이름 변경·목표일·삭제, 단계별 진행률. 이슈의 "마일스톤" 속성(새 이슈 창, 이슈 상세), 이슈 목록의 마일스톤 거르기 | 구현, 화면 확인 안 함 (아래 "마일스톤") |
| 실시간 반영: 프로젝트(개요·속성·설정·구성원·이슈 목록)와 이슈 상세의 변경이 같은 화면을 연 다른 사람에게 바로 보인다. 오른쪽 위에 같은 화면을 보는 사람의 아바타(이름 툴팁) | 구현, 화면 확인 안 함 ([../02-architecture.md](../02-architecture.md) "실시간 동기화") |

아직 없는 것:

- **라벨** (Linear 의 Labels 칩). 라벨 관리가 필요해 뒤로 미뤘다.
- 하위 이슈, 반복 이슈, 링크 첨부, 파일·이미지 첨부 (Linear 창의 "…" 메뉴와 클립 버튼)
- 라벨 이름·색 고치기와 삭제(관리 화면), 프로젝트별 라벨, 필터에서 여러 값 동시 선택(라벨만 됨, D-081), 필터 저장(뷰)
- 프리셋과 프리셋 목차(새 이슈 본문에 깔리던 제목들): D-060 으로 화면에서 없앴다. 아래 "프리셋" 절은 처음 쓴 명세로 남겨 둔다
- 내 이슈의 "구독", "활동" 탭(Linear 에 있는 것). 구독과 활동 기록은 생겼으니(D-061) 다음에 만들 수 있다
- 댓글에 댓글 달기(스레드), 댓글의 이모지, 댓글 해결 표시, 프로젝트 개요·문서 안의 `@` 태그, `#` 로 이슈 연결
- 첨부 파일 미리 보기, 본문 안에 파일 넣기, 문서를 이슈 없이 따로 만들기, 문서의 변경 이력, 이모지 직접 고르기(정해진 8개만)
- 편집기의 접는 구역·다이어그램·콜아웃 블록, 이미지 크기 조절·정렬·설명 글, 문서에서 빠진 이미지 파일 정리
- 프리셋 목차를 프로젝트 관리 역할이 고치는 기능 (지금은 코드에 고정: `frontend/src/features/issues/meta.tsx`)
- 완료 조건 진행률(`3/5`) 표시, 필터, 이슈 삭제
- 본문 동시 편집 충돌 알림 (지금은 나중에 저장한 쪽이 이긴다. 저장 안 된 입력이 있는 동안에는 남의 변경으로 덮지 않는다)
- 낙관적 업데이트: 지금은 변경 후 서버에서 다시 그린다
- 본문 변경의 이전 판 보기

구현하면서 명세와 달라진 점:

- 상태는 프로젝트별 표가 아니라 **고정된 5개 값**이다(`BACKLOG`, `READY`, `IN_PROGRESS`, `DONE`, `CANCELED`). 프로젝트마다 상태를 바꾸는 기능을 만들 때 표로 옮긴다.
- 프리셋은 표가 아니라 이슈의 값(`BUG`, `ENHANCEMENT`, `FEATURE`)이고, 목차는 프런트엔드가 가진다.
- 이슈 본문은 `issues.content`(jsonb), 거기서 뽑은 글자는 `issues.description`(text)에 둔다. 프로젝트는 `description` 이 한 줄 요약, `content` 가 설명 문서다.
- 프로젝트 요약과 설명은 **편집 역할부터** 고칠 수 있다. 이름 변경만 관리 역할이 필요하다.

이슈 API (모두 프로젝트 구성원만, 쓰기는 편집 역할부터):

| 메서드와 경로 | 설명 |
|---|---|
| `GET /api/v1/projects/{id}/issues` | 목록. 최근에 만든 것부터. `content` 는 빠진다 |
| `POST /api/v1/projects/{id}/issues` | `{ title, content?, preset?, status?, priority?, assigneeId?, dueDate? }` → 201. 제목만 필수 |
| `GET /api/v1/projects/{id}/issues/{number}` | 한 건. `content` 포함 |
| `PATCH /api/v1/projects/{id}/issues/{number}` | 보낸 항목만 바뀐다. `assigneeId`, `dueDate`, `preset`, `content` 는 `null` 로 지운다 |
| `PATCH /api/v1/projects/{id}` | `{ name?, description?, content?, status?, priority?, leadId?, startDate?, targetDate?, labels? }`. `content` 는 개요 문서. `leadId`, `startDate`, `targetDate` 는 `null` 로 지운다 |

### 프로젝트 업데이트와 건강도

사용자가 Linear 의 Health 열("On track · 1h")을 지정했다 (D-048). 건강도는 따로 고르는 속성이 아니라 **가장 최근 프로젝트 업데이트의 값**이다.

- 업데이트: 건강도(순조로움 `ON_TRACK` / 위험 `AT_RISK` / 지연 `OFF_TRACK`) + 글(선택, 5000자 이하, 평문). 편집 역할부터 남긴다. **쓴 사람(편집 역할 이상일 때)과 관리 역할은 지울 수 있다**(D-085; 지우면 건강도는 그 앞의 업데이트 값으로 돌아간다). 고치는 기능은 없다. 글이 없고 건강도도 직전 업데이트와 같으면 새로 알릴 것이 없으므로 화면이 "업데이트 남기기"를 막는다(API 는 받는다).
- 화면: 프로젝트 개요의 마일스톤 아래 "프로젝트 업데이트"(건강도 칩 + 글 + "업데이트 남기기", `Ctrl/⌘+Enter`; 최근 것부터 50개). 속성 카드의 "건강도" 줄, 전체 프로젝트 표의 "건강도" 열(`순조로움 · 1시간 전`). 업데이트가 없으면 "업데이트 없음".
- 남기면 실시간으로 `project:{id}` 를 알린다.

| 메서드와 경로 | 설명 |
|---|---|
| `GET /api/v1/projects/{id}/updates` | 최근 것부터 50개: `[{ id, health, body, author, createdAt }]` |
| `POST /api/v1/projects/{id}/updates` | `{ health, body? }` → 201. 편집 역할부터 |
| `DELETE /api/v1/projects/{id}/updates/{updateId}` | 204. 쓴 사람(편집 역할 이상) 또는 관리 역할. 그 밖에는 403, 없는 업데이트는 404 `PROJECT_UPDATE_NOT_FOUND` |

### 마일스톤 (화면 이름은 "목표")

**화면과 오류 문구에서는 이 기능을 "목표"라고 부른다** (D-057). 코드·API·테이블 이름은 `milestone` 그대로이고, 이 문서의 "마일스톤"도 같은 것을 가리킨다. 개발 일정의 마일스톤(M1, M2 …)과는 다른 말이다.

사용자가 Linear 의 프로젝트 마일스톤처럼 만들어 달라고 지정했다 (D-045). 프로젝트 안의 **단계**이고, 이슈를 단계에 묶어 단계별 진행률을 본다. 할 일을 따로 적는 목록이 아니라 기존 이슈를 분류하는 것이다.

- 마일스톤: 이름(1~80자), 목표일(선택). 프로젝트마다 여러 개. 순서는 목표일이 빠른 것부터, 목표일이 없으면 만든 순서로 뒤에.
- 이슈는 마일스톤 **하나**에 속하거나 아무 데도 속하지 않는다. 다른 프로젝트의 마일스톤은 붙일 수 없다(422 `NOT_IN_PROJECT`, 필드 `milestoneId`).
- 진행률 = 완료(`DONE`) 이슈 수 ÷ 취소(`CANCELED`)를 뺀 이슈 수. 이슈가 없으면 0%. 추정치(포인트)가 없어 개수로 센다.
- 마일스톤을 지우면 이슈는 남고 마일스톤만 빠진다.
- 권한: 프로젝트 구성원은 모두 보고, **편집 역할부터** 만들고 고치고 지운다.
- 화면: 프로젝트 개요의 설명 아래 "마일스톤" 목록(진행률 막대와 %, `이슈 완료수/전체`, 목표일 칩, `…` 메뉴의 삭제). `이슈 n/m` 을 누르면 그 마일스톤으로 걸러진 이슈 목록(`/project/{id}/issues?milestone={id}`). 이슈 목록 위의 마일스톤 칩으로 거르고, 거른 상태에서 새 이슈를 만들면(버튼이든 `C` 든) 그 마일스톤이 미리 골라져 있다. 거르는 값은 **주소에 둔다**(`?milestone=<id>`, 마일스톤 없음은 `?milestone=none`): 개요의 링크, 뒤로 가기, 주소 공유가 같은 결과를 낸다. 거른 상태에서는 "필터 초기화" 버튼이 보이고, 누르면 모든 이슈로 돌아간다. 목록의 줄에도 마일스톤 이름이 보인다(넓은 화면).
- 바뀌면 실시간으로 `project:{id}` 를 알린다.

| 메서드와 경로 | 설명 |
|---|---|
| `GET /api/v1/projects/{id}/milestones` | `[{ id, name, targetDate, issueCount, doneCount, createdAt }]`. `issueCount` 는 취소를 뺀 수 |
| `POST /api/v1/projects/{id}/milestones` | `{ name, targetDate? }` → 201. 편집 역할부터 |
| `PATCH /api/v1/projects/{id}/milestones/{id}` | `{ name?, targetDate? }`. `targetDate: null` 로 지운다 |
| `DELETE /api/v1/projects/{id}/milestones/{id}` | → 204. 이슈는 마일스톤 없음이 된다 |

이슈 API 에는 `milestoneId`(만들기, `PATCH`, `null` 로 지움)와 응답의 `milestone: { id, name } | null` 이 더해졌다. 오류: 404 `MILESTONE_NOT_FOUND`, 422 `VALIDATION_FAILED`(이름 비었음·너무 김).

### 프로젝트 속성

사용자가 Linear 의 프로젝트 화면을 보여 주며 지정했다 (D-042). 개요 오른쪽 "속성" 카드에서 그 자리에서 바꾸고, **편집 역할부터** 바꿀 수 있다.

| 속성 | 값 | 기본 |
|---|---|---|
| 상태 `status` | 백로그 `BACKLOG` / 계획됨 `PLANNED` / 진행 중 `IN_PROGRESS` / 완료 `COMPLETED` / 취소 `CANCELED` (고정 5개) | 백로그 |
| 우선순위 `priority` | 이슈와 같은 값: 없음 / 긴급 / 높음 / 보통 / 낮음 | 없음 |
| 리드 `lead` | 프로젝트의 활성 구성원 한 명 또는 없음. 아니면 422 `NOT_A_MEMBER`(필드 `leadId`) | 없음 |
| 기간 `startDate` → `targetDate` | 날짜 두 개, 각각 비울 수 있다. 시작일이 종료일보다 늦으면 422 `BEFORE_START`(필드 `targetDate`) | 없음 |
| 라벨 `labels` | 자유 입력 태그. 1~30자, 최대 10개, 대소문자 무시하고 중복 제거. 입력할 때 다른 프로젝트에 쓰인 라벨을 제안한다 | 없음 |

- 라벨은 아직 별도 표(색, 관리 화면)가 없다. 프로젝트의 `labels` 배열에 이름만 둔다. 라벨 관리가 필요해지면 표로 옮긴다.
- 프로젝트 목록 API(`GET /api/v1/projects`)에도 이 속성들이 함께 온다. 목록 화면에 보여 주는 것은 아직 없다.

- 담당자는 그 프로젝트의 활성 구성원이어야 한다 (422 `NOT_A_MEMBER`).
- 문서(`content`)는 서버가 검증한다: 편집기가 제공하는 블록과 서식만 허용하고, 링크는 `http(s)`, `mailto`, 앱 안의 경로만 받는다. 이미지 주소는 이 서버가 저장한 파일(`/api/v1/files/<key>.webp`)만, 표 칸의 정렬은 정해진 값(`left/center/right`, `top/middle/bottom`)만, 칸 합치기 수는 1~100만 받는다. 어기면 422 `INVALID_DOCUMENT`. HTML 은 저장하지도 내보내지도 않는다.
- 이슈 번호는 프로젝트별로 1부터 차례로 붙고, 동시에 만들어도 겹치지 않는다.

백엔드 테스트: `IssuesIntegrationTest`(댓글 3개 포함), `RichTextIntegrationTest`(7개), `NotificationsIntegrationTest`(태그 알림 1개).

사용자가 정한 것 (D-032):

- 프로젝트를 만들면 권한이 있는 사용자가 들어와 이슈·고도화 같은 글을 등록하고 정리한다.
- Jira처럼 **프리셋**(정해진 항목)을 먼저 채우고, Outline처럼 **문서**로 세부 내용을 적는다. 개발자는 이 글을 보고 개발한다.
- **팀 개념은 없앤다.** 프로젝트가 이슈의 집이자 권한 단위다.
- 프리셋은 기본 3종을 제공하고 관리자는 목차 문구만 고친다.
- 구성원 추가를 이번 범위에 넣는다.

그 밖의 세부(권한 단계, 상태 목록, 편집기, 화면 구성)는 에이전트의 제안이다. 각 단계를 구현하기 전에 "확인이 필요한 것"을 사용자에게 확인한다.

## 한눈에 보기

```
워크스페이스
 ├─ 구성원 (관리자 / 구성원)
 └─ 프로젝트 FLOW  ── 프로젝트 구성원 (관리 / 편집 / 보기)
      ├─ 상태 목록 (백로그 → 준비됨 → 진행 중 → 완료, 취소)
      ├─ 프리셋 (버그, 고도화, 기능 요청)
      └─ 이슈 FLOW-12
           ├─ 속성: 상태, 담당자, 우선순위, 기한, 라벨      ← 프리셋과 무관하게 모두 같다
           ├─ 문서: 프리셋이 깔아 준 목차 + 자유로운 본문    ← Outline 같은 부분
           └─ 댓글, 변경 이력
```

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 구성원 추가·관리, 프로젝트 만들기, 프로젝트 권한 | **구현됨** |
| 2 | 프리셋 3종, 이슈 쓰기(속성 + 문서 + 자동 목차) | 명세만 |
| 3 | 이슈 목록(상태별 묶음, 필터), 상태 변경, 실시간 반영 | 명세만 |
| 4 | 댓글, 변경 이력 | 댓글·`@` 태그·활동 기록 구현 ("지금 구현된 범위") |

## 용어

| 용어 | 코드 | 뜻 |
|---|---|---|
| 구성원 | `user` | 워크스페이스에 로그인하는 사람. 워크스페이스 역할은 관리자(`ADMIN`) / 구성원(`MEMBER`) |
| 프로젝트 | `project` | 이슈의 집이자 권한 단위. 키(`FLOW`)를 가진다 |
| 프로젝트 구성원 | `projectMember` | 프로젝트에 들어올 수 있는 사람과 그 역할 |
| 이슈 | `issue` | 프로젝트에 등록하는 글 하나. 버그든 고도화든 기능 요청이든 모두 이슈다. 키는 `FLOW-12` |
| 프리셋 | `preset` | 이슈의 종류. 새 이슈의 문서에 깔리는 목차를 정한다 |

## 권한

워크스페이스 역할과 프로젝트 역할, 두 겹이다.

| 할 수 있는 일 | 프로젝트 밖 구성원 | 보기 `VIEWER` | 편집 `EDITOR` | 관리 `MANAGER` | 워크스페이스 관리자 |
|---|---|---|---|---|---|
| 전체 프로젝트 목록에서 보기(이름, 속성, 건강도, 진행률) | ○ (D-047) | ○ | ○ | ○ | ○ |
| 프로젝트에 들어가기 | ✕ ("권한 없음" 화면, 관리자 안내) | ○ | ○ | ○ | ○ (모든 프로젝트) |
| 이슈 읽기, 댓글 읽기 | ✕ | ○ | ○ | ○ | ○ |
| 이슈 쓰기·고치기, 댓글 쓰기 | ✕ | ✕ | ○ | ○ | ○ |
| 프로젝트 이름·설명, 프리셋 목차 고치기 | ✕ | ✕ | ✕ | ○ | ○ |
| 프로젝트 구성원 추가·역할 변경·내보내기 | ✕ | ✕ | ✕ | ○ | ○ |
| 프로젝트 만들기 | ○ (만든 사람이 관리 역할) | | | | ○ |
| 워크스페이스 구성원 추가·역할 변경·비활성화 | ✕ | | | | ○ |

- **모든 프로젝트가 전체 프로젝트 목록에 보인다** (D-047, 사용자 지정). 들어갈 수 없는 프로젝트는 자물쇠가 붙고, 누르면 `/no-access/{id}` 에서 "권한이 없습니다"와 그 프로젝트의 관리 역할(이름·아이디·사진)을 보여 주며 그들에게 추가를 요청하라고 안내한다. 사이드바 "내 프로젝트"에는 들어갈 수 있는 것만 있다.
- 목록 밖의 데이터(개요, 이슈, 구성원, 마일스톤, 업데이트)는 지금처럼 구성원이 아니면 404 로 답한다. 화면은 `GET /api/v1/projects/{id}/access`(로그인한 누구나: `{ id, name, myRole, managers }`)로 "없는 프로젝트"와 "권한 없음"을 가른다.
- 워크스페이스 관리자는 프로젝트 구성원이 아니어도 모든 프로젝트에서 관리 역할로 동작한다.
- 프로젝트에는 관리 역할이 항상 한 명 이상 있어야 한다. 마지막 관리 역할을 내보내거나 낮출 수 없다 (409 `LAST_MANAGER`).
- 관리자는 자기 자신의 워크스페이스 역할을 바꾸거나 자신을 비활성화할 수 없다 (409 `CANNOT_CHANGE_SELF`). 그래서 관리자가 한 명도 없는 상태가 생기지 않는다.
- 판단은 항상 백엔드가 한다. 화면에서 버튼을 숨기는 것은 편의다.

## 1단계: 구성원과 프로젝트 (구현됨)

### 구성원 관리 (워크스페이스 관리자)

- 관리자가 구성원을 **직접 만든다**: 아이디, 임시 비밀번호, 이름(선택), 역할. 이메일 초대는 없다(이메일 발송 기능이 없다). 관리자가 아이디와 비밀번호를 당사자에게 전달한다.
- 아이디와 비밀번호 규칙은 초기 설정과 같다 ([M1-auth-and-setup.md](M1-auth-and-setup.md)).
- 역할 변경, 비활성화/다시 활성화, 비밀번호 재설정.
- 비활성화하거나 비밀번호를 재설정하면 그 사람의 로그인 세션이 모두 끝난다.
- 구성원을 삭제하는 기능은 없다. 비활성화만 한다(쓴 글과 이력이 남아야 한다).
- 감사 로그: `MEMBER_CREATED`, `MEMBER_ROLE_CHANGED`, `MEMBER_DISABLED`, `MEMBER_ENABLED`, `MEMBER_PASSWORD_RESET`.

아직 없는 것: 구성원이 **자기 비밀번호를 바꾸는 기능**. 임시 비밀번호를 받은 사람이 바꿀 방법이 지금은 관리자에게 재설정을 부탁하는 것뿐이다. 다음에 가장 먼저 채울 빈 곳이다.

### 프로젝트

- 만들 때 받는 것: 이름(1~80자), 키, 설명(선택, 500자 이하).
- 키: 영문 대문자로 시작하는 영문 대문자·숫자 2~10자(`FLOW`, `APP2`). 워크스페이스 안에서 유일하고, **만든 뒤에는 바꿀 수 없다**(이슈 번호와 링크가 여기에 묶인다). 화면은 이름에서 키를 제안한다.
- 만든 사람이 관리 역할의 첫 구성원이 된다.
- 프로젝트 삭제·보관은 아직 없다(`archived_at` 컬럼만 준비).

### API

공통 규칙은 [../06-api-conventions.md](../06-api-conventions.md).

| 메서드와 경로 | 설명 | 권한 |
|---|---|---|
| `GET /api/v1/users` | 활성 구성원 목록(id, 아이디, 이름, 사진). 사람을 고르는 화면용 | 로그인 |
| `GET /api/v1/admin/members` | 모든 구성원(비활성 포함)과 역할·상태·마지막 로그인 | 관리자 |
| `POST /api/v1/admin/members` | `{ loginId, password, displayName?, role }` → 201 | 관리자 |
| `PATCH /api/v1/admin/members/{id}` | `{ role?, status? }` | 관리자 |
| `PUT /api/v1/admin/members/{id}/password` | `{ password }` → 204 | 관리자 |
| `GET /api/v1/projects` | 모든 프로젝트. 들어갈 수 없는 것은 `myRole: null`. 속성과 함께 `health`, `healthUpdatedAt`(최근 업데이트), `issueCount`(취소 제외), `doneCount`, `currentMilestone`(끝나지 않은 첫 마일스톤 이름)이 온다 | 로그인 |
| `POST /api/v1/projects` | `{ name, description? }` → 201 | 로그인 |
| `GET /api/v1/projects/{id}` | 프로젝트와 내 역할 | 프로젝트 구성원 |
| `PATCH /api/v1/projects/{id}` | `{ name?, description? }` (속성은 위 "프로젝트 속성") | 관리 |
| `PUT /api/v1/projects/{id}/icon` | multipart `file` 하나. 256px 정사각 WebP 로 바꿔 저장(M2a 의 변환·저장). 응답은 프로젝트(`iconUrl`) | 관리 |
| `DELETE /api/v1/projects/{id}/icon` | 기본 아이콘으로 되돌림 | 관리 |
| `GET /api/v1/projects/{id}/members` | 프로젝트 구성원과 역할 | 프로젝트 구성원 |
| `PUT /api/v1/projects/{id}/members/{userId}` | `{ role }`. 없으면 추가, 있으면 역할 변경 | 관리 |
| `DELETE /api/v1/projects/{id}/members/{userId}` | 내보내기 → 204 | 관리 |

오류 코드: 404 `PROJECT_NOT_FOUND`, 404 `MEMBER_NOT_FOUND`, 403 `FORBIDDEN`, 409 `LOGIN_ID_TAKEN`, 409 `LAST_MANAGER`, 409 `CANNOT_CHANGE_SELF`, 422 `VALIDATION_FAILED`.

### 화면

| 경로 | 내용 |
|---|---|
| 사이드바 "프로젝트" | 내가 들어갈 수 있는 프로젝트 목록, `+` 로 새 프로젝트 |
| `/` (전체 프로젝트) | Linear 의 프로젝트 목록처럼 표로 보인다 (D-046): 이름 + 현재 마일스톤(◆), 건강도(D-048), 우선순위, 리드, 목표일, 이슈 수(취소 제외), 상태 아이콘 + 진행률(완료 ÷ 취소 제외 이슈). 줄 전체가 링크. 좁은 화면에서는 이름과 상태만. 머리 오른쪽에 "새 프로젝트" |
| `/project/{id}` | 프로젝트 머리(이름, 설명). 이슈 목록 자리에는 아직 빈 상태 안내 |
| `/project/{id}/settings` | 프로젝트 아이콘 올리기·지우기, 이름 고치기, 구성원 추가·역할 변경·내보내기 (관리 역할만). 아이콘은 사이드바, 전체 프로젝트 표, 경로 표시, 개요 머리에 보인다. 없으면 기본 상자 아이콘 |
| `/admin/members` | 워크스페이스 구성원 목록, 추가, 역할 변경, 비활성화, 비밀번호 재설정 (관리자만) |

### 인수 기준 (1단계)

백엔드 통합 테스트(`MembersIntegrationTest`, `ProjectsIntegrationTest`)가 있다.

- [x] 관리자가 만든 구성원이 그 아이디와 비밀번호로 로그인할 수 있다
- [x] 같은 아이디로는 만들 수 없다. 아이디·비밀번호 규칙을 어기면 필드별 오류
- [x] 구성원은 구성원 관리 API 를 쓸 수 없다 (403)
- [x] 비활성화하면 로그인도, 기존 세션도 쓸 수 없다. 다시 활성화하면 로그인된다
- [x] 비밀번호를 재설정하면 새 비밀번호로만 로그인되고 기존 세션은 끝난다
- [x] 관리자는 자기 역할을 바꾸거나 자신을 비활성화할 수 없다
- [x] 프로젝트를 만들면 만든 사람이 관리 역할이 된다. 키가 겹치거나 형식이 틀리면 거부
- [x] 프로젝트 구성원이 아닌 사람은 목록에서 볼 수 있지만(`myRole: null`) 들어갈 수 없고(404), `/access` 로 관리자를 안내받는다 (D-047 로 바뀜)
- [x] 워크스페이스 관리자는 구성원이 아닌 프로젝트도 보고 관리할 수 있다
- [x] 보기·편집 역할은 프로젝트 설정과 구성원을 바꿀 수 없다 (403)
- [x] 마지막 관리 역할은 내보내거나 낮출 수 없다
- [x] 비활성 구성원이나 없는 사람은 프로젝트에 추가할 수 없다

화면은 자동 테스트가 없고 에이전트가 브라우저로 확인하지 못했다(lint, typecheck 만 통과).

## 2단계: 프리셋과 이슈 쓰기 (명세만)

### 이슈의 두 부분

**속성** (모든 이슈가 같다. 목록에서 거르고 정렬하는 데 쓴다)

| 속성 | 값 |
|---|---|
| 상태 | 프로젝트의 상태 목록 중 하나 |
| 프리셋 | 버그 / 고도화 / 기능 요청. 만든 뒤에도 바꿀 수 있다(문서는 그대로 둔다) |
| 담당자 | 프로젝트 구성원 한 명 또는 없음 |
| 우선순위 | 없음 / 긴급 / 높음 / 보통 / 낮음 |
| 기한 | 날짜 또는 없음 |
| 라벨 | 프로젝트의 라벨 여러 개 |

프리셋마다 입력 칸을 따로 두지 않는다. 그렇게 하면 Jira의 필드 설정이 된다 (D-033).

**문서** (Outline 같은 부분)

- 제목(이슈 제목) + 본문. 본문은 블록 편집기: 제목 1~3단계, 문단, 목록, **체크리스트**, 코드 블록, 인용, 표, 구분선, 이미지, 링크.
- 본문의 제목들로 **목차**가 자동으로 만들어져 오른쪽에 보이고, 누르면 그 위치로 간다.
- `/` 로 블록 삽입, 마크다운 입력(`## `, `- `, `[] `)이 바로 서식으로 바뀐다.
- 이미지는 붙여넣거나 끌어다 놓으면 올라간다. M2a 의 변환·저장을 그대로 쓴다(본문 이미지는 최대 1600px).
- 저장 버튼이 없다. 멈추면 자동 저장하고 "저장됨"을 보여준다.

### 프리셋

새 이슈를 만들 때 프리셋을 고르면 본문에 목차가 깔린다. 각 제목 아래에는 무엇을 쓰면 되는지 안내 문구가 흐리게 보이고, 쓰기 시작하면 사라진다.

| 프리셋 | 깔리는 목차 |
|---|---|
| 버그 | 무슨 문제인가 / 재현 방법 / 기대한 결과 / 실제 결과 / 환경 / 완료 조건 |
| 고도화 | 배경 / 현재 동작 / 바꾸려는 동작 / 영향 범위 / 완료 조건 |
| 기능 요청 | 왜 필요한가 / 누가 쓰는가 / 원하는 동작 / 범위 밖 / 완료 조건 |

- 모든 프리셋의 마지막은 **완료 조건**이고 체크리스트로 시작한다. 본문의 체크박스 수가 목록에서 진행률(`3/5`)로 보인다. 개발자가 "무엇이 되면 끝인가"를 여기서 본다.
- 프로젝트 관리 역할은 프리셋의 목차 제목과 안내 문구를 고칠 수 있다. 프리셋을 새로 만들거나 지우는 것은 없다 (사용자 확정).
- 프리셋을 고쳐도 이미 쓴 이슈는 바뀌지 않는다.

### 개발자가 쓰는 것

- **이슈 키** `FLOW-12`: 누르면 복사. 브랜치 이름과 커밋 메시지에 쓴다.
- **"준비됨" 상태**: 기획이 끝나 개발을 시작해도 되는 이슈. "백로그"는 아직 쓰는 중이라는 뜻이다.
- **완료 조건 진행률**: 목록과 상세에 보인다.
- **변경 이력** (4단계): 준비됨 이후에 본문이 바뀌면 무엇이 바뀌었는지 보인다.

### 상태 목록 (프로젝트를 만들 때 기본으로 생긴다)

| 상태 | 범주 | 뜻 |
|---|---|---|
| 백로그 | backlog | 쓰는 중이거나 아직 다듬지 않음 |
| 준비됨 | unstarted | 내용이 정리되어 개발을 시작할 수 있음 |
| 진행 중 | started | 개발 중 |
| 완료 | completed | 끝남 |
| 취소 | canceled | 하지 않기로 함 |

범주 5개는 고정이고, 범주 안에서 상태를 추가하거나 이름을 바꾸는 것은 이후에 다룬다.

### 편집기와 저장 (기술 결정, D-034)

- 편집기: **Tiptap**(ProseMirror 기반). 직접 만들지 않는다.
- 저장 형식: 편집기의 문서 JSON 을 `jsonb` 로 저장한다. 검색과 미리 보기를 위해 서버가 본문에서 뽑은 평문을 함께 저장한다.
- 서버는 받은 문서를 허용된 블록 종류만 남기도록 검증한다. HTML 을 저장하거나 그대로 내보내지 않는다.
- **동시 편집**: 한 글자씩 합쳐지는 공동 편집은 하지 않는다. 이슈마다 `version` 을 두고, 저장할 때 내가 본 버전을 함께 보낸다. 그 사이 다른 사람이 본문을 고쳤으면 409 로 거절하고, 화면은 "다른 사람이 먼저 고쳤습니다"와 함께 두 내용을 보여 주고 고르게 한다. 속성(상태, 담당자 등)은 필드 단위로 나중 값이 이긴다.
- 같은 이슈를 보고 있는 사람은 아바타로 보여 준다(누가 고치는 중인지 알 수 있게).

## 3단계: 이슈 목록 (명세만)

- `/project/{id}`: 상태별로 묶인 이슈 목록. 한 줄 = 우선순위 · 키 · 프리셋 · 제목 · 완료 조건 진행률 · 라벨 · 기한 · 담당자.
- 필터: 상태, 프리셋, 담당자, 라벨, 우선순위. "내 이슈" 바로 가기.
- 줄의 상태·담당자·우선순위 아이콘을 눌러 그 자리에서 바꾼다. 즉시 반영하고 실패하면 되돌린다.
- 다른 사람이 바꾼 것은 WebSocket 으로 바로 반영된다 ([../02-architecture.md](../02-architecture.md) "실시간 동기화").
- 화면의 세부는 [../01-product.md](../01-product.md) 4.2 를 따른다.

## 4단계: 댓글과 변경 이력 (처음 쓴 명세. 구현된 모습은 "지금 구현된 범위"의 댓글·`@` 태그·이슈 활동)

- 댓글: 이슈 아래에 시간순. 본문과 같은 편집기의 가벼운 판(제목 없음). `@` 로 구성원 언급.
- 변경 이력: 속성 변경은 "김지민이 상태를 준비됨 → 진행 중으로 바꿨습니다"처럼 한 줄로, 댓글 사이에 시간순으로 섞여 보인다. 본문 변경은 "본문을 고쳤습니다"와 함께 이전 판을 볼 수 있다.
