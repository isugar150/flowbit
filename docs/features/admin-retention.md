# 관리자 설정: 데이터 보관

삭제한 티켓·문서·댓글은 지금까지 표시만 하고 행을 남겼다(D-079, D-121). 관리자가 항목별로 "삭제하고 얼마가 지나면 영구 삭제할지"를 정하면, 서버가 그 기간이 지난 것을 실제로 지운다. 사용자 지정(2026-10-15), 결정은 D-132.

## 범위

- 관리자 설정의 **"데이터 보관"** 탭 (`/admin/retention`)
- 항목 네 가지(삭제된 티켓·문서·댓글, **공유 링크 접속 기록**(D-198, 아래))에 각각 **"영구 삭제 안 함"** 또는 **"N일 / N주 / N개월 뒤 영구 삭제"** 를 정한다. 워크스페이스 전체에 하나의 설정이다(프로젝트별 설정은 없다)
- 서버가 주기적으로 기간이 지난 것을 지운다

영구 삭제를 한 회에는 **그 안에 있던 사진(WebP 사본과 원본)도 정리한다**(D-171, [admin-files.md](admin-files.md) "보관 배치와의 연결"). 다른 본문에서도 쓰는 사진은 남고, 올라온 지 24시간이 안 된 것은 건드리지 않는다.

범위 밖: 아카이브된 프로젝트(삭제가 아니라 "지워지는 것은 없다"고 안내하는 기능이다), "지금 정리" 버튼, 정리 결과를 화면에 보여 주기, 백업 파일에 이 설정을 넣기.

## 항목

| 항목 (`API 이름`) | 기준 시각 | 영구 삭제하면 함께 사라지는 것 |
|---|---|---|
| 삭제된 티켓 (`issues`) | `issues.deleted_at` | 활동 기록, 댓글, 리액션, 첨부 파일(저장소의 파일까지), 티켓의 문서, 라벨·담당자·구독. **하위 티켓은 남고** 상위가 없는 티켓이 된다 |
| 삭제된 문서 (`documents`) | `documents.deleted_at` | 그 문서 안에 든 문서 |
| 삭제된 댓글 (`comments`) | `issue_comments.deleted_at`, 프로젝트·문서·목표의 일반 댓글(`content_comments.deleted_at`)과 블록 댓글(`content_thread_comments.deleted_at`) (D-165) | 그 댓글의 이모지, 댓글에 붙은 파일(저장소의 파일까지. D-164) |
| 공유 링크 접속 기록 (`shareAccesses`, D-198) | `share_accesses.accessed_at`(삭제가 아니라 **기록한 시각**) | 그 줄만. 공유 링크 자체와 다른 기록은 남는다 ([sharing.md](sharing.md)) |

- 기본값은 셋 다 **영구 삭제 안 함**이다. 설치한 뒤 관리자가 정하기 전에는 지금처럼 아무것도 지우지 않는다.
- 삭제되지 않은 티켓 안의 삭제된 문서·댓글은 각자의 설정을 따른다. 삭제된 티켓 안의 것은(따로 삭제됐든 아니든) 티켓이 영구 삭제될 때 함께 사라진다.
- 영구 삭제한 티켓의 번호는 다시 쓰지 않는다(번호는 `instance_settings.next_issue_number` 로만 늘어난다).
- 기간은 1~999 사이의 정수와 단위(일·주·개월)다. 개월은 달력의 달이다(UTC 기준 "같은 날짜"까지).

## 정리 작업

- 서버가 뜨고 1분 뒤에 처음, 그 뒤로 1시간마다 돈다 (`flowbit.retention.initial-delay`, `flowbit.retention.interval`). `flowbit.retention.enabled=false` 면 돌지 않는다(통합 테스트가 끈다).
- 공유 링크 접속 기록(D-198)은 같은 작업에서 `accessed_at` 이 기간보다 오래된 줄을 지운다(다른 항목과 따로, 같은 트랜잭션). 정리한 개수는 `DATA_PURGED` 의 `detail.shareAccesses` 에 들어간다.
- 한 번 돌 때 댓글 → 문서 → 티켓 순으로 지운다. 티켓·댓글의 첨부 파일은 DB 에서 지운 뒤 저장소에서 지운다(파일 삭제가 실패해도 DB 는 되돌리지 않는다, 남은 파일은 해가 없다).
- 설정과 상관없이 같은 작업이 **영구 삭제된 티켓·문서·목표·프로젝트가 남긴 블록 스레드, 활동, 일반 댓글, 파일**(`content_*` 는 대상에 외래 키가 없다. D-165)도 지우고(`sweepOrphans`), 같은 작업이 **댓글을 쓰다 올렸지만 하루 안에 보내지 않은 파일**(`issue_attachments.pending`)도 지운다(D-164). 개수는 `DATA_PURGED` 에 넣지 않는다.
- 무엇이든 지웠으면 감사 로그에 `DATA_PURGED`(행위자 없음, `detail` 에 항목별 개수)를 남긴다. 설정을 바꾸면 `RETENTION_SETTINGS_CHANGED`.
- 지운 것을 실시간으로 알리지 않는다. 삭제된 티켓·문서는 이미 목록에서 빠져 있고, 그것을 열어 둔 화면은 다음에 불러올 때 "찾을 수 없음"이 된다.

## API

| 메서드·경로 | 내용 |
|---|---|
| `GET /api/v1/admin/retention` | 지금 설정. **관리자** |
| `PUT /api/v1/admin/retention` | 세 항목을 통째로 바꾼다. **관리자** |

```json
{
  "issues": { "amount": 3, "unit": "MONTHS" },
  "documents": { "amount": 30, "unit": "DAYS" },
  "comments": null,
  "shareAccesses": { "amount": 90, "unit": "DAYS" }
}
```

- `null`(또는 빠진 항목)은 영구 삭제 안 함. 네 항목 모두 통째로 바꾼다(`PUT`). `unit` 은 `DAYS`·`WEEKS`·`MONTHS`.
- `amount` 가 1~999 가 아니면 422 `VALIDATION_FAILED`, 필드는 `issues.amount` 처럼 적는다.

## 화면

- 항목마다 한 줄: 이름과 설명, 오른쪽에 "영구 삭제 안 함 / 기간 지정" 선택. 기간을 고르면 숫자 칸과 단위(일·주·개월) 선택이 나온다.
- 아래에 "저장" 버튼. 기간을 줄이거나 새로 켜는 저장이면 "기간이 지난 항목은 1시간 안에 영구 삭제되고 되돌릴 수 없습니다"를 확인받는다.
- 맨 위에 안내: 영구 삭제된 것은 복원할 수 없고, 데이터 백업은 PostgreSQL 덤프로 한다.

- [x] 기간이 지난 삭제된 문서·댓글이 지워진다
