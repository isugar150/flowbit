# M1. 로그인 및 초기 설정

상태: **구현됨** (2026-10-12). 범위와 초기 설정 방식은 사용자가 확정했고, 사용자가 브라우저에서 초기 설정과 로그인을 직접 확인했다. 세부 수치(비밀번호 길이, 잠금 기준 등)는 제안값으로 구현했으며 "확인이 필요한 것"에 모아 두었다. 인수 기준 중 백엔드에서 확인되는 것은 통합 테스트가 있고, 화면 흐름의 자동 테스트(E2E)는 아직 없다.

## 목표

Flowbit을 처음 설치한 사람이 브라우저에서 **워크스페이스 이름(과 로고), 관리자 아이디와 비밀번호를 정하면** 초기 설정이 끝나고, 그 계정으로 로그인할 수 있다. 이후에는 아이디와 비밀번호로 로그인하고 로그아웃할 수 있다.

## 범위

포함:

- 초기 설정 화면: 워크스페이스 이름과 로고, 관리자 아이디와 비밀번호 입력 (사용자 확정, D-015, D-051)
- 아이디/비밀번호 로그인, 로그아웃
- 로그인 상태 유지(세션)와 로그인이 필요한 화면 보호
- 로그인 실패 제한과 계정 잠금
- 감사 로그 기록
- 로그인 후 도착하는 빈 홈 화면 (사용자 아이디와 로그아웃만 있는 앱 레이아웃)

제외 (이후 마일스톤):

- 조직 이름, 언어, 시간대 등 인스턴스 설정 화면 (M2)
- 사용자 추가/초대, 역할 변경, 이메일·표시 이름 등 프로필 (M2)
- 비밀번호 변경·재설정 (M2)
- 소셜 로그인, SSO, 2단계 인증, 이메일 발송

## 사용자 흐름

### 1. 초기 설정

1. 설치자가 서버를 실행하고 브라우저로 접속한다. 초기 설정 전에는 어떤 주소로 들어와도 `/setup` 으로 이동한다.
2. 워크스페이스 이름, 로고(선택), 관리자 아이디, 비밀번호, 비밀번호 확인을 입력하고 제출한다.
3. 워크스페이스 이름이 저장되고 관리자 계정이 만들어지며 초기 설정이 완료 처리된다. 로고를 골랐으면 이어서 올라간다. 바로 그 계정으로 로그인된 상태가 되어 홈(`/`)으로 이동한다.
4. 이후 `/setup` 에 접근하면 `/login` (로그인 상태면 `/`)으로 이동한다. 로그아웃한 뒤에는 `/login` 에서 같은 아이디와 비밀번호로 로그인한다.

주의: 초기 설정이 끝나기 전에는 서버 주소에 접근할 수 있는 누구나 관리자 계정을 만들 수 있다. 설치 직후 바로 초기 설정을 하도록 README 와 설정 화면에 안내한다. (D-015 에서 감수하기로 한 위험)

### 2. 로그인

1. 로그인하지 않은 사용자가 보호된 화면에 접근하면 `/login?next=<원래 경로>` 로 이동한다.
2. 아이디와 비밀번호를 입력해 제출한다.
3. 성공하면 `next` 로(없으면 `/`) 이동한다. `next` 는 같은 사이트 안의 경로만 허용한다.
4. 실패하면 폼 위에 "아이디 또는 비밀번호가 올바르지 않습니다"를 보여준다. 아이디가 존재하는지는 알려주지 않는다.
5. 이미 로그인한 사용자가 `/login` 에 오면 `/` 로 이동한다.

### 3. 로그아웃

헤더의 사용자 메뉴에서 로그아웃하면 세션이 삭제되고 `/login` 으로 이동한다.

## 규칙

### 입력 검증

| 필드 | 규칙 |
|---|---|
| 아이디 | 4~32자. 영문 소문자, 숫자, `.`, `_`, `-` 만 허용. 첫 글자는 영문 또는 숫자. 대문자로 입력해도 소문자로 바꿔 저장하고 비교한다 |
| 비밀번호 | 10~128자. 문자 종류 조합은 강제하지 않는다. 아이디와 같은 값은 거부 |
| 비밀번호 확인 | 프론트엔드에서만 확인한다. API 로 보내지 않는다 |

### 초기 설정

- 초기 설정은 한 번만 성공한다. 동시에 두 요청이 와도 하나만 성공해야 한다 (`instance_settings` 행을 잠그고 `setup_completed_at` 을 확인).
- 관리자 생성, 워크스페이스 이름 저장, 완료 표시는 한 트랜잭션이다.
- 워크스페이스 이름은 앞뒤 공백을 떼고 1~100자. 화면에서는 필수이고, API 에서는 생략하거나 비우면 기본 이름(`Flowbit`)을 쓴다.
- **로고는 설정 요청에 싣지 않는다** (D-051). 로그인 전에 파일을 받는 공개 경로를 만들지 않으려고, 화면이 설정에 성공한 뒤(이미 로그인된 상태) `PUT /api/v1/admin/workspace/logo` 로 올린다. 파일 종류와 크기는 고를 때 화면이 먼저 확인한다. 그래도 올리기에 실패하면 "초기 설정은 끝났지만 로고를 올리지 못했습니다"와 함께 워크스페이스 설정으로 가기 / 로고 없이 시작하기를 보여 준다(설정은 한 번만 되므로 폼으로 돌아가지 않는다).
- 만들어지는 계정의 역할은 `ADMIN`, 상태는 `ACTIVE` 다.
- 같은 IP 에서 초기 설정 요청은 분당 10회로 제한한다.

### 로그인

- 비밀번호 검증은 계정이 없을 때도 같은 시간이 걸리게 한다 (가짜 해시와 비교).
- 연속 5회 실패하면 계정을 15분간 잠근다. 잠긴 동안에는 올바른 비밀번호로도 로그인할 수 없고, 응답은 일반 실패와 같다.
- 로그인 성공 시 실패 횟수를 0 으로 되돌리고 `last_login_at` 을 기록한다.
- `DISABLED` 상태의 사용자는 로그인할 수 없다. 응답은 일반 실패와 같다.
- 같은 IP 에서 로그인 시도는 분당 10회로 제한한다. 초과 시 429.
- 세션 규칙은 [../06-api-conventions.md](../06-api-conventions.md) 의 "인증" 참고.

### 감사 로그

`SETUP_COMPLETED`, `LOGIN_SUCCEEDED`, `LOGIN_FAILED`, `ACCOUNT_LOCKED`, `LOGOUT` 을 기록한다. `LOGIN_FAILED` 의 `detail` 에는 시도한 아이디를 넣되 비밀번호는 넣지 않는다.

## API

공통 규칙과 오류 형식은 [../06-api-conventions.md](../06-api-conventions.md).

### `GET /api/v1/setup/status` (공개)

```json
{ "completed": false }
```

### `POST /api/v1/setup` (공개, 초기 설정 전에만)

```json
{ "loginId": "admin", "password": "...", "workspaceName": "우리 회사" }
```

`workspaceName` 은 선택. 검증 오류의 필드 이름은 `workspaceName`.

성공: 201, 세션 쿠키 발급, 본문은 `GET /api/v1/me` 와 같은 형태.
오류: 409 `SETUP_ALREADY_COMPLETED`, 422 `VALIDATION_FAILED`, 429

### `GET /api/v1/auth/csrf` (공개)

CSRF 쿠키를 발급한다. 204.

### `POST /api/v1/auth/login` (공개)

요청: `{ "loginId": "...", "password": "..." }`
성공: 200, 세션 쿠키 발급, 본문은 `GET /api/v1/me` 와 같은 형태.
오류: 401 `INVALID_CREDENTIALS` (계정 없음, 비밀번호 틀림, 잠김, 비활성 모두 동일), 409 `SETUP_REQUIRED` (초기 설정 전), 429

### `POST /api/v1/auth/logout` (인증 필요)

204. 세션 삭제, 쿠키 만료.

### `GET /api/v1/me` (인증 필요)

```json
{
  "id": "0199...",
  "loginId": "admin",
  "role": "ADMIN",
  "locale": "ko",
  "timezone": "Asia/Seoul"
}
```

`locale`, `timezone` 은 사용자 값이 없으면 인스턴스 기본값을 채워서 내려준다.
오류: 401 `UNAUTHENTICATED`

## 데이터

`instance_settings`, `users`, `user_sessions`, `audit_events`. 정의는 [../05-data-model.md](../05-data-model.md) 의 "M1 테이블".

## 화면

| 경로 | 내용 |
|---|---|
| `/setup` | "워크스페이스"(이름, 로고 고르기와 미리 보기) + "관리자 계정"(아이디, 비밀번호, 비밀번호 확인), "설정 마치고 시작하기" 버튼. 한 화면 |
| `/login` | 아이디, 비밀번호, 로그인 버튼 |
| `/` | 앱 레이아웃(헤더에 사용자 메뉴)과 빈 상태 안내 |

화면 요구사항:

- 제출 중에는 버튼을 비활성화하고 진행 중임을 보여준다. 중복 제출이 되지 않는다.
- 필드 오류는 필드 아래에, 그 외 오류는 폼 위에 보여준다. 제출 실패 시 첫 오류 필드로 포커스를 옮긴다.
- 비밀번호 필드에는 보기/숨기기 전환이 있다. `autocomplete` 속성을 올바르게 지정한다 (`username`, `current-password`, `new-password`).
- 설정 화면에는 이 계정이 관리자 계정이 된다는 설명과 아이디 규칙 안내가 있다.
- 429 응답이면 얼마 뒤에 다시 시도할 수 있는지 알려준다.
- 네트워크 오류와 서버 오류(500)에 대한 문구가 따로 있다.
- 라이트/다크 테마, 좁은 화면(360px), 키보드만으로 전체 흐름 진행 가능.

리다이렉트 규칙 (`proxy.ts` 와 서버 컴포넌트에서 처리):

| 상태 | 접근 경로 | 이동 |
|---|---|---|
| 초기 설정 전 | `/setup` 이외 | `/setup` |
| 초기 설정 후 | `/setup` | `/login` 또는 `/` |
| 로그인 안 함 | 보호된 경로 | `/login?next=...` |
| 로그인 함 | `/login` | `/` |

## 인수 기준

각 항목마다 자동화된 테스트가 있어야 한다.

초기 설정:

- [ ] 초기 설정 전에는 `/` 접근 시 `/setup` 으로 이동한다
- [ ] 유효한 아이디와 비밀번호로 설정을 마치면 그 계정으로 로그인된 상태가 된다
- [ ] 설정 후 로그아웃하고, 같은 아이디와 비밀번호로 다시 로그인할 수 있다
- [ ] 설정이 끝난 뒤에는 다시 설정할 수 없다 (409)
- [ ] 동시에 보낸 두 설정 요청 중 하나만 성공하고 사용자는 한 명만 만들어진다
- [ ] 입력 검증 규칙을 어기면 필드별 오류와 함께 422 를 받는다
- [ ] 설정에서 정한 워크스페이스 이름이 저장되고, 보내지 않으면 기본 이름을 쓴다. 너무 긴 이름은 422 이고 설정은 끝나지 않는다

로그인:

- [ ] 올바른 아이디/비밀번호로 로그인하면 `/me` 가 사용자 정보를 돌려준다
- [ ] 아이디는 대소문자를 구분하지 않는다
- [ ] 없는 아이디와 틀린 비밀번호의 응답이 같다
- [ ] 5회 연속 실패하면 올바른 비밀번호로도 로그인할 수 없고, 15분 뒤에는 가능하다
- [ ] 로그인 성공 시 세션 ID 가 바뀐다
- [ ] 로그아웃 후에는 이전 세션 쿠키로 `/me` 를 부를 수 없다 (401)
- [ ] CSRF 토큰 없이 보낸 `POST` 는 거부된다 (403)
- [ ] `next` 에 외부 주소를 넣어도 외부로 이동하지 않는다
- [ ] 로그인하지 않고 보호된 화면에 접근하면 로그인 화면으로 가고, 로그인 후 원래 화면으로 돌아온다

감사 로그:

- [ ] 설정 완료, 로그인 성공/실패, 잠금, 로그아웃이 기록된다
- [ ] 감사 로그와 애플리케이션 로그에 비밀번호가 남지 않는다

## 구현 순서 (제안)

1. 백엔드: 마이그레이션 (`instance_settings`, `users`, `user_sessions`, `audit_events`)
2. 백엔드: 보안 설정 (세션, CSRF, 공개 경로, 401/403 을 Problem Details 로)
3. 백엔드: `setup` 모듈 (status, setup)
4. 백엔드: `auth` 모듈 (login, logout, 잠금, 횟수 제한), `user` 모듈 (`/me`)
5. 백엔드: 감사 로그
6. 프론트엔드: `lib/api` 클라이언트 완성 (CSRF, 오류 파싱), OpenAPI 타입 생성
7. 프론트엔드: `/setup`
8. 프론트엔드: `/login`, 리다이렉트 규칙, 앱 레이아웃과 로그아웃
9. E2E 테스트, 디자인 리뷰, 접근성 점검

## 확인이 필요한 것

아래 값은 제안값 그대로 구현되어 있다. 사용자가 다른 값을 원하면 `CredentialPolicy`, `application.yml` 의 `flowbit.auth.*`, 프론트엔드 `features/auth/schema.ts` 와 이 문서를 함께 고친다.

1. 아이디 규칙 (4~32자, 영문 소문자·숫자·`._-`)
2. 비밀번호 최소 길이(10자), 잠금 기준(5회/15분), 세션 수명(7일/최대 30일)
