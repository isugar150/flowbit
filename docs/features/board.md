# 보드 (칸반)

상태 (2026-10-28): **구현됨** (D-234, D-235). `01-product.md` §4.3 의 보드를 티켓 목록 화면의 **기본 보기**로 넣었다.

- 도구 줄 오른쪽의 보기 전환은 **보드 · 목록 · 타임라인 · 캘린더** 순서이고, 티켓 화면을 처음 열면 **보드**가 나온다(D-235). 주소 `?view=board`(기본이라 주소에는 보통 없다), 목록은 `?view=list`. 목록을 보드로 *바꾼* 것이 아니라 같은 화면의 한 보기라서, 내 티켓·요청한 티켓·전체 티켓 어디서나 쓰고, 검색·필터·"완료" 선택·"이번 사이클"·저장한 뷰가 목록과 똑같이 적용된다. 온보딩 투어의 예시 화면만 목록으로 연다(`defaultView="list"`).
- **정렬**: 도구 줄의 "정렬"(목록과 같은 기준)이 각 열 안의 순서를 정한다. **묶음은 없다**(열이 상태). 완료 선택도 목록처럼 있다.
- **열 = 상태**. 상태 목록의 순서(백로그 → 준비됨 → … → 완료 → 취소) 그대로. 열 머리에 상태 아이콘, 이름, 티켓 수.
- **카드**: 키, **프로젝트 이름**(프로젝트 하나로 좁히지 않은 보드에서만. 목록의 프로젝트 칸과 같은 규칙이고, 한 프로젝트의 보드에서는 모두 같아서 뺀다. 프로젝트가 없는 티켓은 비운다), 제목(3줄까지), 우선순위, 라벨, 기한, 추정치(켠 프로젝트만), **댓글 수·활동 수**, 담당자 아바타, 상위 티켓 키, 선행 티켓이 남아 있으면 "선행 작업 대기", 트리아지 대기면 "트리아지". **카드의 아무 곳이나 누르면** 티켓 창이 열린다(`/issue/KEY` 가로채기 경로). 카드 안의 상태 버튼·링크·라벨처럼 따로 동작하는 곳과, 방금 끌었다 놓은 직후의 누름은 열지 않는다.
- **옮기기**: 카드를 다른 열로 끌어 놓으면 그 상태가 된다. **dnd-kit**(`@dnd-kit/core`)으로 구현했고(D-235), 마우스는 6px 움직여야, 터치는 0.25초 누르고 있어야 끌기로 친다(그보다 짧은 누름은 카드 열기). 끄는 동안 카드 모양이 마우스를 따라오고(`DragOverlay`), 놓을 열에 링이 보인다. 키보드·터치는 카드의 상태 버튼(아이콘)으로도 같은 일을 한다. 낙관적 갱신이라 놓는 즉시 옮겨지고, 실패하면 되돌아온다. 옮긴 것은 실행 취소(`Ctrl/⌘+Z`)로 되돌린다. 보기 역할·삭제된 티켓은 옮길 수 없다. 스크린 리더 안내 문구는 `lib/dnd.ts`.
- "완료" 선택(2주 등)을 따라 끝난 지 오래된 티켓은 보드에서 빠지고 열 아래에 몇 개가 숨었는지 알린다.
- 좁은 화면: 열이 85% 폭으로 옆으로 밀려 넘어간다(보드는 가로로 넘기는 보기다).

코드: `features/issues/components/issue-board.tsx`, `issues-view.tsx`(보기 전환·정렬·옮기기), `issue-views.tsx`(`DEFAULT_ISSUE_VIEW`, `useIssueView(defaultView)`). 화면은 아무도 확인하지 않았다.

## 가로 스크롤 영역 (2026-10-28)

보드 바깥 레이아웃은 화면 너비를 넘지 않도록 최소 너비를 0으로 제한하고, 상태 열의 가로 넘김은 보드 안의 스크롤 영역에서 처리한다. 페이지 전체가 옆으로 이동해 보드가 잘리거나 빈 공간이 생기지 않도록 한다. 카드 끌기·상태 열의 고정 너비는 유지한다.

원인과 수정 효과는 사용자 환경에서 아직 재현 확인되지 않았다. 오래 머문 뒤 발생하고 새로고침으로 복구되는 현상은 브라우저 렌더링·실시간 갱신 가능성도 열어 둔다.
