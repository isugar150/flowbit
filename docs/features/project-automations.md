# 프로젝트 자동화와 리뷰 상태

2026-10-28 사용자 확정. 상태가 바뀌었을 때 프로젝트별로 후속 작업을 자동 실행한다.

## 상태

진행 중 → 리뷰 준비됨 → 리뷰 중 → 완료. 리뷰 준비됨·리뷰 중은 모두 IN_PROGRESS 범주(미완료)다. V13에서 기존 설치에도 기본 상태를 더한다. 같은 이름의 상태가 이미 있으면 중복 생성하지 않고 해당 상태를 미완료 범주로 맞춘다. 두 상태는 기존 진행 중 상태 뒤에 놓으며 기존 티켓·기본 상태는 유지한다. 관리자는 기존 상태 화면에서 이름·순서를 관리한다.

## 설정과 파이프라인

프로젝트 설정 및 관리자 설정 > 프로젝트의 **자동화**에서 관리 역할 또는 워크스페이스 관리자가 규칙을 만든다. 이름, 켜짐, 이전 상태(모든 상태 가능), 다음 상태(필수), 실행 블록을 저장한다. 실행 블록을 팔레트에서 끌어 넣고 순서를 바꾸는 세로 파이프라인이다. 클릭으로 추가·위아래 이동도 가능하다. 한 규칙에 실행 1~10개, 프로젝트당 50개. 분기·반복·지연 실행은 이번 범위에 없다.

실행 블록:
- 알림 보내기: 지정 구성원, 담당자, 요청자, 프로젝트 관리 역할 중 선택(지정 구성원은 복수 선택). 메시지(선택). 기존 수신함·메일·푸시·API 통로를 이용한다. 자동화에서 명시적으로 정한 수신자는 상태를 바꾼 본인이어도 받는다. 프로젝트 접근 권한이 없는 사람·비활성 계정에게는 보내지 않는다.
- 담당자 변경: 고른 프로젝트의 편집·관리 역할 구성원으로 교체(복수, 최대 10명). 빈 선택은 담당자 비우기.
- 라벨 추가 / 라벨 제거: 고른 라벨을 더하거나 뺀다. 다른 라벨은 유지한다.

예: 진행 중 → 리뷰 준비됨일 때 ‘담당자를 리뷰어로 변경’ → ‘담당자에게 리뷰 요청 알림’ → ‘리뷰 대기 라벨 추가’. 실행 순서가 영향을 준다.

## 실행

실제로 상태 ID가 바뀐 경우에만, 변경 후 프로젝트의 켜진 규칙 중 이전·다음 상태가 맞는 것을 생성 순서대로 실행한다. 수동 변경·보드 이동·Git 상태 변경에 적용한다. 티켓 생성, 같은 상태 저장, 상태 정의 삭제에 따른 일괄 이동에서는 실행하지 않는다. 담당자·라벨 변경은 원래 상태 변경과 같은 트랜잭션에 저장하고 일반 활동에도 반영한다. 규칙 실행은 상태를 다시 바꾸지 않아 순환하지 않는다. 프로젝트 변경과 상태 변경이 함께 일어나면 도착한 프로젝트 규칙만 사용한다.

규칙별 실행 기록은 티켓 번호·규칙 이름 스냅샷·실행 시각·각 실행 결과를 남긴다. 규칙을 삭제해도 기록은 남고, 프로젝트/티켓 영구 삭제 시 기록도 삭제된다. 한 티켓 버전·규칙 조합은 한 번 기록한다. 실행 시 구성원·라벨이 없어졌으면 그 대상만 건너뛰고 결과에 표시한다. 알림 결과는 발송 요청이며 외부 채널의 전달 성공을 뜻하지 않는다. 외부 발송은 기존처럼 DB 커밋 후 이루어진다. 프로젝트 설정에는 최근 50개 실행 기록을 표시한다.

## API / 저장소

- GET·POST `/api/v1/projects/{id}/automations`
- PUT·DELETE `/api/v1/projects/{id}/automations/{ruleId}`
- GET `/api/v1/projects/{id}/automations/runs` (최근 50개)
- 관리자 설정은 같은 경로를 `/api/v1/admin/projects/{id}/automations` 아래에서 제공한다.
- 조회·변경 모두 프로젝트 관리 역할을 요구한다. 관리자 경로는 워크스페이스 관리자 전용이며 일반 티켓 접근 권한을 확장하지 않는다.
- V14: `project_automations`(프로젝트, 이름, 켜짐, 이전·다음 상태, 실행 JSON, 생성·수정 시각), `automation_runs`(규칙 ID, 프로젝트, 티켓, 버전, 이름 스냅샷, 결과 JSON, 시각). 설정 변경은 감사 로그 `PROJECT_AUTOMATIONS_CHANGED`.
- 새 알림 종류 `AUTOMATION_TRIGGERED`를 API 알림의 보낼 변경에도 제공한다.

## 인수 기준

- 리뷰 두 상태는 진행 중 범주이며 완료 집계에서 제외된다.
- 관리자가 규칙을 저장·수정·끄기·삭제하고 다시 조회할 수 있다.
- 상태 전환 시 실행 순서대로 담당자 교체·라벨 추가/제거·지정 대상 알림이 실행된다.
- 실행 기록에서 어떤 티켓에 어떤 규칙·실행이 적용됐는지 확인한다.
- 같은 상태 재저장·꺼진 규칙은 다시 실행하지 않는다.
- Git 상태 변경에서도 같은 규칙이 실행된다.

기존 티켓의 라벨 상한(10개)을 유지하며, 추가 블록이 상한을 넘기면 남은 자리까지만 추가하고 결과에 표시한다. 조건으로 사용한 상태를 삭제하면 연결된 규칙도 삭제되지만 실행 기록은 남는다.

## 사람 속성 알림 대상

알림 대상 **티켓의 사람 속성**은 audience=PROJECT_FIELD와 fieldId로 저장한다. 티켓 값(미지정이면 프로젝트 기본값)의 활성·접근 가능한 사람에게 알린다. [공통 속성 명세](project-issue-fields.md) 참고.

## 리뷰 단계 아이콘 (2026-10-28)

진행 중은 원 안의 점, 리뷰 준비됨은 클립보드, 리뷰 중은 눈 아이콘으로 구분한다. 공통 StatusIcon에 상태 ID·이름을 전달하여 목록·보드·상태 선택·상세·캘린더·관리자 상태 화면에 적용한다. 고정 리뷰 ID와 기존 동일 이름 상태를 모두 지원한다. 두 리뷰 단계는 계속 미완료다.

자동화 블록 ID는 HTTP 설치 환경에서도 생성해야 한다. randomUUID가 없으면 getRandomValues로 RFC 4122 v4 UUID를 생성한다. 인증용 토큰에는 사용하지 않는다.
