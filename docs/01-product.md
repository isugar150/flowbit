# 01. 제품 정의

## 한 줄 정의

Flowbit은 한 조직이 자기 서버에 설치해서 쓰는 이슈·프로젝트 관리 도구다. Jira의 핵심 흐름(프로젝트 → 이슈 → 보드 → 스프린트)을 더 가볍게 제공하는 것이 목표다.

## 확정된 전제

| 항목 | 내용 |
|---|---|
| 배포 형태 | 단일 조직 설치형. 한 인스턴스 = 한 조직. 워크스페이스/테넌트 개념 없음 |
| 1차 범위 | 로그인 및 초기 설정 ([features/M1-auth-and-setup.md](features/M1-auth-and-setup.md)) |
| 백엔드 | Spring Boot + Kotlin (최신 안정 버전) |
| 프론트엔드 | Next.js + shadcn/ui (최신 안정 버전) |

## 사용자 유형

| 유형 | 설명 | M1에서 |
|---|---|---|
| 설치자 | 서버에 Flowbit을 올리고 초기 설정을 하는 사람. 설정 후 첫 관리자가 된다 | 사용 |
| 관리자 (`ADMIN`) | 인스턴스 설정, 사용자 관리 | 역할만 존재 |
| 구성원 (`MEMBER`) | 프로젝트에서 이슈를 다루는 일반 사용자 | 역할만 존재 |

프로젝트 단위 역할(프로젝트 관리자, 뷰어 등)은 프로젝트 기능과 함께 도입한다. (초안)

## 용어

문서, 코드, UI에서 같은 뜻으로 쓴다.

| 용어 | 코드 식별자 | 뜻 |
|---|---|---|
| 인스턴스 | `instance` | 설치된 Flowbit 하나. 조직 하나와 1:1 |
| 초기 설정 | `setup` | 설치 직후 한 번만 하는 설정. 관리자 아이디와 비밀번호를 받아 첫 관리자 계정을 만든다 |
| 사용자 | `user` | 로그인할 수 있는 계정 |
| 아이디 | `loginId` (DB `login_id`) | 로그인에 쓰는 사용자 식별 문자열. 이메일이 아니다 |
| 프로젝트 | `project` | 이슈의 묶음. 고유 키(예: `FLOW`)를 가진다 (M3 이후) |
| 이슈 | `issue` | 작업 단위. `FLOW-123` 형태의 키를 가진다 (M3 이후) |
| 워크플로 | `workflow` | 이슈 상태와 상태 간 이동 규칙 (M3 이후) |
| 보드 | `board` | 이슈를 상태별 열로 보여주는 화면 (M4 이후) |
| 스프린트 | `sprint` | 기간이 정해진 작업 묶음 (M5 이후) |

## 전체 기능 범위 (초안)

M1 이후의 범위는 사용자가 아직 확정하지 않았다. 마일스톤을 시작하기 전에 사용자에게 범위를 확인한다. 순서는 [08-roadmap.md](08-roadmap.md) 참고.

- 사용자·역할 관리 (초대, 비활성화, 비밀번호 재설정)
- 프로젝트와 이슈 (유형, 우선순위, 담당자, 라벨, 댓글, 첨부, 변경 이력)
- 워크플로와 칸반 보드 (드래그 앤 드롭)
- 백로그와 스프린트
- 검색, 저장된 필터
- 알림 (인앱, 이메일), 실시간 갱신
- 리포트와 대시보드

## 하지 않는 것

- 멀티 테넌시, 조직 간 데이터 분리
- 결제, 요금제
- M1 기준: 소셜 로그인/SSO, 이메일 발송, 2단계 인증 (필요해지면 별도 마일스톤으로 다룬다)

## 품질 기준

- 접근성: WCAG 2.2 AA. 모든 기능을 키보드만으로 쓸 수 있어야 한다.
- 성능: 주요 화면 LCP 2.5초 이하, INP 200ms 이하.
- 언어: UI 기본 언어는 한국어. 문자열은 처음부터 번역 가능한 구조로 둔다. (초안 — [09-decisions.md](09-decisions.md) 미결정 항목)
- 화면: 데스크톱 우선, 모바일 폭에서도 깨지지 않아야 한다. 라이트/다크 테마 지원.
