# 01. 제품 설계 (Linear식 재설계)

Flowbit은 한 조직이 자기 서버에 설치해서 쓰는 티켓 트래커다. 처음에는 Jira식(프로젝트 → 워크플로 → 스프린트, 설정 중심)으로 설계했으나, 2026-10-12 에 **Linear처럼 빠르고 단순하며 한국 사용자가 편하게 쓰는 도구**로 방향을 바꿨다 (D-020). 이 문서가 제품과 UX의 기준이다.

> **2026-10-12 변경 (D-032)**: 아래 문서의 "팀"은 없어졌다. **프로젝트가 티켓의 집이자 권한 단위**이고(키 `FLOW`, 구성원, 상태 목록을 가진다), 티켓은 **프리셋(버그·고도화·기능 요청)으로 목차가 깔린 문서**다. 이 문서에서 "팀"이라고 쓴 곳은 "프로젝트"로 읽고, 티켓의 내용과 권한은 [features/M3-projects-and-issues.md](features/M3-projects-and-issues.md) 를 기준으로 한다. "기한이 있는 목표"라는 옛 뜻의 프로젝트(4.7)와 사이클·트리아지는 아직 다시 정하지 않았다.

확정 여부: 재설계 원칙과 이 문서의 구조는 사용자가 지정했다. 세부 수치와 화면 구성은 그 원칙에 따라 에이전트가 설계한 것이며, 각 마일스톤을 시작할 때 `features/` 명세에서 확정한다. 현재 구현된 범위는 M1(로그인, 초기 설정)뿐이다.

바뀌지 않은 전제:

| 항목 | 내용 |
|---|---|
| 배포 형태 | 단일 조직 설치형. 한 인스턴스 = 한 워크스페이스 (D-003) |
| 1차 범위 | 로그인 및 초기 설정 ([features/M1-auth-and-setup.md](features/M1-auth-and-setup.md)) |
| 스택 | Spring Boot(WebFlux) + Kotlin, Next.js + shadcn/ui ([02-architecture.md](02-architecture.md)) |

## 1. 제품 철학 & 재설계 요약

만들 때마다 묻는 질문: **"이 화면에서 가장 자주 하는 일이 0.1초 안에, 키 한두 번으로 끝나는가?"**

Jira식 설계에서 바뀐 핵심 7가지:

| # | 이전 (Jira식) | 지금 (Linear식) |
|---|---|---|
| 1 | 화면마다 서버 응답을 기다린다 | **속도가 기능이다.** 모든 변경은 화면에 먼저 반영하고(optimistic) 서버에는 뒤에서 보낸다. 실패하면 되돌리고 알린다. 목록은 로컬 캐시에서 즉시 그린다 |
| 2 | 메뉴와 폼을 마우스로 찾아 들어간다 | **키보드 퍼스트.** `Ctrl/⌘+K` 커맨드 팔레트에서 모든 액션과 이동이 가능하다. 주요 액션은 한 글자 단축키. 같은 액션이 항상 마우스로도 한두 번 클릭 안에 있다 |
| 3 | 워크플로, 필드, 화면, 권한을 관리자가 설계한다 | **기본값이 정답이다.** 상태·우선순위·역할은 정해져 있고 바로 쓴다. 바꿀 수 있는 것은 팀별 상태 이름과 추가 정도이며, 설정 화면 깊숙이 둔다 |
| 4 | 스프린트를 직접 만들고 시작·종료한다 | **사이클이 저절로 돈다.** 팀이 길이만 정하면 자동으로 다음 사이클이 생기고, 끝나면 남은 티켓이 다음으로 넘어간다 |
| 5 | 프로젝트가 티켓의 컨테이너이자 권한 단위다 | **팀이 티켓의 집이고, 프로젝트는 목표다.** 티켓은 팀에 속하고(`FLOW-123`), 프로젝트는 기한이 있는 결과물로 여러 팀의 티켓을 묶는다 |
| 6 | 대시보드와 리포트를 가젯으로 조립한다 | **뷰가 곧 대시보드다.** 필터를 저장한 뷰, 그리고 사이클·프로젝트 화면에 기본 내장된 진행 그래프만 둔다 |
| 7 | 영문 제품을 번역한 문구와 형식 | **한국어로 처음부터 쓴다.** Pretendard, 자연스러운 한국어 문구, `YYYY-MM-DD`, 모바일에서도 주요 액션이 편하다 |

지키는 원칙:

1. **속도**: 상호작용에 스피너를 보여주지 않는다. 첫 로딩에만 스켈레톤을 쓴다. 목표는 입력 후 100ms 안에 화면 반응.
2. **키보드와 마우스 둘 다**: 단축키를 몰라도 불편하지 않아야 한다. 단축키는 메뉴와 툴팁 옆에 항상 표시해서 쓰다 보면 익힌다.
3. **단계적 공개**: 처음 보는 화면은 단순하다. 고급 옵션은 "더 보기"나 설정 안에 둔다.
4. **밀도**: 한 화면에 티켓 20~30개가 보이는 밀도를 기본으로 한다. 여백으로 구분하되 낭비하지 않는다.
5. **되돌리기**: 삭제, 상태 변경, 일괄 편집은 모두 `Ctrl/⌘+Z` 와 토스트의 "실행 취소"로 되돌린다. 그래서 확인 창을 띄우지 않는다.
6. **명확한 피드백**: 무엇이 바뀌었는지 토스트 한 줄로 알린다 ("FLOW-12 를 완료로 옮겼습니다 · 실행 취소").
7. **실시간**: 여러 사람이 동시에 써도 서로의 변경이 새로 고침 없이 보인다. 다른 사람이 옮긴 카드가 내 보드에서도 바로 움직이고, 수신함 숫자가 바로 오른다. WebSocket 으로 전파한다 ([02-architecture.md](02-architecture.md) "실시간 동기화", D-024).

## 2. 핵심 개념 재정의

| 개념 | 코드 식별자 | 정의 | Jira 대응 |
|---|---|---|---|
| 워크스페이스 | `instance` | 설치된 Flowbit 하나 = 조직 하나. 구성원, 팀, 설정을 가진다 | 사이트 |
| 구성원 | `user` | 로그인하는 사람. 역할은 **관리자**와 **구성원** 둘뿐 (게스트는 이후 검토) | 사용자 + 권한 체계 |
| 아이디 | `loginId` | 로그인에 쓰는 문자열. 이메일이 아니다 (D-016) | 사용자 이름 |
| ~~팀~~ | | 없어졌다 (D-032). 프로젝트가 그 역할을 한다 | |
| 프로젝트 구성원 | `projectMember` | 프로젝트에 들어올 수 있는 사람과 역할(관리 / 편집 / 보기) | 프로젝트 역할 |
| 프리셋 | `preset` | 티켓의 종류(버그, 고도화, 기능 요청). 새 티켓의 문서에 깔리는 목차를 정한다 | 티켓 유형 |
| 티켓 | `issue` | 프로젝트에 등록하는 글 하나. 위쪽은 속성(상태, 프리셋, 담당자, 우선순위, 기한, 라벨), 아래쪽은 프리셋이 목차를 깔아 준 문서다. 요청하는 사람이 접수하고 처리하는 사람이 이 글을 보고 처리한다. 화면에서는 "티켓"이라고 부르고 코드에서는 `issue` 다 (D-122) | 이슈 |
| 상태 | `status` | 5개 **범주**가 고정이다: 백로그 → 할 일 → 진행 중 → 완료, 그리고 취소. 팀은 범주 안에서 상태를 추가하거나 이름을 바꿀 수 있다(예: "진행 중" 범주에 "리뷰 중"). 이동 규칙은 없다 | 워크플로 + 전환 규칙 |
| 우선순위 | `priority` | 없음, 긴급, 높음, 보통, 낮음. 고정 | 우선순위 체계 |
| 라벨 | `label` | 자유로운 분류. 티켓 유형(버그, 기능 등)도 라벨로 표현한다 | 티켓 유형, 컴포넌트, 라벨 |
| 하위 티켓 | `parentIssue` | 티켓을 쪼갠 것. 10단계까지 | 하위 작업 |
| 사이클 | `cycle` | 팀의 반복되는 작업 기간(기본 2주). 자동으로 이어지고, 끝날 때 미완료 티켓은 다음 사이클로 넘어간다. "이번 사이클에 며칠 남았고 얼마나 했는가"를 항상 보여준다 | 스프린트 |
| 프로젝트 | `project` | **티켓의 집이자 권한 단위** (D-032). 키(`FLOW`), 구성원, 상태 목록, 프리셋을 가진다. 구성원이 아닌 사람에게는 보이지 않는다 | 프로젝트 |
| 뷰 | `view` | 저장한 필터 + 표시 방식(목록/보드, 그룹, 정렬). 개인용과 팀 공유용 | 필터, 대시보드, 보드 설정 |
| 수신함 | `inbox` | 나와 관련된 변화(배정, 멘션, 댓글, 상태 변경)가 모이는 곳. 읽고 지우는 흐름 | 알림 메일 |
| 트리아지 | `triage` | 팀으로 들어온, 아직 분류되지 않은 티켓 대기열. 수락·거절·중복 처리한다 | 없음 |

티켓이 가질 수 있는 관계: 막고 있음, 막혀 있음, 관련, 중복.

## 3. 정보 아키텍처 & 주요 내비게이션

```
│ 워크스페이스 ▾ │  뷰 제목 · 필터 · 표시 옵션            [+ 새 티켓] │
│ 검색     ⌘K │───────────────────────────────────────────────│
│              │                                               │
│ 수신함     3 │                                               │
│ 내 티켓      │              목록 / 보드 / 상세                 │
│              │                                               │
│ 즐겨찾기      │                                               │
│  · 저장한 뷰  │                                               │
│              │                                               │
│ 팀           │                                               │
│ ▾ 플랫폼     │                                               │
│    트리아지 2 │                                               │
│    티켓      │                                               │
│    사이클    │                                               │
│    프로젝트   │                                               │
│ ▸ 디자인     │                                               │
│              │                                               │
│ 프로젝트      │                                               │
│ 뷰           │                                               │
│──────────────│                                               │
│ 김지민 ▾     │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- **사이드바(240px, 접기 가능)** 가 유일한 전역 내비게이션이다. 상단 메뉴 바는 없다.
- 본문 상단 한 줄에 현재 뷰의 제목, 필터, 표시 옵션, 새 티켓 버튼이 있다.
- 티켓 상세는 목록 옆 패널(넓은 화면)이나 전체 화면으로 연다. 목록의 위치와 선택은 유지된다.
- 사이드바에는 실제로 쓸 수 있는 항목만 보인다. 아직 구현하지 않은 메뉴를 미리 넣지 않는다 (M1 에는 워크스페이스 이름과 사용자 메뉴만 있다).

### URL

| 경로 | 화면 |
|---|---|
| `/inbox` | 수신함 |
| `/my-issues` | 내 티켓 |
| `/team/{key}/triage` | 트리아지 |
| `/team/{key}/issues` , `/team/{key}/board` | 티켓 목록, 보드 |
| `/team/{key}/cycles/current` , `/team/{key}/cycles/{n}` | 사이클 |
| `/issue/{KEY-123}` | 티켓 상세 |
| `/projects` , `/project/{slug}` | 프로젝트 목록, 프로젝트 개요 |
| `/views/{id}` | 저장한 뷰 |
| `/search?q=` | 검색 결과 |
| `/settings/...` | 설정 (관리자 항목은 관리자에게만 보인다) |
| `/login` , `/setup` | 로그인, 초기 설정 (M1 구현) |

로그인 후 첫 화면은 `/my-issues`(내 티켓의 "요청한 티켓")다 (D-123). 사이드바 왼쪽 위의 워크스페이스 이름도 그곳으로 간다. 전체 프로젝트는 `/` 다. 초기 설정을 막 끝낸 관리자만 `/` 로 간다.

### 모바일 (폭 768px 미만)

- 사이드바 대신 **하단 탭 4개**: 수신함, 내 티켓, 검색, 더 보기(팀, 프로젝트, 뷰, 설정). 수신함과 검색이 생기기 전까지는 위쪽 줄 왼쪽의 **메뉴 버튼**이 사이드바의 항목(내 티켓, 전체 티켓, 전체 프로젝트, 내 프로젝트)을 보여 준다.
- 오른쪽 아래에 **새 티켓 버튼**이 항상 떠 있다.
- 목록의 행을 옆으로 밀면 상태 변경, 길게 누르면 속성 메뉴.
- 속성 선택은 화면 아래에서 올라오는 시트로 연다.

| 키 | 동작 |
|---|---|
| `Ctrl/⌘+K` | 커맨드 팔레트 |
| `/` | 검색 |

## 4. 핵심 화면별 상세 설계

모든 목록 화면이 공유하는 티켓 조작 단축키 (선택한 티켓 또는 포커스된 티켓에 적용):

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `J` / `K` 또는 `↓` / `↑` | 다음 / 이전 | `X` | 선택 (여러 개: `Shift+↓↑`) |
| `Enter` | 열기 | `Space` | 옆 패널로 미리 보기 |
| `S` | 상태 | `P` | 우선순위 |
| `A` | 담당자 (`I`: 나에게) | `L` | 라벨 |
| `D` | 기한 | `Shift+C` | 사이클 |
| `Shift+P` | 프로젝트 | `Ctrl/⌘+Backspace` | 삭제 (되돌릴 수 있음) |

속성 키를 누르면 그 자리에 작은 선택 메뉴가 뜨고, 글자를 치면 걸러지며, `Enter` 로 즉시 적용된다.

### 4.1 수신함 & 트리아지

**수신함** (`/inbox`)

- 목적: 나에게 온 변화를 빠르게 훑고 비운다.
- 레이아웃: 왼쪽 알림 목록(380px), 오른쪽에 선택한 티켓 상세. 모바일은 목록만 보이고 누르면 상세로.
- 주요 컴포넌트: 알림 한 줄 = 누가 · 무엇을 · 티켓 제목 · 시간. 읽지 않은 것은 굵게, 왼쪽에 점.
- 인터랙션: 열면 읽음 처리. 지우면 목록에서 사라지고 그 티켓에 새 변화가 생기면 다시 온다. "나중에"로 미루기(1시간, 내일, 다음 주).
- 단축키: `J`/`K` 이동, `E` 지우기, `U` 읽지 않음으로, `H` 나중에, `Shift+E` 모두 지우기.
- 빈 상태: "모두 확인했습니다" 한 줄.

**트리아지** (`/team/{key}/triage`)

- 목적: 팀으로 들어온 티켓을 받아들일지 정한다. 다른 팀 구성원이 만든 티켓과 연동으로 들어온 티켓이 여기로 온다.
- 레이아웃: 수신함과 같다(목록 + 상세).
- 주요 컴포넌트: 티켓 행, 상세 위쪽의 수락/중복/거절 버튼 막대.
- 인터랙션: 수락(상태를 백로그나 할 일로, 담당자·우선순위 지정), 거절(사유 선택, 취소 상태로), 중복(원본 티켓 선택).
- 단축키: `1` 수락, `2` 중복, `3` 거절.

### 4.2 티켓 목록

- 목적: 팀이나 뷰의 티켓을 훑고, 열지 않고 고친다.
- 레이아웃: 상태별 그룹 머리글 아래 한 줄짜리 행(높이 36px). 그룹은 접을 수 있다.
- 주요 컴포넌트: 행(왼쪽부터 우선순위 아이콘 · 티켓 키 `FLOW-123` · 상태 아이콘 · 제목 · 오른쪽에 라벨 · 프로젝트 · 사이클 · 기한 · 담당자 아바타), 상단의 필터 버튼(`F`)과 표시 옵션(그룹 기준, 정렬, 보일 속성, 목록/보드 전환), "뷰로 저장", 일괄 편집 막대.
  - 좁아지면 오른쪽 속성부터 숨긴다: 라벨 → 프로젝트 → 사이클 → 기한. 제목과 담당자는 남긴다.
  - 기한은 `10-24` 처럼 짧게, 지났으면 빨간색, 3일 이내면 주황색.
- 인터랙션: 행의 아이콘을 누르면 그 자리에서 속성 변경. 여러 개 선택하면 아래에 일괄 편집 막대. 끌어서 순서 변경(수동 정렬일 때), 그룹 사이로 끌면 상태 변경. 가상 스크롤, 변경은 즉시 반영.
- 단축키: 4장 첫머리의 표 전부, `F` 필터, `Ctrl/⌘+A` 모두 선택.
- 빈 상태: "아직 티켓이 없습니다. `C` 를 눌러 첫 티켓을 만드세요" + 버튼.

### 4.3 보드

- 목적: 흐름을 보면서 상태를 옮긴다.
- 레이아웃: 상태가 열. 완료와 취소 열은 기본으로 접혀 있다(이번 사이클 것만 보임).
- 주요 컴포넌트: 카드(티켓 키 · 제목 2줄까지 · 우선순위 · 라벨 · 담당자), 열 머리(상태 이름 · 개수 · `+`), 가로 줄 나누기 선택(담당자별, 프로젝트별, 우선순위별).
- 인터랙션: 카드를 끌어 열과 순서를 바꾼다. 놓는 즉시 반영. 열 머리의 `+` 로 그 상태의 티켓을 바로 만든다.
- 단축키: 목록과 같고, `←`/`→` 로 열 사이 이동, `Shift+←`/`→` 로 카드를 옆 열로 옮긴다(끌지 않고 상태 변경).
- 모바일: 한 번에 한 열. 좌우로 밀어 열을 바꾼다.

### 4.4 티켓 상세

- 목적: 티켓 하나를 읽고, 쓰고, 논의한다.
- 레이아웃: 가운데 본문(최대 폭 720px) + 오른쪽 속성 패널(260px). 모바일은 속성이 제목 아래 한 줄 칩으로 접힌다.
- 주요 컴포넌트: 제목(바로 편집) · 설명(마크다운 편집기, `/` 로 블록 삽입, 이미지 붙여넣기) · 하위 티켓 목록 · 활동(댓글과 변경 이력이 시간순으로 섞임, 이력은 작게) · 속성 패널(상태, 우선순위, 담당자, 라벨, 사이클, 프로젝트, 기한, 추정치, 관계).
- 인터랙션: 모든 편집은 저장 버튼 없이 자동 저장. 댓글은 `Ctrl/⌘+Enter` 로 등록. `@` 로 사람, `#` 로 티켓 연결.
- 단축키: 4장 첫머리의 속성 키 전부, `Ctrl/⌘+Shift+.` 키 복사(`FLOW-123`), `Ctrl/⌘+Shift+,` 링크 복사, `J`/`K` 로 목록의 다음/이전 티켓.

**새 티켓 만들기** (`C`)

- 화면 가운데 작은 창. 제목에 포커스. 제목만 쓰고 `Ctrl/⌘+Enter` 면 끝.
- 팀은 현재 보던 팀이 기본값. 상태·우선순위·담당자·라벨은 제목 아래 칩으로, 누르거나 단축키로 바꾼다.
- 만들면 창이 닫히고 토스트로 "FLOW-124 를 만들었습니다 · 열기". "계속 만들기"를 켜면 창이 남는다.
- 쓰다가 닫아도 초안이 남는다.

### 4.5 사이클 뷰

- 목적: 이번 사이클에 남은 시간과 일을 본다.
- 레이아웃: 상단 요약 띠 + 아래 티켓 목록(목록/보드 전환). 탭: 현재 / 다음 / 지난 사이클.
- 주요 컴포넌트: 요약 띠 = 사이클 이름과 기간(`10-12 ~ 10-25`) · **남은 날 수**(가장 크게, "5일 남음") · 진행 막대(완료 / 진행 중 / 남음) · 범위 변화(시작 후 추가된 티켓 수) · 번다운 그래프(작게, 누르면 확대).
- 인터랙션: 백로그에서 티켓을 끌어 사이클에 넣는다. 종료일 자정에 다음 사이클이 자동으로 시작되고 미완료 티켓이 넘어간다. 수동으로 "시작/종료"를 누르지 않는다.
- 단축키: 목록과 같고, `Shift+C` 로 다음 사이클로 미루기.

### 4.6 커맨드 팔레트

- 목적: 무엇이든 한 곳에서 찾고 실행한다.
- 레이아웃: 화면 위쪽 가운데 입력창(폭 640px) + 결과 목록. 모바일은 전체 화면.
- 주요 컴포넌트: 입력창, 종류별로 묶인 결과(액션, 티켓, 팀, 프로젝트, 뷰, 구성원), 각 액션 오른쪽의 단축키 표시.
- 인터랙션:
  - 아무것도 안 쳤을 때: 지금 상황에 맞는 액션(티켓을 선택했다면 그 티켓에 할 수 있는 일), 그다음 최근 티켓.
  - 글자를 치면 모든 종류를 한 번에 찾는다. 한글 초성(`ㄱㅈ` → "결제"), 오타 허용, 한/영 자판 실수 보정(`rufwp` → "결제").
  - 액션을 고르면 다음 단계가 같은 창에서 이어진다(상태 변경 → 상태 선택).
- 단축키: `Ctrl/⌘+K` 열기, `↑`/`↓`, `Enter`, 빈 입력에서 `Backspace` 로 이전 단계, `Esc` 닫기.

### 4.7 프로젝트 개요

- 목적: 목표가 어디까지 왔는지 한눈에 본다.
- 레이아웃: 머리 + 진행 요약 + 탭(개요, 티켓, 업데이트).
- 주요 컴포넌트: 머리(이름, 상태: 계획됨/진행 중/완료/중단, 책임자, 목표일) · 진행 요약(완료 비율, 남은 티켓 수, 현재 속도로 본 예상 완료일) · 개요 탭의 설명 문서와 팀별 진행 · 업데이트 탭의 진행 보고(건강 상태: 순조/주의/위험 + 글).
- 인터랙션: 책임자가 업데이트를 쓰면 프로젝트 목록(`/projects`)의 그 줄에도 최신 상태가 보인다. 목록 한 줄 = 이름 · 상태 · 진행 막대 · 책임자 · 목표일.
- 단축키: `G` `P` 프로젝트 목록, 티켓 탭에서는 목록 단축키 전부.

### 4.8 검색 결과

- 목적: 팔레트로 못 찾은 것을 조건을 걸어 찾는다.
- 레이아웃: 위에 검색창과 필터 칩(팀, 상태, 담당자, 기간), 아래 결과. 탭: 티켓 / 프로젝트 / 문서(프로젝트 설명과 업데이트).
- 주요 컴포넌트: 결과 한 줄 = 티켓 목록 행 + 일치한 본문 조각(강조).
- 인터랙션: 제목, 설명, 댓글, 티켓 키를 찾는다. `FLOW-12` 처럼 키를 치면 바로 그 티켓이 맨 위. 한글은 부분 일치 + 초성, 조사가 붙어도 찾는다("결제를" → "결제").
- 단축키: `/` 로 검색창, `↑`/`↓` 결과 이동, `Enter` 열기.
- 빈 결과: "'OOO' 에 맞는 결과가 없습니다" + 필터 해제 버튼.

### 톤

### 타이포그래피

- 서체: **Pretendard Variable** (한글·영문·숫자 한 서체). 없을 때 `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`.
- 티켓 키와 숫자 열은 같은 서체의 고정 폭 숫자(`font-variant-numeric: tabular-nums`)를 쓴다. 모노 서체는 코드 블록에만.
- 한글 줄바꿈: `word-break: keep-all` (단어 중간에서 끊지 않음), `overflow-wrap: anywhere`.

### 간격과 모양

- 4px 단위: 4, 8, 12, 16, 24, 32, 48.
- 행 높이: 목록 36px, 터치 화면 44px. 사이드바 항목 30px.
- 반경: 입력·버튼 8px, 창·카드 12px, 배지·아바타는 완전한 둥근 모양. 안쪽 요소의 반경 = 바깥 반경 − 안쪽 여백.
- 구조는 1px 테두리로 나눈다. 그림자는 떠 있는 것(메뉴, 창, 토스트)에만 쓴다.

### 컴포넌트

| 컴포넌트 | 규칙 |
|---|---|
| 버튼 | 높이 32px(기본), 40px(로그인·설정 폼의 주 버튼과 입력), 모바일 주 버튼 44px. 주 버튼은 한 화면에 하나 |
| 입력 | 레이블은 입력 위. 포커스는 테두리 파랑 + 3px 링. 오류는 테두리 빨강 + 아래 메시지 |
| 메뉴·선택 | 열자마자 검색 가능. 항목 오른쪽에 단축키. 현재 값에 체크 |
| 토스트 | 화면 아래 가운데, 한 줄, 4초. 되돌릴 수 있는 일에는 "실행 취소" |
| 빈 상태 | 한 줄 설명 + 다음 행동 버튼 하나. 큰 일러스트는 쓰지 않는다 |
| 스켈레톤 | 첫 로딩에만. 실제 행과 같은 높이와 배치 |

shadcn/ui 컴포넌트를 쓰고, 위 값은 토큰과 variant 로 맞춘다 ([04-frontend-guide.md](04-frontend-guide.md)).

### 움직임

- 자주 일어나는 것(행 이동, 선택, 메뉴 열기, 상태 변경)은 애니메이션 없이 즉시, 또는 120ms 이하의 불투명도 변화만.
- 드물게 일어나는 것(창 열기, 토스트)은 150~200ms, `cubic-bezier(0.2, 0, 0, 1)`.
- `prefers-reduced-motion` 이면 이동·크기 변화를 불투명도 변화로 바꾼다.

## 6. 주요 사용자 플로우

### 6.1 티켓 생성 → 상태 변경 → 완료

1. 어느 화면에서든 `C` → 제목 입력 → `Ctrl/⌘+Enter`. 창이 닫히고 목록 맨 위에 티켓이 **즉시** 나타난다(서버 저장은 뒤에서).
2. 목록에서 그 티켓에 포커스를 두고 `I`(나에게 배정), `S` → `진` → `Enter`(진행 중).
3. 일이 끝나면 `S` → `완` → `Enter`. 티켓이 완료 그룹으로 옮겨지고 토스트에 "FLOW-124 를 완료로 옮겼습니다 · 실행 취소".
4. 서버 저장이 실패하면 화면이 원래대로 돌아가고 "저장하지 못했습니다 · 다시 시도" 토스트가 뜬다.

마우스만 쓸 때: 상단 "새 티켓" 버튼 → 제목 → "만들기". 행의 상태 아이콘 클릭 → 메뉴에서 선택.

### 6.2 사이클 계획

1. 관리자가 팀 설정에서 사이클을 켠다(길이 2주, 시작 요일 월요일이 기본값). 이후로는 자동.
2. `G` `C` 로 사이클 화면 → "다음" 탭. 오른쪽에 백로그가 나란히 열린다.
3. 백로그에서 티켓을 고르고(`X`, `Shift+↓`) `Shift+C` → "다음 사이클". 또는 끌어다 놓는다.
4. 요약 띠에 담긴 양과 지난 사이클들의 평균 완료량이 함께 보여서 넘치는지 알 수 있다.
5. 날짜가 되면 자동으로 시작된다.

### 6.3 트리아지

1. 다른 팀 구성원이 `C` 로 티켓을 만들며 팀을 "플랫폼"으로 고른다 → 플랫폼 팀의 트리아지에 들어가고 팀 담당자의 수신함에 알림.
2. 담당자가 `G` `T` → 티켓을 읽고 `1`(수락) → 우선순위와 담당자를 고른다 → 티켓이 백로그로 간다.
3. 중복이면 `2` → 원본 검색 → 선택. 만든 사람에게 알림이 간다.

### 6.4 수신함 비우기 (모바일)

1. 앱을 열면 수신함. 알림을 눌러 티켓을 본다.
2. 댓글에 답하고 뒤로. 알림을 왼쪽으로 밀어 지운다.
3. 급한 것은 길게 눌러 "나에게 배정", "우선순위 높음".

### 6.5 설치와 첫 로그인 (M1, 구현됨)

1. 서버를 띄우고 브라우저로 접속 → `/setup`.
2. 워크스페이스 이름과 로고, 관리자 아이디와 비밀번호를 정한다 → 그 계정으로 로그인된 상태로 홈.
3. 이후에는 `/login` 에서 같은 아이디와 비밀번호로 로그인.

## 7. 한국 사용자 특화 포인트

| 영역 | 내용 |
|---|---|
| 서체 | Pretendard Variable. 한글 가독성을 위해 본문 14px / 줄 높이 22px, `word-break: keep-all` |
| 문구 | 처음부터 한국어로 쓴다. 간결한 합니다체와 명사형("저장", "새 티켓", "모두 확인했습니다"). 직역투("~하시겠습니까?", "성공적으로 ~되었습니다")를 쓰지 않는다. 용어는 이 문서 2장의 이름으로 통일 |
| 날짜·시간 | `YYYY-MM-DD`, 24시간제. 가까운 날짜는 "오늘", "어제", "3일 전", 올해 안은 `10-24`. 주의 시작은 월요일. 시간대 기본 `Asia/Seoul` |
| 이름 | 표시 이름은 한 칸(예: 김지민)이고 성+이름 순서로 쓴다. 성과 이름을 나눠 받는 옵션은 필요해지면 추가한다. 아바타 글자는 한글이면 이름의 마지막 두 글자("지민") |
| 검색 | 초성 검색, 조사 무시, 한/영 자판 실수 보정, 오타 허용 |
| 입력기 | 한글 조합 중 `Enter` 가 두 번 처리되지 않게 한다(`isComposing` 확인). 단축키는 한글 자판 상태에서도 같은 키로 동작 |
| 로그인 | 기본은 아이디/비밀번호(M1). 이후 관리자가 설정에서 키를 등록하면 **카카오 로그인, 네이버 로그인** 버튼이 로그인 화면에 나타난다(설치형이라 각 조직이 자기 앱 키를 넣는다) |
| 알림 | 인앱 수신함이 기본. 이후 이메일, 그리고 **카카오톡 알림**(관리자가 카카오 연동을 설정한 경우)을 선택할 수 있게 한다. 야간에는 모아서 아침에 보낸다 |
| 모바일 | 반응형 웹으로 주요 액션(확인, 댓글, 상태 변경, 새 티켓)이 한 손으로 가능. 터치 대상 44px |
| 밀도 | 여백만 넓은 미니멀이 아니라 한 화면에 많이 보이는 정돈된 밀도. 표시 옵션에서 "넓게/기본/촘촘하게" |
| 신뢰감 | 흰 바탕과 파란색, 분명한 오류 문구, 되돌리기. 과장된 문구나 이모지를 쓰지 않는다 |

카카오·네이버 연동은 외부 서비스의 앱 등록과 심사가 필요하다. 가능한 방식과 제약은 해당 마일스톤에서 조사하고 확정한다 (D-022).
